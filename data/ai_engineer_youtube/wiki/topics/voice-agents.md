# Voice Agents

## Overview

Voice agents add realtime audio constraints to the usual agent stack of model, instructions, tools, and runtime. The central architecture choice is whether to chain speech-to-text, text reasoning, and text-to-speech components or use a speech-to-speech model that preserves conversational semantics and reduces latency. Cascaded stacks remain useful when teams need explicit monitoring, provider/model choice, RAG, function calling, and language-control tools, but they need tight placement of audio and LLM services to keep latency tolerable. The operational target is voice-to-voice latency: the full path from the user stopping speech to the first returned audio, not only model response time. Stateful streaming APIs extend that decision into a runtime shape: audio buffers, visual frames, transcriptions, realtime events, and tool calls may all flow over one session. Low-latency consumer products may prioritize expressiveness and responsiveness, while customer-service workflows often need stronger accuracy, integrations, and guardrails even if the experience is less fluid. For open-source realtime TTS, serving must also be measured in audio-token throughput: codec-token voice models need enough generated tokens per second to keep up with playback, and generated leading silence wastes the same latency budget even when filtered before the user hears it. Frameworks such as Pipecat make that runtime explicit as a frame pipeline: transports, STT, LLMs, TTS, native speech models, tools, recording, transcription, and observers can be composed as streaming processors instead of hidden inside one monolithic bot. Pipecat's deployment framing adds that production voice agents also need a realtime session layer around the pipeline: cold starts, autoscaling, global routing, telephony/WebRTC endpoints, data residency, and inference-server placement affect whether a caller hears the agent quickly and gets sub-second responses. Realtime media transport is part of the agent architecture: WebRTC should carry browser, native, and edge-to-cloud audio/video streams when packet freshness, jitter handling, bandwidth adaptation, and observability matter more than TCP-style in-order delivery. WebRTC topology can also match the product shape, from local peer-to-peer devices to cloud AI servers to multiparty agents in meetings. Voice AI can also become a hardware and developer ecosystem: app editors, dev kits, open source, and custom hardware form factors let assistants move from smart speakers into robots, toys, appliances, and home automation. Voice can also be a presentation layer over explicit retrieval workflows: a visual-document RAG agent can retrieve page images, construct multimodal answer prompts, and then speak the grounded answer. Contact-center voice intelligence adds a data-pipeline shape: preserve speaker channels, tune STT with domain vocabulary and normalization, extract structured JSON, mask PII before LLM processing, and verify CRM-bound summaries before durable updates. Multilingual agents need explicit language detection and switching policies rather than treating language as only a transcription feature, especially when official-language requirements or mixed-language conversations affect user comfort. Production voice systems should keep the conversational agent's tool surface small, delegate complex tasks to specialist agents or models, and preserve context through summarized handoffs. Slow tools need spoken waiting states, bounded timeouts, or queued follow-up paths so unavoidable backend latency does not become dead air. Turn-taking is itself a production behavior: fixed VAD and silence timeouts are too blunt for pauses, backchannels, and culture- or speaker-specific response timing, so semantic end-of-turn detection should use conversation context, transcript meaning, syntax, prosody, and acoustic cues. Background audio is another production behavior, not just a transcription detail: speech-like noise can trigger interruptions and pseudo-transcripts that cause downstream inference at the wrong time. Full-duplex speech models point to a different path where listening, silence, speech, and backchannels are learned from raw audio, but cascaded pipelines may remain preferable when products need stronger control over pronunciation, brand terms, instruction following, tool integration, and evaluation. Evaluation needs traces, labeled conversations, transcript-based checks, audio-specific judgments, synthetic conversations, turn-taking benchmarks, release evals across realtime provider services, and guardrails that fit within the timing of spoken responses. Autonomous voice-agent evals should also borrow from self-driving simulation: run many multi-turn conversations, measure failure probabilities, calibrate realism to the behavior under test, and feed production bugs back into regression suites and monitoring dashboards. Generated voice safety also requires platform controls beyond model behavior: consent checks for cloning, moderation for restricted speech, and provenance signals such as watermarking help respond to fraud and impersonation. A frontier multimodal model can also collapse parts of the audio stack: one call with a response schema can return a rich structured profile of a recording — diarization with speaker names, timestamps, per-segment language detection with translation, emotion, and a summary — instead of chaining ASR, diarization, language-ID, and emotion models, useful when speaker channels are not separable. The same audio understanding changes speech generation: rather than filtering a large voice catalogue, a small set of base voices is steered by a natural-language director's note (audio profile, scene, performance guidance) so accents and personas are synthesized on demand, with the caveat that a directed accent can bleed across languages. Native sound-to-sound real-time models (e.g. Gemini 3.1 Flash Live) push this further by ingesting text/audio/video over a WebSocket with thinking baked into the model rather than cascaded through a text LLM, and they can orchestrate generative media by calling a media-generation model (such as Lyria 3 for music) as a tool, letting the conversation gather the creative brief before generating. Underneath "rich transcription" sits speaker diarization — "who speaks when" — a distinct, still-unsolved task with its own pipeline (voice activity detection → segmentation/overlap → speaker assignment), its own difficulties (unknown speaker count, permutation-invariant labels, overlapping speech, very short turns), and its own metric (diarization error rate = confusion + false alarm + missed detection over total speech), where the conversation-understanding ladder rises from "what was said" to who said what, *when* (interruptions, backchannels, pauses), and *how* (laughter, stress, prosody). Speaker-attributed transcription is harder than a timestamp join: STT is mostly single-speaker-trained, boundary words straddle two turns, and the two models' timestamps disagree, so production stacks reconcile them with an STT-agnostic orchestration layer (an "exclusive diarization" trick that, on overlap, picks the single most-likely speaker for the STT) — the architectural opposite of collapsing everything into one multimodal call. Above the architecture sits an interaction-design layer that good ASR/TTS does not solve: a viral "talk to a statue" build (ElevenLabs Voice Design API → an agent → a phone call in ~30 seconds) surfaced that voice is a strong *input* channel for dumping raw intent but a weak *output* channel for dense information, so the better shape is single-stream voice input paired with parallel high-density multimodal output (text, diagrams, generative UI) rather than symmetric voice-in/voice-out; concise speech "sounds rude" where concise text does not, voice can deliver companionship and motivation rather than facts, and "skim listening" (jump forward by concept, not sentence) is still missing. Turn-taking is as much a UX problem as a detection one: people are too polite to interrupt, so push-to-talk beats unreliable barge-in detection, an "agent-wants-to-interject" nudge can signal *which topic* it wants to raise, and because platforms generate the full text before TTS, a mid-speech interruption can be handled by using audio-playback timestamps to truncate the transcript so the model "forgets" what it generated past the interruption. Hardware form factors extend the same goal of removing the screen so the agent does not feel "tacked on" — a statue or red phone booth with an embedded mic/speaker you talk to directly — and raise the question of deriving an object's voice from its provenance. At the engineering layer, building voice agents "at scale" is an "and problem": low latency, baseline intelligence/tool-calling, natural voice, and reliability across thousands of concurrent calls must all hold at once. Two production levers tie the pipeline together. First, the LLM dominates the shared latency/cost budget (then TTS, then STT), so its size is set by a time-to-first-token target (~200-300 ms) that pins it to an ~8-30B sweet spot — larger blows the budget, smaller breaks tool calling — with use-case fine-tuning to recover tool-calling quality in a small model. Second, total latency is engine latency (model compute) *plus* network latency (data-center hops), and once engine latency is optimized the biggest remaining win is co-locating every model and the orchestrator: dropping a ~75 ms cross-region hop to ~5 ms is a ~30% cut even in an already-optimized pipeline, which is the latency case for self-hosting an open model near the agent rather than calling a distant managed API. Around this, classifiers route before the LLM and guardrails run after generation but before TTS (spoken audio cannot be unsaid), the "thinker-talker" pattern lets a small conversation model emit immediate filler and delegate hard work via a single tool call to a bigger model, and autoscaling must be aggressive on the way up but drain stateful long-lived sessions on the way down. Above all of this sits an interaction-*protocol* framing: a prompt box (even a spoken one) is a batch protocol with "exactly one slot" — your turn, then its reply — so a speech-to-speech model answers "Hey Ted, come on in" because it "has no concept of who's speaking, whether the words were even meant for it," and backchanneling ("mhm") or learned turn-taking is "not really the same as knowing who's in the room." Moving from batch to genuine participation therefore needs a multi-party protocol on top of the audio stack (a utility-driven model that labels each statement as question/proposal/answer, tracks who a speaker refers to, and only takes the floor when no one else holds it), which is the interaction-design layer that good ASR/TTS and even full-duplex turn-taking do not by themselves solve. The same voice-in/visuals-out asymmetry is also a *latency* strategy: full voice-in/voice-out demands a punishing ~200 ms response to feel conversive, but the visual response envelope is far more forgiving (~1 s on screen still feels seamless), so responding into a visual instead of spoken output ships delightful realtime experiences today without novel 200 ms-slice architectures — and inside that ~1 s envelope three levers matter most: a latency-prioritized fast model (Haiku-class, not a small-but-slow model whose P95 balloons to 5-10 s) that hands heavy work off asynchronously to a larger thinking model and re-interleaves the result, eager short-interval inference fired every 1-2 s as the user talks instead of waiting for end-of-speech silence, and a stable prefix-caching regimen that keeps ~90% of the context identical request-to-request while minimizing output tokens.

Vivek Muppalla (Hippocratic AI) supplies the highest-stakes production data point in this topic — 200M+ outbound clinical patient calls across 60+ health systems — and his stack inverts two defaults. On the input side, ASR is not a context-free audio→text function but a decoder-only audio LLM: [condition ASR on conversation context and domain vocabulary](../concepts/condition-asr-on-conversation-context-and-domain-vocabulary.md) by feeding the conversation so far, the patient's medications, the current task, and the policy alongside the audio, so a spoken drug name resolves against "a finite list" instead of "an infinite list," with a prosody-preserving conformer projector, training-time contextual biasing on synthetic entities, and a second scoring pass reserved for single-word answers where "a *now* becomes a *no*." The diagnosis behind it generalizes: "most of what looks like model reasoning failures end up actually being model mishearing things," so debugging a domain voice agent starts at the transcript. On the reasoning side, he rejects the single-model brain as "one point of failure" and instead [runs parallel specialist models behind a speak-up gate](../concepts/run-parallel-specialist-models-with-a-speak-up-gate.md): 31 models per conversation — one holding the thread plus 30 specialists — all executed concurrently, with each specialist first making a cheap "do I need to speak?" check that short-circuits, which is what keeps an always-on ensemble inside the latency budget where a routing hop or sequential handoff would not fit. Asynchronous verifiers check tool-call parameters and responses behind the synchronous path, and for reversible actions such as scheduling the verification moves fully offline. Two framings tie the stack together: the tug-of-war between latency and intelligence is treated as a compounding flywheel — latency bought back by an optimization is never banked, it is spent on more intelligence — and the inference work is constrained to be lossless ("quality is our constraint and speed is the work"). The reason a generic voice stack was rejected at all is measurement: the benchmarks that decide this product (lab results check, IVR navigation) are "things that you don't typically hear about or see in the most common benchmarks," and needed >99% accuracy.

Jared Joselowitz (Ufonia) adds the release-safety side of the same clinical-voice problem, from a product — Dora, ~200,000 real clinical calls across 20 UK hospitals — that regulators classify as a medical device because it asks about symptoms and gives advice. His argument is that voice removes the release valves this topic's eval concepts quietly assume: you cannot A/B test on patients, and "once Dora says it, it's been said and there is no rollback," which is the same "spoken audio cannot be unsaid" constraint that puts guardrails after generation but before TTS, escalated from a turn-level check to a whole release process. So he [replaces ship-and-rollback with hazard-first simulation](../concepts/replace-ship-and-rollback-with-hazard-first-simulation.md): a clinician-written hazard list drives a simulation framework (Matrix) in which an LLM plays the patient, and only accumulated evidence buys autonomy. This sharpens the topic's existing self-driving-simulation thread with a validation demand it did not make — [validate the simulated user and the judge before trusting a simulation](../concepts/validate-the-simulated-user-and-the-judge.md) — since Coval's probabilistic conversation evals and Sierra's persona harness both presuppose a credible synthetic user. Ufonia measured it: a script-adherence filter to weed out models that ignore instructions, then a blind study where real patients judged the simulated patient more realistic in three of four sets, plus the coverage lesson that "there is no single realistic patient," which is the concrete argument behind calibrating eval realism to the behavior under test. His voice-specific finding is a hazard the text era does not produce: an agent mid-safety-advice ("you must avoid bright lights") gets cut off by an out-of-scope question and "weak models usually just forget about the safety advice and just answer the next question" — a backchannel/interruption failure that turn-detection work treats as a timing problem and he treats as a safety one. The framing that generalizes is that new modalities change the hazards but not the method: "voice is just a new module in the same safety case."

Not every speech pipeline is a conversation, and Todd Fisher's talking guitar marks the edge of this topic's assumptions. The cascade is the familiar one — microphone → Whisper → a local LLM ("it doesn't really matter what LLM") → text-to-speech — but the output device is an instrument, so the latency budget this topic is organized around simply does not apply: the words are synthesized in advance and each one is fired by a played note, which is what [separating what generated audio says from when it plays](../concepts/separate-what-generated-audio-says-from-when-it-plays.md) buys. It also surfaces a problem the conversational stack never has to solve, because it normally plays TTS output whole. Cutting a synthesized sentence into individually triggerable words is harder than generating it: [energy-gap segmentation assumes silence between words and running speech often has none](../concepts/segment-synthesized-speech-with-multiple-cues-and-manual-repair.md), a sonority-peak syllabifier keyed on vowel nuclei covers different failures, and the residual after combining both was cheaper to repair in a drag-to-edit UI than with another heuristic. Both observations are worth keeping wherever speech becomes material to be re-timed — captioning, dubbing, karaoke-style alignment, or any product that plays generated audio in units rather than in one stream.

## Key Concepts

- [Separate What Generated Audio Says From When It Plays](../concepts/separate-what-generated-audio-says-from-when-it-plays.md) - decoupling synthesis from playback gives a human control of timing and pitch and takes generation latency off the live path entirely.
- [Segment Synthesized Speech With Multiple Cues, Then Let a Human Fix the Rest](../concepts/segment-synthesized-speech-with-multiple-cues-and-manual-repair.md) - word-level slicing of TTS output needs two independent cues plus a manual repair affordance for the remainder.
- [Replace Ship-and-Rollback With Hazard-First Simulation When Errors Are Irreversible](../concepts/replace-ship-and-rollback-with-hazard-first-simulation.md) - spoken output cannot be retracted, so a voice agent in a high-stakes domain needs an enumerated hazard list, simulation as the inner loop, and autonomy granted stage by stage against evidence.
- [Validate the Simulated User and the Judge Before Trusting a Simulation](../concepts/validate-the-simulated-user-and-the-judge.md) - simulated-conversation evals are only as good as the synthetic caller and the automated grader, both of which should be validated against humans before their verdicts gate a release.
- [Realtime multimodal models should plan over specialized local actuators](../concepts/realtime-multimodal-models-should-plan-over-specialized-local-actuators.md) - realtime multimodal models can interpret speech or vision while specialized components execute embodied actions.
- [Choose voice-agent architecture by latency, accuracy, and semantics](../concepts/choose-voice-agent-architecture-by-latency-accuracy-and-semantics.md) - architecture should match whether the product prioritizes responsiveness, semantic preservation, deterministic control, or system integration.
- [Voice Agent Infrastructure Needs Realtime Session Deployment](../concepts/voice-agent-infrastructure-needs-realtime-session-deployment.md) - deployment has to account for long-running media sessions, cold starts, global routing, and tight P95 latency.
- [Design voice agents around voice-to-voice latency budgets](../concepts/design-voice-agents-around-voice-to-voice-latency-budgets.md) - spoken UX depends on the full speech-input-to-speech-output path fitting conversational timing.
- [Size the Voice-Agent LLM to the Time-to-First-Token Budget](../concepts/size-the-voice-agent-llm-to-the-time-to-first-token-budget.md) - a ~200-300 ms TTFT target and the LLM's dominance of the latency/cost budget pin the model to an ~8-30B sweet spot.
- [Separate Engine Latency From Network Latency in Voice Pipelines](../concepts/separate-engine-latency-from-network-latency-in-voice-pipelines.md) - co-locating models and orchestrator collapses cross-region hops for a ~30% latency cut on top of an optimized pipeline.
- [Serve Realtime TTS By Audio-Token Throughput](../concepts/serve-realtime-tts-by-audio-token-throughput.md) - codec-token voice models need generated audio-token rates that keep up with realtime playback.
- [Remove Head-Of-Line Silence From Voice Models](../concepts/remove-head-of-line-silence-from-voice-models.md) - leading generated silence can waste compute and latency before any useful audio reaches the user.
- [Route LoRA Voice Clones With Sticky GPU Affinity](../concepts/route-lora-voice-clones-with-sticky-gpu-affinity.md) - voice-clone adapters should be routed with session continuity and GPU residency in mind.
- [Use WebRTC instead of WebSockets for realtime media streams](../concepts/use-webrtc-instead-of-websockets-for-realtime-media-streams.md) - live audio/video needs fresh low-latency media transport more than TCP-style guaranteed ordering.
- [Choose WebRTC topologies by realtime application shape](../concepts/choose-webrtc-topologies-by-realtime-application-shape.md) - local devices, cloud AI services, and multiparty voice agents need different realtime connection patterns.
- [Delegate complex voice-agent tasks through specialist tools and handoffs](../concepts/delegate-complex-voice-agent-tasks-through-specialist-tools-and-handoffs.md) - realtime voice agents can stay conversational while specialist agents handle harder tool and policy decisions.
- [Prompt voice agents for persona, prosody, and brand fit](../concepts/prompt-voice-agents-for-persona-prosody-and-brand-fit.md) - voice prompts shape spoken demeanor, tone, pacing, and brand realism.
- [Evaluate voice agents with traces, transcripts, audio checks, and simulations](../concepts/evaluate-voice-agents-with-traces-transcripts-audio-checks-and-simulations.md) - voice evals combine standard task checks with audio-specific and latency-aware validation.
- [Realtime multimodal agents use stateful streams for audio, vision, and tools](../concepts/realtime-multimodal-agents-use-stateful-streams-for-audio-vision-and-tools.md) - live audio agents can include visual context, streaming events, transcriptions, and tools in the same session.
- [Use frame pipelines to compose realtime voice agents](../concepts/use-frame-pipelines-to-compose-realtime-voice-agents.md) - streaming processors make transports, model services, utilities, and runtime settings composable.
- [Filter Background Audio Before Voice-Agent Inference](../concepts/filter-background-audio-before-voice-agent-inference.md) - speech-like noise can trigger unwanted interruptions and spurious transcripts before the LLM reasons.
- [Evaluate Speech-To-Speech Models Against Enterprise Control Needs](../concepts/evaluate-speech-to-speech-models-against-enterprise-control-needs.md) - native audio models should be adopted when evals show enough instruction, function-calling, and language-control reliability.
- [Multilingual Voice Agents Need Language Detection and Switching](../concepts/multilingual-voice-agents-need-language-detection-and-switching.md) - multilingual voice products need explicit language identification, switching, and prompt policy.
- [Keep Voice Agents Conversational During Long Tool Latency](../concepts/keep-voice-agents-conversational-during-long-tool-latency.md) - slow tools need spoken wait states, bounded timeouts, or queued follow-up paths.
- [Voice Generation Safety Needs Moderation, Consent, and Provenance](../concepts/voice-generation-safety-needs-moderation-consent-and-provenance.md) - synthetic voice platforms need abuse controls around generated audio and voice cloning.
- [Semantic turn detection improves voice interruption timing](../concepts/semantic-turn-detection-improves-voice-interruption-timing.md) - voice agents need complete/incomplete turn signals rather than only fixed silence timeouts.
- [Pair Low-Bandwidth Voice Input With High-Density Multimodal Output](../concepts/pair-voice-input-with-high-density-multimodal-output.md) - voice excels as an input channel for raw intent but is a poor output channel, so pair voice input with parallel high-density multimodal output and explicit turn-taking cues.
- [Full-duplex speech models make turn-taking a learned behavior](../concepts/full-duplex-speech-models-make-turn-taking-a-learned-behavior.md) - native speech models can learn simultaneous listening, output, silence, forecasting, and backchannels from raw audio.
- [Test realtime voice services with bot-to-bot release evals](../concepts/test-realtime-voice-services-with-bot-to-bot-release-evals.md) - provider integrations should be checked end to end before release.
- [Make voice AI devices developer-extensible](../concepts/make-voice-ai-devices-developer-extensible.md) - voice AI hardware can become an open platform for custom applications and form factors.
- [VoiceVision agents wrap visual RAG with retrieval, image-reading, and speech tools](../concepts/voicevision-agents-wrap-visual-rag-with-retrieval-image-reading-and-speech-tools.md) - document-grounded voice assistants can keep retrieval and image prompt construction explicit before speaking the answer.
- [Preserve speaker channels before voice-agent transcription](../concepts/preserve-speaker-channels-before-voice-agent-transcription.md) - voice pipelines should keep agent and customer speech separable before STT and summarization.
- [Extract contact-center intelligence as structured JSON](../concepts/extract-contact-center-intelligence-as-structured-json.md) - contact-center voice workflows need schema-aligned intent, action, entity, sentiment, and CRM fields rather than free-form summaries.
- [Verify AI call summaries before CRM sync](../concepts/verify-ai-call-summaries-before-crm-sync.md) - operators should validate AI-generated summaries before they update durable customer records.
- [Simulate Voice Agents With Probabilistic Conversation Evals](../concepts/simulate-voice-agents-with-probabilistic-conversation-evals.md) - repeated simulated conversations expose failure probabilities across flexible user and agent paths.
- [Calibrate Voice Eval Realism To The Behavior Under Test](../concepts/calibrate-voice-eval-realism-to-the-behavior-under-test.md) - eval realism should match whether the target is workflow logic, tool calls, latency, interruptions, accents, noise, or full production behavior.
- [Extract a Rich Structured Audio Profile in One Multimodal Call](../concepts/extract-a-rich-structured-audio-profile-in-one-multimodal-call.md) - one multimodal call with a response schema can return diarization-by-name, timestamps, language+translation, emotion, and a summary.
- [Direct TTS Voices With a Director's Note, Not a Voice Catalogue](../concepts/direct-tts-voices-with-a-directors-note.md) - a small base-voice set steered by natural-language performance direction replaces a large filterable voice library.
- [Orchestrate Generative Media From a Real-Time Voice Agent via Tool Use](../concepts/orchestrate-generative-media-from-a-realtime-voice-agent.md) - a live conversational model can gather a creative brief then call a media-generation model as a tool.
- [Treat Speaker Diarization as a Distinct, Unsolved Task](../concepts/treat-speaker-diarization-as-a-distinct-unsolved-task.md) - "who speaks when" has its own pipeline, its DER metric, and structural difficulties (unknown speaker count, permutation-invariant labels) that keep it unsolved in noisy multi-speaker audio.
- [Reconcile Diarization and STT for Speaker-Attributed Transcription](../concepts/reconcile-diarization-and-stt-for-speaker-attributed-transcription.md) - combining two specialist models into "who said what" needs an STT-agnostic orchestration layer, not a naive timestamp join.
- [Benchmark Voice AI on Distant-Mic Multi-Speaker Audio, Not Headset Single-Speaker](../concepts/benchmark-voice-ai-on-distant-mic-multi-speaker-audio.md) - leaderboard numbers measured on close-talk single-speaker audio overstate real multi-speaker, distant-mic performance.
- [Treat AI as an Interface Technology That Removes Human Burden](../concepts/treat-ai-as-an-interface-technology-that-removes-human-burden.md) - a participating voice interface needs multi-party awareness (who's speaking, whether words are meant for it), not just listening noises.
- [Treat the Prompt as a Batch Protocol, Not a Conversation](../concepts/treat-the-prompt-as-a-batch-protocol-not-a-conversation.md) - a spoken prompt box is still a one-slot batch protocol, so transcribing voice into "the box" does not make the interaction conversational.
- [Relax the latency budget by choosing voice-in, visuals-out over voice-out](../concepts/relax-the-latency-budget-with-voice-in-visuals-out.md) - the ~1 s visual response envelope is ~5x more forgiving than the ~200 ms voice-out envelope, so visuals-out ships responsive experiences without novel realtime architectures.
- [Hit soft-realtime latency with a fast model, eager inference, and prefix caching](../concepts/hit-realtime-latency-with-fast-models-eager-inference-and-prefix-caching.md) - a latency-prioritized fast model with async handoff, eager 1-2 s inference, and stable prefix caching keep a voice-driven experience inside the ~1 s envelope.
- [Condition ASR on Conversation Context and Domain Vocabulary](../concepts/condition-asr-on-conversation-context-and-domain-vocabulary.md) - feeding conversation state and domain lists into a decoder-only audio LLM turns entity recognition into a finite-list choice and halves domain word error rate.
- [Run Parallel Specialist Models Behind a Speak-Up Gate](../concepts/run-parallel-specialist-models-with-a-speak-up-gate.md) - running every specialist concurrently behind a cheap relevance short-circuit buys redundancy without paying a routing or handoff latency cost.

## Open Questions

- When a product needs word-level boundaries in synthesized speech, is forced alignment against the known text a better default than the acoustic heuristics this wiki records, and what does it cost?
- Which voice-agent workflows should accept extra latency for chained control rather than use a lower-latency speech-to-speech model?
- What audio-specific eval rubrics reliably measure brand fit, pacing, interruption handling, and conversational comfort?
- What benchmark data can evaluate turn-taking across pauses, incomplete thoughts, backchannels, barge-ins, and speaker-specific response timing?
- How should teams evaluate multimodal voice agents when the relevant context includes screen frames or camera input as well as transcript content?
- When is voice output enough over a visual-RAG backend, and when does the product need a fully realtime speech-to-speech architecture?
- Which contact-center fields can be auto-confirmed safely, and which always require operator validation before CRM sync?
- Which voice-device capabilities should be exposed through app editors and dev kits, and which should remain fixed platform behavior?
- How should teams set thresholds for semantic end-of-turn models so interruption behavior balances latency with the user's need to pause and think?
- Which voice products can tolerate prototype WebSocket transports, and which need WebRTC before user testing is meaningful?
- How should multilingual voice products decide when to auto-switch language, ask for confirmation, or constrain mixed-language turns?
- Which long-running enterprise voice tasks should stay synchronous with spoken status updates, and which should become queued follow-up work?
- What provenance and consent controls are sufficient for generated-voice features in high-risk domains?
