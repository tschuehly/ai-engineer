## Summary

Ian Butler reports bug-finding benchmark results from Bismuth and turns them into practical IDE-agent guidance: generic bug-hunting prompts create many false positives and alert fatigue, while scoped bug rules, explicit defect classes, test-backed fix validation, careful context management, component inventories, and thinking models improve the chance that agents find real defects.

## Notes

- In Bismuth's benchmark, several agents had low true-positive rates for bug reports; one agent produced 70 issues for one task and all were false, which the talk frames as unreviewable alert fatigue. (00:33-01:36)
- The talk argues that false-positive-heavy bug reports reduce trust in the agent and can cause real bugs to be ignored or shipped. (01:36-01:59)
- Rules files should include scoped instructions for security issues, logical bugs, named defect classes such as auth bypasses, prototype pollution, and SQL injection, and a requirement that fixes include passing tests. (02:10-04:10)
- Agents can lose logical links after reading code or after context compaction, so users should preserve key files, provide diffs, and ask for step-by-step component inventories that map classes, variables, and usage across the codebase. (02:24-02:48, 04:26-05:24)
- Thinking models performed better at bug finding and deeper reasoning in the benchmark, but the talk cautions that even thinking models showed run-to-run variability and incomplete holistic file inspection. (02:48-03:03, 05:30-06:33)
