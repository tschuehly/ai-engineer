## Summary

Nimrod Hauser shows how a public Playwright MCP server can be adapted for a production agent workflow by removing irrelevant tools, rewriting tool descriptions for the local task, adding deterministic runtime guardrails, composing intent-specific tools from generic ones, and moving mandatory brittle steps such as login outside the agent's decision loop.

## Notes

- The initial out-of-the-box Playwright MCP setup exposed 21 generic browser tools; generic descriptions such as keyboard press, browser resize, and page close were too broad for the spec-review workflow. 10:39-12:22
- The baseline agent failed by navigating to a made-up `/spec-reviewer` page and producing an unusable 404 evidence screenshot, showing that generic browser tools can degrade agent behavior rather than improve it. 13:13-14:12
- The first adaptation removed tools that the spec reviewer did not need, such as browser resize, drag, and browser code execution, reducing the available tool set from 21 to 16 and shrinking the agent's choice surface. 15:47-18:02
- The wrapping step kept the original Playwright tool implementation but replaced descriptions with task-specific guidance, such as preferring accessibility snapshots before hover or click actions. 18:10-22:24
- Deterministic guardrails validated screenshot output paths against an allowed screenshot root before invoking the tool, then returned an agent-facing correction message instead of crashing the whole run. 22:53-28:25
- The evidence screenshot tool was composed from the generic screenshot tool with a separate description and evidence-specific filename guidance, including ticket identifiers in the saved image. 28:47-32:33
- Login was handled outside the agent flow by directly calling MCP-provided browser operations and injecting JWT tokens into local storage, because every spec-review run needs login and login can involve secrets or client-specific mechanics. 32:49-36:30
- After curation, wrapping, guardrails, composed evidence tooling, and deterministic login, the demo agent produced a passing verdict with a ticket-named evidence screenshot, while the speaker noted pixel-perfect validation requires additional production work. 36:38-38:55
