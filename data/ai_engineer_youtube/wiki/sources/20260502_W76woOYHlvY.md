## Summary

Louis Knight-Webb argues that coding agents shift software engineering time away from direct code writing and toward planning, reviewing, QA, and shepherding changes. The talk distinguishes plan-heavy and review-heavy agent workflows, maps them to task types, and highlights the need for interfaces that manage parallel long-running agent work without constantly interrupting human focus.

## Notes

- As code generation tools improve from line completion to multi-step agents, the speaker says direct coding time shrinks while planning and reviewing consume the displaced effort; he treats AI as an accelerant, not a full return of coding time. (02:04-03:30)
- The plan-based approach spends more time upfront on plan documents, specs, and clarifying questions so the agent has fewer edge cases to miss and needs fewer review rounds. (03:53-04:56)
- The review-heavy approach starts from lighter prompts and accepts more back-and-forth review, which can fit exploratory front-end work but becomes expensive when half-delivered work repeatedly interrupts the human. (05:02-05:59)
- Task shape matters: front-end feature development is harder to fully specify because of state, interactions, animations, styles, and functionality, while back-end features, refactors, migrations, and maintenance can often be more plan-heavy and test-driven. (06:02-07:09)
- Longer agent executions make waiting behavior break down; once runs exceed roughly five minutes, humans need workflows for managing multiple concurrent tasks rather than watching one agent log. (07:26-10:26)
- Vibe Kanban is described as a tool for parallel agent workspaces, diffs, GitHub-style comments, previews, and running setup scripts in Git worktrees before invoking agents such as Codex. (10:26-15:28)
- Future coding-agent interfaces should help humans write tasks, QA work, review code, and shepherd changes through pull-request comments and deployment rather than only generate code. (11:47-14:01)
