## Summary

Brooke Hopkins argues that production voice agents need self-driving-style evaluation infrastructure: large-scale simulated conversations, probabilistic failure measurement, calibrated simulation realism, human-calibrated automated metrics, and continuous regression and monitoring loops.

## Notes

- Voice agents get stuck in pilot or proof-of-concept use because teams both overestimate near-term full automation and underestimate the narrower capabilities that can become useful with trust and scope, 00:56-01:48.
- Hopkins frames deterministic IVR-style control and unpredictable autonomy as a false choice; the desired target is autonomous behavior with reliability evidence, 01:51-02:32.
- Self-driving evaluation moved from manual road testing to brittle specific scenarios and then to large-scale simulation that measures event frequency across many runs, 03:04-04:01.
- Conversation simulation is valuable because each user or agent turn changes the next state; repeated runs expose possible paths and success probabilities, 04:16-05:32.
- Reference-free conversational metrics should ask how often the agent resolves the user inquiry, repeats itself, or says unsafe things rather than require exact expected outputs for every input, 05:34-06:36.
- Production voice eval loops should include local bug reproduction, larger regression sets, presubmit and postsubmit workflows, release evaluation, live monitoring, and feedback into future simulations, 07:04-08:05.
- Automated evals should scale the process, while human review remains important for judgment calls and for calibrating LLM-as-judge metrics, 08:15-08:31, 13:49-14:56.
- Simulation realism should match the behavior under test: text can cover workflow and tool-call iteration, voice-to-voice tests can cover interruption and latency, and hyperrealistic audio is most relevant for accent, background-noise, and audio-quality failures, 09:18-11:15.
- Voice-agent evaluation strategy should start from public benchmarks, add domain-specific data, run module or task evals, then validate the full production-shaped stack at scale, 15:16-16:01.
- Continuous eval processes should define what happens when production bugs are found, which test sets they enter, and which dashboards or customer/workflow-specific suites track ongoing quality, 16:53-17:32.
