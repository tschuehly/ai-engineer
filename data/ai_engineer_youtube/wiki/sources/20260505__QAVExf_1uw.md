# Demand-Driven Context: A Methodology for Coherent Knowledge Bases Through Agent Failure

## Summary

Raj Navakoti frames enterprise agent underperformance as a context-management problem: general model knowledge and explicitly taught skills are not enough when delivery depends on undocumented, stale, duplicated, or tribal institutional knowledge. The proposed demand-driven context workflow gives agents real work, observes where they fail, uses those failures to identify missing knowledge, and curates reusable context blocks so future agents can solve similar work with less human gap-filling.

## Notes

- Agents can already handle general coding tasks, PR review, and incident workflows, but enterprise delivery stalls when tasks require domain-specific institutional knowledge that is not present in model pretraining or explicit skills, 03:33-06:37.
- The talk separates task requirements into general knowledge the model already has, taught knowledge such as skills or conventions, and red-zone institutional or tribal knowledge inside the company and its people, 05:40-06:37.
- Building many RAG or MCP connectors over a messy knowledge monolith does not solve the problem by itself because the retrieved data may be outdated, unreliable, duplicated, missing, or tribal, 07:03-10:57.
- Demand-driven context is a pull workflow: assign real work, let the agent fail or ask questions, capture the missing information, and curate it for reuse instead of trying to push a complete knowledge base upfront, 13:01-15:45.
- The workflow resembles TDD: failures come first, missing context is added to pass the task, and repeated cycles gradually improve agent autonomy, 15:49-16:31.
- In the demo framing, the knowledge base can be represented as files, but the same persistence layer can sit behind MCP servers, RAG, Confluence, Slack, or other enterprise systems, 22:48-23:10.
