## Summary

Ruben Casas (staff engineer, Postman) frames the central tension of agent UI: frontier models (he names GPT-5.2 and Opus 4.5) now write high-fidelity front-end code "better than me" — a single "rewrite my blog" prompt produced a search box with a blur animation and accessibility he never asked for — yet most agent UIs still invoke static prebuilt components. He maps how agents generate UI along a three-point spectrum. **Static**: the agent is just an orchestrator; a tool call passes parameters/props to developer-built predefined components that the client renders (AG UI's SDK registers a client tool → React component; Goose's "Auto Visualizer" matches arbitrary data to predefined components) — the dominant pattern today and essentially 20-year-old server-data-→-client-render. **Declarative**: still predefined design-system components, but the agent emits a descriptor (JSON or YAML, or Python with FastMCP) that a translation/rendering engine maps to those components, so the LLM generates the JSON not the components (Vercel's JSON Render, recently adding YAML; Netflix server-driven personalization is the prior art) — Casas argues this is the right balance *today* for flexibility vs consistency, predictability, latency, and token cost. **Generative**: skip components entirely and let the model write HTML/CSS/JS on demand at runtime (call the same model with "reverse sampling" or a second model); his Postman weather agent fetches the API, writes a joke, and emits HTML/CSS/JS in one tool call with no component and no translation. The catch is trust: LLM-generated code is untrusted third-party code, so generative UI needs a distribution model with a boundary, containment, and a sandbox — which is why **MCP apps are the best delivery mechanism**: they ship auth, tool calling, and UI↔agent message passing and are sandboxed by default via the double iframe, work for first-party UI too (Anthropic's visualizer uses MCP apps rather than a bespoke renderer), and handle UI generated on the fly by coding models. He closes on the TV/radio analogy (early TV was "radio shows with cameras" because no one could imagine the new medium) — we are in the radio era of agent interfaces — and bets the future is "beyond components" toward human-agent collaboration on shared editable artifacts (the Excalidraw MCP app's shared canvas you can both prompt and click-edit), where generative UI is personalized *and* collaborative rather than one-shot output.

## Notes

- "Poor man's vibe coding" was the 2022 ChatGPT loop (ask for a component, copy-paste, fix, repeat); by late 2025 GPT-5.2 and Opus 4.5 were producing thoughtful, fast, working high-fidelity UI — motivating the question "if models write UI this well, why are we still stuck in mostly static UI?" (00:29-03:08)
- Karpathy framing: the new computer is "like talking to the terminal" with direct OS access but the GUI is not invented yet — we're in the '70s text era with super-intelligence but no mature interface language; chat is fine for now but not the final UI. (03:36-04:35)
- Two separate questions kept distinct: *where does the UI run* (third-party UI in a super app like ChatGPT/Claude/Gemini, vs "chat everywhere") vs *what is the model generating* — the talk is about the second. (04:40-05:45)
- Static UI = agent as orchestrator; tool call (via MCP apps or direct) passes data/props to developer-built predefined components, client renders; "very similar to what we've been doing for the past 20 years." Examples: AG UI protocol SDK (register a client tool that maps to a React component, props mapped to a static component), Goose Auto Visualizer (pass any data, Goose matches/organizes and routes to predefined components the Goose team built). (06:02-07:41)
- Declarative UI = predefined design-system components but the agent emits a descriptor (JSON/YAML, or Python via FastMCP) that a translation/rendering engine converts to the final UI; "more dynamic, more personalized" but "still static components — the LLM is generating the JSON, not the components." Netflix's personalized-but-component-mapped homepage is the same server-driven-UI idea, "not new." Vercel's JSON Render (JSON + recently YAML) is the current tool. Casas's call: declarative is "probably the perfect balance today" — keeps the design system and predictability, faster, potentially cheaper (fewer tokens than generating the whole UI). (07:42-10:06)
- Generative UI = skip components, let the model write HTML/CSS/JS on demand at runtime; instead of calling the layout rendering engine, call the same model with "reverse sampling" or a second model to generate the markup, passed to the client. Postman weather-agent experiment: hits the weather API, writes a joke, and emits HTML/CSS/JS "all in one tool call" → a random but imaginative UI where "everything is created by the agent — there is no component, there is no translation." (10:06-11:25)
- The trust problem: "if we don't trust third-party code, we should not trust code generated by LLMs and just present it to the user" — generative UI needs a distribution model that requires a boundary, containment, and a sandbox. (11:25-12:06)
- Why MCP apps are the ideal delivery mechanism: they provide auth, tool calling, and message passing between UI and agent, and are "sandboxed by default with that double iframe," the default for third-party UI delivery today; not just third-party — also first-party UI. Anthropic's visualizer feature uses MCP apps for first-party UI even though they could have built their own rendering/architecture mechanism, "because MCP apps provide most of those features out of the box" — "if Anthropic decided to use MCP apps for their first-party UI… why cannot we?" — especially apt when UI is generated on the fly by coding models. (12:06-13:21)
- TV/radio analogy: early TV shows were "radio shows with cameras" because no one could imagine the new medium; "we don't have enough imagination yet" and are still in the radio era of agent interfaces. (13:21-14:46)
- "Beyond components" → human-agent collaboration. The Excalidraw MCP app is not just diagram output/visualization: it creates a *shared artifact* — a canvas where human and agent collaborate, going back and forth ("change this") while the user can also click around and modify the UI directly the way they're used to — "don't just use agents as an orchestrator and delivery mechanism to show me some visualizations." Future of generative UI = super-personalized *and* collaborative. (14:46-16:16)
- Speaker is honest about uncertainty: "today is probably not the final form," "we don't have the answer," but "we can shape that future." (13:21, 16:16-16:44)
