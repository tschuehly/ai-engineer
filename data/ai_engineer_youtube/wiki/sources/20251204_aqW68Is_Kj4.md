## Summary

Katelyn Lesse describes Anthropic's Claude developer platform as three layers for agent builders: API controls that expose model capabilities such as thinking budgets and tool use, context-management primitives such as MCP, memory, and context editing, and sandboxed compute infrastructure that lets web or mobile agents write and run code persistently outside the user's local machine.

## Notes

- Anthropic describes its agent API direction as exposing model capabilities, managing the context window, and providing infrastructure for Claude to use a computer. 01:28-02:05
- Thinking is exposed as a budgeted API feature so applications can trade reasoning depth against speed for complex debugging or quick answers. 02:20-03:09
- Custom tools are defined with a name, description, and input schema; Claude Code uses many tools for reading, searching, writing files, and rerunning tests. 03:10-03:47
- MCP is framed as a standardized way for agents to interact with external systems such as GitHub or Sentry that hold information or tools outside the agent's current context. 04:31-05:08
- Memory is described as a client-side file-system-like tool where Claude can store and later retrieve codebase patterns or git workflow preferences only when relevant. 05:12-05:55
- Context editing removes stale tool results from the active window; Anthropic reports a 39% improvement on internal evals when memory and context editing were combined. 05:58-07:05
- Web and mobile Claude Code require secure remote execution, container orchestration, and session persistence because the agent cannot rely on the user's local machine after the user walks away. 08:21-09:12
- Skills are folders of scripts, instructions, and resources that Claude can select by description and run inside the sandbox, while MCP supplies external tool and context access. 10:09-10:47
