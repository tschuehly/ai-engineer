## Summary

Geoffrey Litt (design engineer at Notion) argues that as agents land 50,000-line PRs it gets harder to keep up, but the common framing — "we understand in order to *verify* correctness" — is subtly wrong, because agents are getting better at correctness checking and the human's role there is shrinking. The deeper, durable reason to understand is to *participate*: each review loop changes you, and that accumulated understanding is the foundation for having the next idea and being an active creative participant across loops; letting it degrade builds "cognitive debt" (Margaret-Mary Storey's term, an analogy to technical debt, also blogged by Simon Willison) until you can no longer contribute. He then borrows the best ideas from education and cognitive science to *build* understanding fast with agents, via three techniques: (1) agent-authored **explainer docs** that teach the change (background first, intuition before details, tasteful interactive figures, and "literate code diffs" — prose in the right order instead of a raw diff), packaged as a shareable `explaindiff` skill; (2) a **comprehension quiz** at the bottom of each explainer that acts as a "speed regulator" — you don't send code to review until you can pass it (Andy Matuschak's "Books don't work" + Michael Nielsen's spaced-repetition-quiz essays); and (3) **microworlds** — ephemeral UIs, debuggers, and simulations an agent builds so you can *feel* how code works (Seymour Papert's Mathland/Logo turtle), e.g. a timeline-scrubbing debugger for a Prolog interpreter and a click-through "video game" to do a framework migration step-by-step. A fourth thread is collective/shared understanding on a team (multiplayer human+agent chat threads, commentable collaborative documents, and coding agents like Claude and Cursor running inside Notion). The closing frame invokes Alan Kay's 50-year-old "A Personal Computer for Children of All Ages": computers were meant to level up humans, and because "code is free" now we can build ephemeral UIs and simulations to understand better than ever — putting ourselves *more* deeply in the loop, not out of it.

## Notes

- Hot take that opens the talk: it is still important for humans to understand how code works; agents are landing 50,000-line PRs and it is getting harder to keep up. (00:29-01:22)
- The common (subtly wrong) framing is "understand to verify": agents do dumb stuff and the human keeps them in line; but correctness can be specced/architected/tested and agents are getting better at it, so the human role in correctness checking is decreasing — which Litt says he doesn't hate when he has a clear idea and the agent does it right. (02:42-03:52)
- The deeper reason is "understanding to participate": it's not one loop; reviewing changes you, and that understanding is what you carry to the next loop and the next. Rich conceptual structures you can fluently recombine (without going out to ask an agent/human) let you take creative leaps — "the human part of the work." (04:08-05:20)
- Cognitive debt (Margaret-Mary Storey; Simon Willison also blogged it) is the technical-debt analogy: you get away with it while vibe coding, then realize you have no idea what's going on and "basically can't participate anymore." (05:26-05:40, ~05:56)
- Reframes the "how" as an education problem — take inspiration from the best ideas ever invented in education. Three techniques. (06:00-07:20)
- `explaindiff` skill: outputs a code-explainer doc (HTML or Markdown; he puts them in Notion so the team can comment). Order: **background first** (teach the system/engine/coordinate system before the change), **intuition before details** (a deeper commit message, examples, essence before code — "what good math teachers do"), **interactive figures** where they help (drag rocks in a sim showing coordinates/Z-layers — using Notion's HTML blocks launched that morning; caution: interactivity can be a crutch/slop), then **literate code diffs** (prose explaining files in the right order, not a raw diff). He prints them out and reads them at a coffee shop "like a textbook about this PR." (07:24-09:55)
- Quiz as speed regulator: reading is hard and people fool themselves into thinking they understood (he once failed a coworker's most basic question on a PR). Andy Matuschak "Books don't work" + Michael Nielsen embed spaced-repetition quizzes so you can't get through an essay without remembering it. So each explainer ends with a 5-question, medium-difficulty quiz; his rule: don't send code to reviewers unless he can pass the quiz. It's the regulator that keeps him moving at the speed of *understanding*, not just correctness. The `explaindiff` skill is public via QR code (HTML and Notion variants). (10:19-12:00)
- Microworlds (Seymour Papert's "Mathland"/Logo turtle — the point isn't the robot, it's that the kids are changed): have Claude build a throwaway debugger to visualize a Prolog interpreter's internal state on a scrubbable step-by-step timeline (with a commenting feature to leave notes) — used to fix narrow bugs *and* get "a feel for the machine," the peripheral vision you don't get when an agent just fixes the bug. Second example: migrating his personal website between frameworks — instead of trusting a one-shot script he didn't have a feel for, he had Claude build a "video game" (old site left, new site right, click Next through each step with visible commands and moving file trees) to get the benefit of doing it iteratively without the pain. Takeaway: agents can write code whose point is to help you understand code, not to ship. (12:06-14:50)
- Shared spaces / collective understanding: teams need shared understanding (shared names for parts of a system) to communicate and jam. Notion is exploring multiplayer chat threads with multiple humans and agents in one space (like moving from one-on-ones to Slack channels — you see each other's agent conversations), and commentable collaborative documents (comment on an agent's plan and discuss it with teammates in place). Notion launched bringing coding agents (Claude, Cursor) into Notion the prior week; their team builds a lot of code in Notion for these shared-space benefits. (15:03-16:55)
- Closing frame: Alan Kay's 50-year-old essay "A Personal Computer for Children of All Ages" envisioned kids modifying a game's code as they play to learn physics — computers to level up humans, a vision Kay says computers "detoured" from. With AI, "code is free," so we can make ephemeral UIs, dynamic simulations, debuggers, and playgrounds to understand concepts — this was the goal all along, and the optimistic bet is to put ourselves *more* deeply in loops than ever, not take ourselves out. (17:37-18:50)
