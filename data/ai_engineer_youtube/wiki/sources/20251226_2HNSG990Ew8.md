## Summary

Aman Khan frames evals as the production discipline that lets PMs move AI features beyond vibe checks: LLM systems are nondeterministic, manipulable, data-dependent, and often multi-path, so PMs need traces, datasets, human labels, code checks, and LLM judges that are calibrated against product goals.

## Notes

- Evals are analogous to software tests, but LLM agents differ because they are nondeterministic, manipulable, can take multiple paths, and rely on enterprise data as part of both product behavior and evaluation. 07:58-09:18
- An LLM judge prompt should define role, context, goal, terminology, and labels; the surrounding system can map labels to scores when a numerical value is required. 09:19-11:28
- The workshop distinguishes LLM-as-judge evals from code-based checks and human annotations, positioning LLM judges as a scalable production eval pattern rather than the only eval type. 11:34-11:59
- Vibe-based acceptance is acceptable for prototypes but weak for production; the talk reframes the workflow as using data to gain confidence while iterating on the same AI-generated application. 12:03-12:57
- In the trip-planner demo, Phoenix/Arize traces expose input, output, metadata, and multi-agent actions so PMs can see what the agent is doing under the hood. 18:50-21:21
- Trace-backed prompt playgrounds let teams pull prompt variables and agent outputs into an interface where product owners can change inputs, inspect outputs, and build eval datasets from observed behavior. 23:31-25:21
