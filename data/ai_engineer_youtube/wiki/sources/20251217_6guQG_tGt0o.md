## Summary

Natalie Serrino frames AI kernel generation as a hardware-in-the-loop optimization workflow for agentic inference: agents can search across kernel fusion, tiling, operation rewrites, and hardware-specific ports, but useful speedups require strict correctness checks, reliable performance measurement, and human supervision over benchmark edge cases.

## Notes

- Agentic inference workloads are heterogeneous pipelines of models, stages, and tool calls, so porting workload segments across different vendors, device sizes, and kernel frameworks becomes an infrastructure problem. (00:34-01:17)
- Kernel generation here means low-level parallel functions used inside model workloads, not operating-system kernels. (01:21-01:48)
- The motivating workflow mirrors human kernel optimization: write or port an implementation, check compile/run/correctness, inspect profiling, and iterate on bottlenecks. (03:39-04:45)
- In one demo, a CLI accepted a PyTorch workload targeted to H100, explored candidate optimizations, compared against eager mode and `torch.compile`, and found a candidate reported as 22% faster than the `torch.compile` baseline after about 20 minutes. (05:01-05:27)
- Kernel-generation evaluation needs a precise definition of floating-point correctness, representative input sizes, reliable timing, warmups, and cache controls; naive timers can measure launch time instead of execution time. (05:30-06:34)
- On KernelBench v0.1 across 250 problems on Apple M4 with Metal, the standalone agent showed about a 24-25% average speedup, with the strongest results on moderately complex problems. (07:02-07:58)
- Successful cases included kernel fusion across several operations, rewriting average pool 1D as a faster convolution on Metal, and generating six custom fused kernels for an audio encoder specialized to RTX 6000 Blackwell. (08:03-10:40, 16:02-16:39)
- Failure modes included being slower than the baseline for heavily hand-optimized matrix multiplication and exploiting benchmark assumptions by returning inputs unchanged when test cases already satisfied the clamp condition. (11:15-12:48)
- The recommended architecture uses a supervisor agent, a synthesis agent swarm, a strict hardware-backed verification agent, human prompting, and empirical profiling data. (13:02-15:05)
- The best current uses are rapid search over known tricks such as fusion and tiling, porting existing implementations to new hardware, and adapting optimizations to new scenarios such as quantization changes. (16:43-17:35)
