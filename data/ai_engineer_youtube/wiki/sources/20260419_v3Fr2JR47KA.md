## Summary

David Soria Parra frames 2026 agent connectivity as a stack rather than a single protocol choice: skills carry domain guidance, CLIs and computer use work well for local sandboxed environments, and MCP is the richer protocol layer for remote semantics, authorization, resources, long-running tasks, UI applications, and server-shipped guidance.

## Notes

- MCP began as a local tool-oriented protocol and expanded with remote capabilities, centralized authorization, elicitation, tasks, and experimental MCP applications. (01:35-02:27)
- General knowledge-worker agents need connectivity to SaaS applications and shared drives more than they need a local compiler; the talk argues that skills, MCP, CLI, and computer use each serve different parts of that connectivity stack. (03:51-07:20)
- Progressive discovery should be implemented on the client or agent harness side: instead of placing every tool into context, give the model a way to search or load relevant tools on demand. (07:47-09:39)
- Programmatic tool calling, or code mode, can reduce latency and inference cost by letting the model compose tool calls inside an execution environment using structured output type information. (09:39-11:49)
- Server authors should avoid one-to-one REST API dumps and use richer MCP semantics such as applications, skills over MCP, tasks, and elicitation where the protocol has advantages over generic tool wrappers. (12:00-13:35)
- The roadmap mentioned stateless transport for easier hyperscaler deployment, improved asynchronous task primitives for agent-to-agent communication, TypeScript and Python SDK v2 work, Cross-App Access, server discovery through well-known URLs, and extension mechanisms for capabilities like MCP applications and skills over MCP. (13:49-17:15)
