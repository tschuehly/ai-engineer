## Summary

Kevin Hou presents Google Antigravity as an agent-first developer platform built around an editor, an agent-controlled browser, and an agent manager. The useful patterns are an orchestration surface for many background agents, browser-based context retrieval and visual verification, dynamic artifacts for plans, task lists, diagrams, screenshots, recordings, walkthroughs, comments, and memory, and a product/research loop where real IDE use reveals model and harness gaps.

## Notes

- Antigravity is described as an AI developer platform with three surfaces: editor, browser, and agent manager; the agent manager is the central agent-first view, while the editor and browser become tools for the agent. 01:45-04:32
- The agent-controlled Chrome browser can use the same authentication context as the user for docs and dashboards, can click, scroll, run JavaScript, retrieve DOM context, and produce recordings as verification evidence. 03:14-04:24, 09:48-10:27
- The agent manager includes an inbox for actions needing attention, such as terminal-command approval, and OS-level notifications so multiple agent tasks can run without constant log watching. 04:39-05:13
- Hou frames new product paradigms as following model capability shifts: autocomplete, chat, agents, and then agent-first surfaces enabled by better reasoning, tool use, long-running work, and multimodality. 06:11-08:16
- Browser use supports both context retrieval and verification: software work depends on docs, dashboards, experiments, and institutional knowledge, while browser recordings and screenshots can prove what the agent did. 08:48-10:27
- Artifacts are dynamic agent-generated representations such as plans, task lists, architecture diagrams, screenshots, screen recordings, walkthroughs, and images; they communicate progress and evidence more readably than raw chain-of-thought-like token streams. 12:26-16:44
- Artifacts can be scoped to users, subagents, other conversations, or memory, and can preserve derived API understanding so future tasks do not rederive it. 16:49-17:35
- Comments on text or image artifacts let users provide batched feedback during execution without forcing a full stop in the agent loop. 17:37-19:20
- Product dogfooding inside DeepMind lets researchers and product engineers see where model capability, computer-use data, instruction following, image generation, or harness/tool design need improvement. 20:31-23:32
