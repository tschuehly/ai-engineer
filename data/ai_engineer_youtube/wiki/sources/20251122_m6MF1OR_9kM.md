## Summary

Yuxuan Zhang describes GLM 4.6 as an open-weight frontier model shaped by staged pretraining, repo-level code contexts, synthetic reasoning traces, long-context agent data, and a SLIME reinforcement-learning framework that separates short synchronous reasoning tasks from slow asynchronous agent trajectories.

## Notes

- GLM 4.6 is presented as part of a long-running open model family with more than 65 released models and more than 100 million downloads across Hugging Face, ModelScope, and other platforms. (00:23-02:10)
- CC-Bench 1.1 evaluates agent-style coding beyond isolated algorithm problems, with 74 tasks spanning front-end development, internal tools, data analysis, and algorithm implementation, while recording full agent trajectories including queries, planning, tool calls, code edits, and execution. (03:36-04:45)
- The training pipeline starts from about 15 trillion general pretraining tokens, then adds about 7 trillion code and reasoning tokens, moves to repo-level code contexts at 32k context length, then adds synthetic reasoning and long-context agent data for long-context and agent capability. (05:16-07:50)
- SLIME uses colocated training and inference for short math or code-completion tasks, but moves to decoupled asynchronous rollout workers and a buffer for slow real software-engineering tasks involving browsers, APIs, external responses, and multi-step environments. (07:51-10:19)
- The talk argues for single-stage 64k-token RL after long-context SFT because shorter multistage context schedules can make the model forget long-context ability and fail to recover it later. (11:51-12:48)
- For coding RL, token-weighted loss averaged over tokens rather than sequences converged faster and more steadily, and reduced very short template answers that only chase reward. (12:55-13:24)
- For scientific reasoning RL, a smaller expert-verified high-quality multiple-choice dataset outperformed a larger mixed-quality dataset, so data quality mattered more than raw size. (13:27-14:03)
- GLM 4.5V keeps visual input closer to native resolution and aspect ratio instead of forcing every input into a fixed square, and adds time-index tokens to video frames so the model can reason about temporal order. (14:35-15:30)
