## Summary

Soheil Feizi (founder/CSO of RELAI, CS professor at University of Maryland) frames continual learning for AI agents as letting an agent learn from its own production experience — act, get feedback, improve — without forgetting prior capabilities. He splits the problem into two challenges: where feedback comes from (benchmarks at dev time; production logs plus automatic or human-expert feedback at runtime — but a log-plus-feedback pair is *one observation* and is not yet testable), and how to act on it (three update layers: model weights via SFT/RL/LoRA, harness via prompts/skills/tools/code, and memory via facts/skill-distillation — each with different cost and verifiability). His central contribution is **verifiable continual learning (VCL)**: improve an agent so every fix is proven to help and proven to break nothing, via an executable test, a measured before/after delta, and a regression test. He argues a practical VCL rests on four principles — replayability (lift a one-off failure into a replayable learning environment with inferred tools, synthetic users, and evaluators), holisticness (route the fix to the right layer with the smallest durable change), lifelongness (regression-aware optimization that fixes new failures subject to no regression on past environments, in-loop not post-hoc), and efficiency (the loop and the regression control must run continuously without scaling linearly in the number of past environments). RELAI packages this as a learning loop (signals → learning environments → root-cause routing → regression-aware optimization → reviewable version PR) added to an existing agent with a one-time harness setup plus two commands.

## Notes

- Continual learning imitates human learning from experience — act, get feedback, improve without forgetting; for agents, improvement can happen in the model layer (change/swap model weights), the harness layer (context: prompts, skills, tools, code, workflow), or session/persistent memory. (00:30-01:44)
- Two fundamental challenges: (1) how to get feedback — how do we know if the agent did well, and what should it have done instead; (2) how to act on feedback — which layer/component to change, and how. (01:48-02:26)
- Feedback source, dev time: a curated benchmark plus evaluators gives pass/fail/reward scores; this is what teams use during development. (02:34-03:04)
- Feedback source, production: no benchmark, only logs (e.g. a session where a user is unhappy but gives no explicit signal). Two ways to add feedback — automatic (another model/LLM/code analyzes the log; the agent can even critique its own log; scalable) and human-expert (a handful of logs reviewed by domain experts; low volume but high-value, encoding how you want the agent to behave). (03:08-04:14)
- A log plus feedback is still not enough because it is not testable — "one instance of what happened." What is needed is a replayable learning environment: a simulation that can be rerun with defined grading of what success looks like. (04:14-04:43)
- Building a learning environment = inferring a distribution from one observation: infer how tools should behave (real vs mock tools, and what data feeds the mocking), infer synthetic users from the interaction, and infer the evaluators that define success. If done well, the output is executable — you can run different agent candidates against it, observe behavior on that pattern, and fix issues because everything becomes testable/verifiable. (04:43-06:15)
- Three update layers with tradeoffs. Model layer: SFT (imitate correct trajectories, needs labeled samples), RL post-training (DPO, GRPO, RLVR — sample, score against reward/preference, reinforce winners), LoRA (limits changeable parameters → cheaper and safer); expensive, and these need benchmarks and explicit evaluators unless logs are turned into replayable environments. Harness layer: trace-to-harness (ask a coding agent to analyze the log and improve the agent — works on log+feedback but is "vibe-based," untestable, risks hidden regressions) and prompt-search methods like GEPA (mutate prompts, score candidates, keep winners via evolutionary search — testable but needs a benchmark/evaluators). Memory layer: write facts / distill skills (Letta, Mem0; skill distillation compresses successful trajectories into reusable how-to skills) — cheapest and fastest, works directly on log+feedback, but usually unverified (no way to test whether the write fixes the issue or creates regressions). "A good learning engine should ask for the smallest durable change at the right layer." (06:15-11:01)
- Verifiable continual learning (VCL): improve an agent from its own experience where "every fix is proven to help and proven to break nothing that already worked," via three steps — an executable test (the failure becomes a replayable task), a measured delta (score the update before/after), and a regression test (prior tests still pass after the change). (11:04-11:47)
- Four principles of practical VCL: (1) replayability — turn a one-off failure into a rerunnable test by lifting log+feedback into a learning environment; (2) holisticness — one failure may have several causes/repairs (a stale-policy citation that skips escalation could stem from stale memory, an unoptimized prompt, a tool that doesn't normalize policy, a missing workflow escalation gate, or a weak reasoning model), so route the fix to the layer(s) that explain it with the smallest durable change; (3) lifelongness — a new fix must improve the new case without breaking the past; given K past learning environments and a new one E(K+1), regression-aware learning treats regression as an in-loop mechanism (fix recent failures subject to no regression on past environments), not post-hoc, and must not scale linearly in K; (4) efficiency — the loop must run frequently, with efficiency both in the per-layer update cost (memory cheap, prompt/harness medium, model weights expensive) and in the optimization loop itself. (11:47-15:31)
- RELAI's learning loop: start with signals (logs, feedback, or instructions/prompts) → lift to replayable learning environments (replayability) → root-cause analysis and route fixes to memory/harness/model (holisticness) → regression-aware optimization (lifelongness) → run efficiently (efficiency); output is a reviewable version update (a PR) explaining what changed and why it improves the agent without regression. Added with a one-time learning-harness setup (bring your own LLM, any major agent framework) plus two commands: create learning environments, then optimize. (15:44-18:14)
- Demo/benchmark: a fictional tool-using support agent with a single source of truth, interacting policies, deterministic evaluators, and a built-in *regression trap* (overfitting the latest fix breaks previously-passing tasks). From the instruction "caller is rude and adversarial" alone (no logs), it builds a learning environment with personas, intents, mock/real tools, and evaluators; simulating scores 78% with two low-scoring evaluators; one optimize loop lifts the average ~10% (to 97%). A production example lifts a log plus feedback ("keep fast eligible refunds, but do not generalize generosity beyond refund thresholds") into an environment and optimizes without regressing past behavior — compounding over time. (18:16-21:33)
- Three takeaways: (1) agent continual learning is not necessarily model fine-tuning — many useful updates happen in the harness and memory layers; (2) production logs are not learning environments — transform them into replayable environments to simulate and evaluate on the same patterns; (3) the frontier is regression-aware continual improvement — when fixing a new failure, verify you don't forget the old ones. (21:35-22:26)
