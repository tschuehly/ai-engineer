## Summary

Alex Volkov (host of ThursdAI, AI evangelist at Weights & Biases / CoreWeave) turns the industry argument "how much better do models have to get before you stop reading the code?" into an operating framework. Two AI Engineer Europe talks anchor the debate: OpenAI's Ryan Lopopolo said "code is free… humans no longer need to concern themselves with implementation," while Mario Zechner (creator of Pi) said "slow the f*** down and read every effing line." Volkov names the axis between them the Z/L Continuum, then delivers his mea culpa: the continuum is real but it is about *tasks*, not people. The same engineer is a Lopopolo on one change and a Zechner on another; the useful question is no longer "should I read code?" but "what proof does this specific change need?" He distills a routing table (his "Monday artifact") that maps a change to the review it needs, shows survey/production data that output is up but stability is not, and argues capability drift moves *where* proof belongs (outputs → task direction → loops) without ever removing the requirement for proof. He closes on self-verifying loops as the emerging 2026 primitive, warning that a builder that grades itself hasn't removed review — it has hidden it.

## Notes

- The framing: two opposite talks, both standing ovations. Lopopolo — "code is free… free to produce, free to refactor… the important thing is not the code but the prompt and the guardrails" and "you can just say do not produce slop… but that requires taking short-term velocity hits to double-click into what the agents are struggling with." Zechner — "agents are compounding boo-boos with zero learning and delayed pain… non-critical code, write slop ahead; critical code, read every line." (00:12-13:xx)
- Output-is-up evidence: METR shows models for the first time completing tasks that take engineers 16+ hours (00:01-01:xx); GitHub on track for ~14 billion commits this year vs ~1 billion in all of 2025 (14x), mostly AI-assisted (02:59); 80%+ of Anthropic's code is AI-written, shipping 8x more code per quarter than 2025 (02:28); Faros AI's April 2026 survey of 22,000 engineers ("the acceleration whiplash") shows 861% increase in code deletion per PR (09:10-09:15). Swyx collects "what broke the trendline" evidence at wtfhappened2025.com.
- Stability-is-not evidence: Anthropic's status page "looks like a Christmas tree," GitHub also has downtime — "output does not mean stability" (10:05-10:23). Same Faros survey: 31% increase in PRs merged with no review at all, human or agentic ("don't do this, I beg of you"), 242% increase in incidents per PR (10:33-10:52); a second study shows bugs per developer up 6x vs 2025 (10:59).
- Human review is the new bottleneck: Anthropic's "recursive self-improvement" (RSI) essay says the likely future is engineers 10x–1000x-ing output, at which point "human code review has become a new bottleneck," citing Amdahl's law — an explosion of productivity in one area blocks another. Nobody removes the human; both OpenAI and Anthropic keep hiring engineers (11:44-11:46).
- Mea culpa: "The continuum is real, but it's not about the people. It's about the task." Same engineer is Lopopolo on one piece of code and Zechner on another; "different tasks just need different proof." (12:17-12:24)
- Both extremes converge: Lopopolo's mechanism is "move attention up the layer" — humans are unreliable at catching repeated same-type mistakes, so when you catch one in review, write the doc/linter/reviewer once so the system catches that bug class; "inspect the system, not every line" (13:18). Zechner's mechanism is "route by task" — non-critical let it rip, critical read every line; how do you know what's critical? "read the effing code." Volkov's addition: ask your agent ("clanker") — it's good at scanning a large repo and flagging which lines/primitives are critical (13:49).
- The routing table ("your Monday artifact," a slide meant to be screenshotted): read every line of authentication, money movement, permissions, and irreversible data; inspect the critical path yourself; decompose long PRs into atomic reviewable PRs (agents are great at this); verify with traces, evals, shadow mode; separate the writer from the reviewer/tester ("if I came up with an exam and then took it and scored myself, it's not productive"); engineer rails, observability, rollback — "build the system that builds the system, because read spends your attention once." (14:35-15:40)
- Capability drift: the continuum is a temporary place in time; capability increases push everyone toward the Lopopolo end. The review layer moves — yesterday inspect outputs/read code, today inspect task direction, maybe tomorrow inspect the loops. "Capability drift changes where proof belongs; it doesn't remove the requirement of proof." (17:42-17:57) Jared (Anthropic) on Fable 5 / Mythos: "We used to check if Claude is doing the work right; now I check if Claude is doing the right work." (16:28) Karpathy: "It's never felt so tempting to stop looking at code at all. But don't do this in production." (~16:45)
- Loops as the next primitive: Peter Steinberger (creator of Open Claude, now OpenAI) and Boris Cherny (Claude Code) both started talking about loops within ~2 days (18:36). Loops = "fancy cron jobs that run on a schedule" that discover a task, write the plan/prompt, execute, and — crucially — verify themselves and retry on failure (19:21). Caveat: "if the builder grades itself, you didn't remove the review, you hid it" (19:45). Addy Osmani (Google): relying entirely on automated loops to fix code (a Jira bug the loop picks up) would make product quality suffer — "a downward spiral, digging a deeper hole" (20:07). "Loops don't remove judgment, they raise the stakes on where you put it" (20:13). Lab engineers have free tokens, so treat them as a lighthouse of where things go ("skate where the puck is going"), not immediate advice.
- Closing line: "Not every line in 2026 needs your eyes. Every system still needs your judgment." (21:13)
