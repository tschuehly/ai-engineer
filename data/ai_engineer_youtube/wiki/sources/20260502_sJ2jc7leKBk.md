## Summary

Radek Sienkiewicz describes growing a personal OpenClaw agent from a single chat channel into an always-on system with access to email, notes, calendars, local files, scripts, Discord channels, and a large Obsidian knowledge base. The useful pattern is incremental trust: add one small workflow, observe failures, add guardrails or rollback, then expand autonomy only when the previous step is reliable.

## Notes

- The agent received access to email, notes, files, calendars, operating-system automation, and memory step by step rather than all at once (00:32-01:23).
- The rollout pattern is to start with one channel and one simple workflow, then add another step after the previous one works (01:48-02:17).
- Incremental rollout limits blast radius: when something breaks, the operator can step back, fix the issue, understand the cause, and add prevention before moving forward again (04:02-04:47).
- The Obsidian vault contains roughly 3,000 Markdown notes across work, personal tasks, projects, research, articles, and link inboxes, and OpenClaw can search and connect that material (04:53-06:17).
- Inbox automation analyzes saved links from tweets, articles, threads, and YouTube videos, adds tags and context, looks for related notes, and surfaces prior knowledge that might otherwise be forgotten (07:30-08:45).
- Overnight jobs index, back up, refresh memory/search indexes, summarize email and calendar, and prepare an updated system for the morning (08:59-10:25).
- The system separates LLM judgment from deterministic scripts: LLMs handle understanding and connection-making, while scripts handle known "if this happens, do this" cases without model judgment (14:56-15:19).
- Failure modes include compounding bad memory, brittle multi-step automations, noisy nodes, and weak boundaries; mitigations include inspectable Markdown memory files, critical rules near the top of agent instructions, cleanup, simpler automations, and guardrails (15:22-17:20).
