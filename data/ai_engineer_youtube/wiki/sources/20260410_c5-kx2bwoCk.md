## Summary

Mozhgan Kabiri chimeh frames local LLM workstations as a practical middle ground between laptop experiments and shared cloud or data-center infrastructure: local serving can improve iteration speed, privacy, cost predictability, and latency, but only when model size, quantization format, memory bandwidth, and reproducible benchmarking are measured directly.

## Notes

- Local serving becomes attractive when cloud or shared infrastructure introduces queueing delays, unpredictable cost, data-residency concerns, or nondeterministic latency. 00:38-01:36
- The talk describes DGX Spark/Jetson Spark as a desk-side Grace Blackwell system with 128 GB unified memory and the same NVIDIA AI software stack used in production environments, allowing desktop-to-cloud workflow portability. 01:39-02:37
- The benchmark setup used vLLM inside an NVIDIA-optimized container against quantized models from 1.5B to 14B parameters. 02:40-03:04
- The benchmark harness isolated the environment with Docker, ran three mandatory warmups, logged GPU metrics every second, and wrote timestamped per-model artifacts with responses, metadata, and metrics. 03:09-04:05
- Time to first token was measured by timestamping the first streaming chunk from the vLLM server, because perceived responsiveness depends on when output begins, not only total completion time. 04:13-05:03
- In the reported throughput chart, a 1.5B instruct model delivered 61.73 tokens per second, a 14B NVFP4/NVFB4 model delivered 20.19 tokens per second, and the unoptimized 14B base model delivered 8.40 tokens per second. 05:34-07:11
- The talk's central caveat is that memory capacity and memory bandwidth are different constraints: 128 GB unified memory can fit large models, but throughput depends on how efficiently data moves, so quantization format can be as important as hardware choice. 08:37-09:18
