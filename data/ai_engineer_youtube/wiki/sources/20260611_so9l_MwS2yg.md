## Summary

Zack Proser (Applied AI team, WorkOS) argues that as coding agents scale toward infinite parallelism, the durable hard constraint is no longer agent capability but human attention, which degrades under load. He cites Simon Willison firing up four parallel agents and being "wiped out by 11am" as the shared symptom. The talk proposes a personal-sustainability stack of four layers that keep an individual developer in balance: (1) a signal layer where agents read Slack and Linear on a loop, deduplicate asks, and surface only real high-priority tickets so the human never opens those apps and gets pulled off task; (2) voice-first dictation (~184 wpm vs ~90 typing) that lets one developer drive several agent windows in parallel and work away from the keyboard; (3) remote control of a Claude Code session that runs on the dev machine but is driven from a phone over LTE, tied to the "shower principle" (focus vs diffuse cognitive mode) so insights captured while walking are applied without returning to the desk; and (4) a self-improving harness that runs a scheduled pass over locally stored JSONL conversation history to find high-token or high-back-and-forth struggle patterns and generate the missing skills or MCP servers. He frames "speed requires safety" as an escalating verification ladder (lint/build/unit-test hooks → browser click-through → a constitutional critic agent), and closes with a holistic-wellbeing note: an Oura ring connected via MCP lets Claude flag that you did not sleep before pushing a long session. The default path with these tools is "burnout turbo"; the intentional path delegates minutiae while the human stays responsible for quality, review, and shipping.

## Notes

- The framing: tools are "nuclear" while the human nervous system is "ancient"; agents can loop infinitely until they hit the verification criteria you give them, but human judgment and taste (knowing something is actually solved) remain the scarce input. (03:36-05:12)
- Concrete opening example: gave Claude Code read/write access to Slack (it already had Linear ticket access via MCP), told it to fix a sentence-case bug mangling acronyms and to verify its own work and not stop until done; he returned to a completed, verified loop without having to re-prompt. (01:09-02:49)
- Signal layer: combing Slack himself is ~80% likely to get him distracted by another thread; instead Claude Code reads Slack on a loop to find @-mentions, DMs, and high-priority asks, and deduplicates them against Linear to find the real tickets — a "facade" that preserves focus. (06:01-06:49)
- Voice-first: dictation reaches ~184 wpm vs his ~90 wpm typing peak; this enables parallel workflows where he speaks across three Cursor windows, Codex, and Claude tabs so agents are running while a typist is still on their first prompt; compounds over years. (07:04-08:15)
- Remote control: a Claude Code remote-control flag/config keeps the session on the dev machine (filesystem access) while he drives it from his phone on LTE/CDMA miles away; ties to the shower principle — focus mode (IDE) is good for execution but prone to blind spots, diffuse mode (walking) yields full-form creative solutions; remote control means leaving the desk no longer means stopping work, and reduces RSI. (08:15-13:22)
- New balanced day: deep-focus morning (clear GitHub backlog/SDLC chores into Codex, start the features you care about in an IDE or Claude Code), then walk away after work tracks are running, review PRs from the phone, and leave natural-language comments on GitHub-mobile PRs (@Claude, @cursor agent, @Vercelbot) that "most of the time" land correctly with Opus 4.6. (12:05-13:22)
- Self-improvement: Claude Code conversations are saved locally as JSONL files; a scheduled (weekly/daily) pass has an agent review them for patterns where you spent many thinking tokens or went back-and-forth to remove ambiguity, find the missing skills/MCP servers (the "delta"), and tighten the loop; treat sessions as "gold." Claude Code has a built-in skill to build, evaluate, improve, and author bespoke skills from a natural-language prompt. (13:22-15:31)
- Q&A caveat on history mining: raw JSONL is "not really meant for AI consumption," gets long and full of junk; pointing Claude straight at it works, but a hook at session-end / PR-merge can extract the key bits (especially where you struggled) into a separate store (Obsidian, flat markdown, an archive) before the weekly analysis. (20:07-21:30)
- Verification gates ("speed requires safety"): gate 1 = minimal lint/build/unit test enforced every run via hooks; gate 2 = the agent must verify with a browser, clicking through to ensure it did not break (e.g.) login, enabled by `--chrome` and emerging computer-use; gate 3 = closer to Anthropic's constitutional AI, where a separate agent checks the work against a constitution and returns actionable feedback. (11:13-12:05)
- Holistic wellbeing: connected an Oura ring via MCP (GitHub projects exist) and gave it to Claude, which sometimes refuses to do the whole task ("you didn't sleep last night") — you can override it, but at least you considered a break; default path is burnout-turbo, intentional path preserves the human. (15:31-16:50)
- Q&A — early-career skill development: best advice is "don't use AI to do something you don't already know how to do"; build battle scars by hand so you can immediately catch hallucinations/bad ideas, and use LLMs to go deeper faster ("test me, where is my mental model murky"). (17:35-20:07)
- Q&A — night shift: experiments with cron-scheduled night-shift agents producing content (reviewed and mostly discarded in the morning); aspiration is Linear tickets for everything, an "agent ready" tag, and a loop running every 15 minutes day and night; also uses a phone/Twilio call interface and an open-source, local-only (no-API) dictation tool. (21:30-23:39)
- Q&A — chunky multi-stack features: voice/parallel flows work well for discrete bite-size bug/UI tasks but grind on features touching backend, database, and frontend at once; his answer is git worktrees so agents run in true parallel without stepping on each other, agent teams with clearly defined prompts, and stronger verification gates / CI testing against a spec. (23:39-25:00)
