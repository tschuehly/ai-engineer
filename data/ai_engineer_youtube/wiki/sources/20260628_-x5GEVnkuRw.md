## Summary

Cedric Clyburn (Red Hat) gives a live-demo talk on turning unstructured enterprise documents (PDFs, presentations, contracts, scanned docs, tables, images) into LLM-ready Markdown/JSON for RAG and fine-tuning, using **Docling** — an open-source local CLI/library under the Linux Foundation. His central framing is that document processing quality is the determining factor in whether a downstream AI answer is correct, and that the choice of extractor is a cost/determinism/scale tradeoff between three tiers: a naive PDF parser (fast/cheap on CPU but merges and truncates tables/columns), a frontier VLM (high quality but ~$30/M output tokens, non-deterministic and hallucination-prone at scale, and brittle to model deprecations), and a local structure-aware tool like Docling (fast, cheap, deterministic, air-gappable, ~50× cheaper than naive VLM/OCR at scale per a Hugging Face case). The talk also demos a "chunkless"/agentic RAG pattern where the document's Markdown outline *is* the retrieval index (no chunker, embedding model, or vector database), and covers Docling's operational surface: table→DataFrame export, image/layout extraction with bounding boxes, a layout model usable for PII removal, VLM enrichment of images (local Granite via Ollama's OpenAI endpoint), `docling serve` REST microservice for scaling to thousands of docs, and a Docling MCP server exposing conversion/generation/manipulation tools to coding agents.

## Notes

- Unstructured data is "the new context layer for AI" (cites a Jensen Huang / Nvidia keynote); a large majority of the world's data is unstructured and spread across dozens of systems. 01:02
- Failure motivation: ~20 scientific papers now cite a nonsensical term that doesn't exist because an old scanned article was OCR'd and two words from two different PDF columns got merged; researchers writing with LLMs then propagated and cited it — extraction errors compound downstream. 03:07
- Naive PDF parser output is fast/cheap on CPU but truncates and linearizes tables so a human (and a model) can't decipher them; page headers leak in and image content is dropped entirely. 05:26
- Frontier-model extraction is "not bad" quality but expensive (~$30/M output tokens), scales badly across thousands of PDFs, is non-deterministic/hallucination-prone, and is brittle to model version deprecations (a 5.1→5.2 change breaks consistent structured output). 05:26
- Docling is the "middle ground": a fast, cheap, local CLI/library (`pip install docling`) that converts many input types to Markdown, JSON, and a Pydantic `DoclingDocument`; runs offline/air-gapped without a GPU. 05:44
- Cost datapoint: Leandro (Hugging Face) built the FinePDFs training corpus by extracting structure with OCR + Docling on CPU at ~50× cost savings vs naively using VLMs/OCR. 08:15
- Beyond conversion: VLM image annotation adds retrievable context to diagrams/photos (useful when the SME who made them has left), and structured output pulls only chosen fields (e.g. an invoice's bill number, total price, sender) as Pydantic. 09:10
- Table extraction exports each detected table to a DataFrame (8 tables pulled from the Docling research paper); image extraction maps picture → caption → embedded text elements; a layout visualizer draws bounding boxes over section headers, text, subtitles, and pictures. 11:04, 12:42
- The layout model can strip personally identifiable information from a source document before extraction; VLM enrichment used a local Granite model served through Ollama's OpenAI-compatible completions endpoint to describe images. 13:26
- Chunkless/agentic RAG (DocLing document): the Markdown outline with per-section summaries becomes the entire retrieval index; an agent loops (~5 iterations) picking the relevant section and pulling its full text — no chunker, embedding model, or vector database. Scaled to the IBM 2025 annual report (418 sections). 14:09, 16:13
- Scaling: `pip install docling-serve` runs a REST microservice (`docling serve`, container/Kubernetes) accepting per-request options (OCR, backend, image annotation) to handle thousands of documents. 16:50
- Docling MCP server (run via `uvx`) exposes conversion / generation / manipulation tools so agents (Claude Code, Cursor, Codex, Continue) can process/parse/generate documents without knowing Docling's arguments; demoed against a local MLX-served Qwen 3 model wired into VS Code. 17:32
- Under the hood: OCR + layout analysis pipelines produce the Pydantic Docling document, which then exports to formats, builds datasets, and chunks via the Hybrid Chunker; integrates with many RAG frameworks and agentic harnesses. 19:52
