## Summary

Kitze frames "vibe engineering" as a supervised agentic coding practice rather than blind prompt-and-accept code generation: experienced engineers provide context, primitives, rules, voice-dumped observations, fast feedback, and judgment about which code is good enough for the job.

## Notes

- LLMs can make abstraction faster in both directions: they can help reach the right abstraction quickly, but can also produce the wrong abstraction quickly. (05:04-05:16)
- The talk says LLMs do not care about repetitive code, while humans often over-abstract repeated code too early. (05:16-05:27)
- Kitze defines vibe engineering as using agents to code continuously while watching, steering, and staying suspicious of generated output. (08:31-09:03)
- Useful agentic coding depends on a solid starting point, such as good primitives, components, functions, patterns, and abstractions, plus prompts that point at them. (09:56-10:07)
- A voice-feedback loop can begin in the browser, describe what the UI does, call out bugs, then continue into code-level observations. (10:14-10:44)
- Rules, docs, commands, and memories help because the model cannot hold or infer the entire application context. (10:59-11:13)
- Vibe engineering prompts should contain technical architecture detail, not only vague requests like moving a whole app to TypeScript without mistakes. (11:17-11:53)
- AI coding is most leveraged with skeptical senior engineers who can judge the output; giving AI tools to juniors without enough code judgment is presented as a bad strategy. (12:03-12:39)
- One-off scripts, simple features, personal tools, and code unlikely to be revisited are safer places for loose vibe coding. (12:41-13:01)
- The talk warns that accepting slop repeatedly eventually blocks even skilled engineers because later agents cannot continue reliably from poor code. (19:33-19:50)
