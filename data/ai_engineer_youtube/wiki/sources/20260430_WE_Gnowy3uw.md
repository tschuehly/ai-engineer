## Summary

David Gomes explains how Cursor replaced a complex Git worktree product feature with server-controlled command prompts that behave like skills, plus subagents for parallel model comparisons. The useful engineering lesson is that prompt or skill layers can retire large amounts of product code for advanced workflows, but only when teams accept weaker hard guarantees, add targeted evals, and preserve native implementations for boundaries that need stronger isolation.

## Notes

- Cursor worktrees isolate agent changes in separate checkouts so agents can run commands, lint, and open PRs from a side worktree rather than the primary checkout. 01:04-02:17
- The original feature required code for worktree creation, management, context feeding, agent scoping, setup scripts, judging, system reminders, and cleanup of accumulated worktrees. 03:10-04:15
- Cursor replaced most of that product code with commands backed by skill-like prompts and subagents, deleting roughly 15,000 lines while keeping most of the workflow for advanced users. 04:15-05:30
- The worktree prompt instructs the model to create worktrees, run configured setup scripts, and stay in the side checkout; the parallel comparison prompt creates one subagent and one worktree per selected model. 05:33-07:12
- Server-controlled command prompts provide skill-like progressive loading while allowing Cursor to update the prompt without requiring a client release. 08:24-09:05
- The prompt-coded implementation is easier to maintain and can support switching into a worktree mid-chat, multi-repo worktree creation, and richer parent-agent comparison across subagent outputs. 09:58-12:13
- The main failure mode is weaker isolation: instead of making it physically impossible to touch files outside the worktree, the system relies on prompting, which can degrade in long sessions or weaker models. 12:33-13:18
- The described eval setup runs Cursor CLI headlessly with one scorer checking for expected edits inside the worktree and another checking that no edits happened in the primary checkout. 15:18-16:10
- Early evals found smaller models such as Haiku more likely to deviate into the primary checkout, while Composer and Grok performed better in the tested cases. 16:20-16:42
- Cursor planned both prompt/eval improvements and model training tasks for this workflow, while also moving stronger worktree support back into a more native agentic UI and exploring non-Git local parallelization primitives. 14:17-18:49
