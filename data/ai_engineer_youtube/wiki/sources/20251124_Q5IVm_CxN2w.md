## Summary

Mahmoud Abdelwahab demonstrates Railway Autofix, a scheduled durable-workflow system that reads Railway project architecture, metrics, and logs, turns detected infrastructure problems into agent-ready Markdown context and plans, then drives a headless OpenCode coding agent to open a pull request for human review.

## Notes

- The motivating failure examples are production signals such as rising memory usage, high 500 rates, high request error rates, and slow responses, 00:13-01:44.
- The proposed workflow moves from Railway issue detection to a GitHub pull request instead of stopping at an alert that still requires a human to gather logs, metrics, and traces, 01:47-03:00.
- The monitor workflow fetches project architecture, service resource metrics, HTTP metrics, threshold breaches, and affected services, 03:11-04:17.
- The talk favors scheduled analysis over alert-only triggering because a time slice can distinguish noisy spikes or high usage from real failures, 04:19-05:06.
- A second context-gathering phase can pull logs, repo-derived upstream provider context, and provider status pages before deciding whether to fix code or wait on an external outage, 05:06-06:06.
- The implementation uses Inngest-style durable workflows so API and LLM steps retry, cache successful results, and resume after failures without repeating prior work, 06:57-08:47.
- OpenCode is used as a terminal coding agent with a headless server API; the demo packages it in a Docker environment with Git, GitHub CLI, and needed shell tools so workflows can create sessions and open pull requests, 09:09-11:39.
- The demo run shows monitor, pull-service-context, and generate-fix workflows passing architecture, metrics, logs, and AI analysis into a coding-agent session that opens a PR with a change summary, root causes, and fixes for review, 12:17-17:47.
