## Summary

Johann Schleier-Smith argues that AI-assisted coding should borrow from high-assurance software practice rather than treating generated code as cheap text alone: detailed specifications, modularity, independent verification, formal methods for critical paths, safety cases, adversarial testing, trusted libraries, and cost-aware process can make agentic coding address its current defect and adoption bottlenecks.

## Notes

- Bugs can mean any gap between program behavior and user expectation, whether caused by product ambiguity, implementation defects, or missed real-world conditions. 05:04-05:30
- Airbus A320 reliability practices included N-version programming across processors, operating systems, and teams; specification-based design; independent verification teams; defensive programming; and static analysis. 07:55-09:16
- High-assurance process includes planning and requirements, external certification, integration testing against physical systems, and feedback between adjacent process steps. 10:17-11:22
- Structured programming and modularity reduce verification complexity by supporting local, compositional reasoning; this matters for LLM-generated code because model context and attention remain scarce. 14:11-19:06
- Trusted libraries and components remain important even when AI can generate custom code cheaply, because generated library code still needs testing and verification. 19:06-19:36
- Dafny-style verification puts proofs beside code, verifies assertions before execution, can emit ordinary language libraries, and catches introduced bugs when the specification covers them. 20:02-22:33
- Verification remains limited by the specification: omitted requirements remain possible bug channels. 22:24-22:33
- Practical agentic-coding assurance moves include detailed specs, typed languages, modular code, explicit LLM risk analysis, safety cases, separate testing prompts, multiple model providers, formal proofs around critical code, and outsourcing behavior to trusted libraries. 25:59-28:04
- LLM-driven software creates new assurance needs because nondeterminism and huge state spaces make ordinary formal techniques insufficient for the model behavior itself, even though LLMs can also add resilience by handling unanticipated inputs. 28:07-29:59
- The talk frames agentic coding adoption as a quality threshold: developers avoid agents when fixing generated defects costs more than writing code directly, but adoption can accelerate when agents routinely produce fewer defects than humans. 34:12-35:02
