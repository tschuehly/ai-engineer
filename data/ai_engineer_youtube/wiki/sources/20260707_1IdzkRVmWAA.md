## Summary

Hanna Lichtenberg (leads agentic search at Mixedbread) and Aamir Shakir (co-founder, "Amir" in the ASR) argue that model reasoning has improved exponentially (GPT-3.5 → GPT-5) while retrieval has crept forward slowly for ~20 years, opening a **knowledge gap** — and because retrieval tools are the main access pattern for reasoning to reach real knowledge (legal, finance, deep research), that gap is now the bottleneck, not reasoning. They quantify it with the *Oracle gap*: the maximum theoretical score if the right documents are handed to the model with the question is 93% on BrowseComp (Plus) and 64% on FinanceQA Pro ("Office QA Pro" in the ASR), but Codex with its default tools over the noisy corpus drops to single digits (~9 / ~8 points) — proof that "the bottleneck here is not the reasoning, it's the access to the right knowledge." Dropping in Mixedbread's late-interaction search as a single search tool recovers most of it (GPT-5 within ~3 points of Oracle on BrowseComp; nearly closed on FinanceQA Pro). The reason strong semantic search still "fails" for agents is that models were never taught to use it: inspecting the queries they emit reveals keyword-over-keyword gibberish (a real example: "senator woman questions billionaires not a company then okay thank you staff will check hearing"). Three causes — models are trained mostly for coding agents optimized for grep/regex codebase exploration, they mimic human keyword patterns to use human-optimized web tools, and benchmark bias (BEIR / NanoBEIR use "caveman-style" entity queries that structurally favor BM25) — so the agent guesses keywords to maximize lexical overlap instead of using powerful search. Their fix is to co-design agent and retrieval: a purpose-built search-agent harness on the Mixedbread platform with four tools (overview/summary-only semantic search over up to 50 chunks, main semantic search returning full payloads of the top 10, a metadata-facet filter tool, and grep), a short fast agent loop capped at four search rounds with parallel searches per round, an initial semantic-search preview plus metadata-facet hints, intent split into ≤4 aspect queries each routed to the best tool, deduplicated chunks to protect context, and a final submitted ranking of all relevant chunks. Five harness levers make it write good queries: goal framing (articulate needed evidence first), tool separation (semantic only for aspects, grep only for exact matches), a prompt-framing trick ("write one concise sentence describing what you want to find" rather than "write a search query," so it can't fall into the BM25 pattern), few-shot good-query examples with aspect decomposition, and showing the original query's semantic-search results so it learns the corpus language. On top of the harness they train a small LLM (for speed) with supervised fine-tuning from a larger teacher, then on-policy RL against a composite search reward: a retrieval reward (NDCG of the final ranked list plus an LLM judge over rubrics — is the result relevant, are all chunks relevant, is the ranking plausible) and a trajectory reward (an LLM judge rewarding natural-sentence queries and the right amount of exploration). Intermediate results: NDCG@10 of 0.4 on the "OpenCongress"-style benchmark ("Oblique Congress" in the ASR) vs 0.18 for the paper's best GPT multi-hop agent, and their in-production beta "Mixedbread agentic search" is top-1 on Snowflake's DocQA ("match QA") benchmark at 93.4 accuracy when Gemini 2.5 Flash is given it as a search tool, with far less effort than comparable search agents.

Trajectory reward = an LLM judge rewarding query quality/efficiency, with rubrics for whether the query is a natural sentence and whether the amount of exploration is sufficient (not too much / too little). 10:37-11:59
