## Summary

Filip Makraduli argues that small-model inference for AI search and document processing needs infrastructure designed for many task-specific models, not one model per GPU. The talk frames production inference as a combination of model support and cluster operations: support embeddings, rerankers, NER, cross-encoders, and late-interaction models while routing, queueing, hot-swapping, autoscaling, monitoring, and provisioning GPUs efficiently.

## Notes

- Context rot makes agent quality degrade as context grows, so small models can preprocess, filter, classify, and retrieve data before the main agent workflow uses it. (04:42-05:27)
- Small models can be exposed as tools for workflows such as e-commerce taxonomy classification, where they retrieve or process data for an agent rather than serving as the main reasoning model. (06:38-06:59)
- Provisioning one GPU per small embedding, reranker, or NER model leaves idle memory and compute; hot-swapping multiple small models onto the same GPU raises utilization and lowers cost. (07:20-08:21)
- A production small-model inference layer needs routing, autoscaling, queueing, GPU provisioning, and observability with systems such as Prometheus, Grafana, and KEDA. (08:39-09:23, 14:47-15:40)
- Broad model support is not automatic: BERT, Qwen, ModernBERT, ColBERT, cross-encoders, and rerankers differ in attention, positional embeddings, normalization, output shape, and scoring behavior. (11:18-13:35)
- The Superlinked Inference Engine exposes API primitives for `encode`, `score`, and `extract`, with models treated as switchable configuration and deployment support through Terraform, Helm charts, and Docker images. (14:47-16:09)
