## Summary

Pietro Zullo (co-founder of Manufact, YC S25, maintainers of the `mcp-use` SDK with 8M+ downloads) gives a builder's tour of MCP Apps: the interaction primitives that make them a full bidirectional interaction layer rather than "an MCP server with a UI bolted on," and the store/dynamic-discovery machinery that turns them into a distribution channel. On the architecture side he recaps that an MCP App tool returns not a JSON string but a widget rendered by the host in a sandboxed iframe, declared as a `ui://` resource at initialization and populated with tool arguments. His distinct contribution is the set of primitives beyond initial render: pushing live UI state into the model's context without a user message, sending follow-up messages from the widget into the conversation, calling other tools from the widget, streaming partial tool-call arguments into the UI incrementally, and returning dual outputs (rich UI for the human, redacted text for the model) for privacy. The second half argues the real unlock is that the client stores opened (ChatGPT apps, Claude connectors, Cursor directory) with self-serve submission and one-click install, and that Claude already does *dynamic discovery* — searching the MCP registry for the right connector when a task has no matching tool — making store presence a high-intent organic acquisition channel ("AI apps are the new browsers; ChatGPTs are the new websites").

## Notes

- Timeline: MCP launched 2024; ~May 2025 co-founder Ido Solomon started MCP UI (MCP servers returning UI components); ChatGPT released the Apps SDK; end of 2025 Character AI and Claude quietly opened MCP stores (initially design-partner-gated); January 2026 MCP UI converged into MCP Apps, "the official extension of the Model Context Protocol" for returning UI. Two big shifts: servers no longer only return JSON, and the stores opened. (03:00-05:08)
- Architecture recap: the host owns the model and tools; the MCP server's tool returns a widget in a sandboxed iframe instead of JSON. UI resources are declared at initialization time; when the model populates the tool's arguments the tool populates the UI resource's arguments, which the client renders. Bidirectional postMessage-style channel lets the widget send messages back to the host. (06:01-07:32)
- Primitive 1 — set state / update-model-context: the model can't introspect live UI state, so the protocol has a set-state primitive; from the widget you call `setState` (shown in `mcp-use` syntax) to update what the model knows about what's displayed (e.g. which of three articles is selected), without a user message. (08:34-10:00)
- Primitive 2 — UI message / follow-up: the widget can send a message back into the conversation unprompted, e.g. a "learn more" button wired to `sendFollowUpMessage`. Client behavior differs: Claude prefills the chat input and lets the user choose to send; OpenAI sends it to the model directly and streams the answer immediately. (10:01-11:15)
- Primitive 3 — stream partial tool args into the UI: as the model streams input tokens into the tool arguments, you take the partial input live and update the UI incrementally. Coolest demos use this: Excalidraw MCP streams mermaid syntax into a canvas that draws as tokens arrive; Manufact built a Remotion MCP app that renders a React video inside the widget in real time as tokens stream. (11:17-12:24, 16:56-18:05)
- Primitive 4 — widget calls other tools: from the widget you can trigger additional tool calls (e.g. a button that fetches more data from the MCP server), beyond the tool that originally rendered it. (12:24-13:03)
- Primitive 5 — dual output for privacy: an MCP tool returns a list of outputs; you can send a structured output into the widget and a *separate* output (or nothing) to the model. Common pattern: show full private info in a rich UI card, but tell the model only "the user is seeing their private information in the widget above." Lets you build agent UX in privacy-sensitive fields where sharing raw data with the model provider is not allowed. (13:03-15:23)
- Minor display primitives: request display mode (inline vs full-screen with the chat input overlaid on the widget — good for video editing where the model streams into the widget you're looking at; also picture-in-picture); open external links from the widget; listen to the host/OS theme so the app matches the host. (15:23-16:36)
- Client support: Claude Cowork and Claude Desktop; ChatGPT and Codex; Cursor (agent mode and side chat); plus VS Code and others. Because the client is known from the metadata exchanged, a server can return a UI element only for hosts that can render widgets and a different output otherwise; non-supporting clients simply don't show the widget, but you often must return a different model-facing output when the widget isn't shown. `mcp-use` exposes primitives to detect widget support. (18:35-20:30)
- Building with `mcp-use`: design the server normally (constructor + tools); a tool returns a widget, and any widget file placed in the `resources` folder is auto-registered as a `ui://` resource. The widget is a React component (can reuse existing UI components) compiled to HTML/CSS and linked to the tool. `npx create-mcp-app` scaffolds a template. (20:30-21:40)
- Stores as a distribution channel: ChatGPT (chatgpt.com/apps), Claude (connectors directory), and Cursor (directory) all support self-serve submission. Both plain MCP servers and MCP Apps are eligible (a UI is not required). Submission: link your remote MCP server; they scan tools for correct annotations/arguments and check declared authentication works; you provide test cases and prompts; the app is tested partially manually / partially automatically and accepted or rejected; ChatGPT accepts faster than Claude currently. Once accepted, users install in one click from a store URL — "no more sharing that ugly JSON file." Manufact (manifact.com) vets an app pre-submission and generates submission artifacts (screenshots, test cases). (21:41-24:59)
- Dynamic discovery: Claude is currently the only client that does this — when assigned a task with no specific tool, it searches the MCP registry for the right connector to do the task. With 1B+ active users manifesting intent in chat, being the connector the model selects is "a huge wave of high-intent individuals" who find your product dynamically and organically. ChatGPT is expected to add this soon. (24:59-26:07)
- Thesis: Paul Graham's "AI apps are the new browsers" — if AI apps (Claude Code, Codex, Claude Cowork) are the new browsers, then ChatGPTs are the new websites, and like a website they can return a UI via MCP Apps. Zullo checks whether a product has an MCP server as a basic buying decision, and runs a Granola→Linear→Claude Code→PR→close-ticket workflow across connectors because sharing context between codebase and connectors matters. (26:07-28:28)
