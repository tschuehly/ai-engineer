## Summary

Ido Pesok explains application-layer evals as a way to understand the domain of real user prompts, separate stable test data from variable system changes, and catch improvements or regressions when prompts, RAG, preprocessing, or models change.

## Extracted Concepts

- [Map application evals to the product court](../concepts/map-application-evals-to-the-product-court.md) - this source frames eval data as coverage across in-domain user behavior rather than isolated examples.
- [Keep eval data constant and task logic variable](../concepts/keep-eval-data-constant-and-task-logic-variable.md) - this source gives a reusable structure for comparing prompts, RAG, preprocessing, and models against the same cases.
- [Prefer simple debuggable eval scores](../concepts/prefer-simple-debuggable-eval-scores.md) - this source argues for deterministic pass/fail scoring where possible and human review where code cannot capture the signal.

## Notes

- Passing a prompt twice or ten times is not enough reliability evidence for an AI app; production users will find unseen prompt variants and edge cases, 01:55-04:31.
- Traditional unit and end-to-end tests can cover deterministic app code while the most important LLM-dependent behavior remains unreliable, 04:34-04:50.
- The "court" metaphor separates in-domain prompts from out-of-bounds work and encourages coverage across easy, hard, passing, and failing areas users actually care about, 05:08-07:50.
- Useful eval data can come from thumbs up/down feedback, observability logs, random weekly log samples, community reports, and noisy social feedback, 07:54-08:40.
- Eval tasks should reuse the same data while varying system prompts, preprocessing, RAG, models, or other system behavior, 09:15-10:38.
- Scores should be as simple as the domain allows, with deterministic pass/fail checks preferred for debugging and human review accepted when the desired signal cannot be encoded, 10:40-12:08.
- Adding evals to CI helps PR review show whether a prompt or system change converts failures to passes or introduces regressions elsewhere in the app, 12:36-13:07.
