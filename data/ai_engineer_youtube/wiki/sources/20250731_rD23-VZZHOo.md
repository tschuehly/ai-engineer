## Summary

Gabber's Orpheus deployment shows that realtime TTS serving needs audio-token throughput, voice-clone adaptation, latency-path cleanup, and LoRA-aware routing to fit consumer voice economics. The talk frames Orpheus as an open-source Llama-derived voice model that emits SNAC audio tokens, then describes how Gabber reduced perceived latency by removing generated leading silence, used vLLM batch inference with dynamic FP8 quantization, and routed sessions through a consistent hash ring so LoRA voice clones stay near GPU memory.

## Notes

- Gabber's target market is realtime consumer AI personas, where per-hour voice cost has to approach consumer-app economics rather than call-center-only budgets. (02:06-04:02)
- Orpheus is described as starting from a Llama 3B model, pre-trained on about 100,000 hours of voice plus text data, and trained to output 24 kHz SNAC audio tokens. (04:45-05:20)
- Orpheus produces about 85 SNAC tokens per second of audio, so serving needs roughly 90-100 generated tokens per second to avoid audible gaps. (05:20-05:39)
- One-shot voice cloning was not good enough for Gabber's consumer use case, so they used low-rank fine-tunes; the example used rank 16 and alpha 32 across projections, with better data volume preferred over a rushed 10-minute sample. (05:43-07:38)
- Gabber found that some Orpheus voices generated about 600 ms of leading silence; filtering that audio after generation did not remove the compute cost, while fine-tuning reduced a clone's leading latency to roughly 100 ms P50. (07:43-09:43)
- Gabber starts LLM work during the endpointing snooze period and begins TTS after about two generated sentences so the voice model has enough text context to capture emotion. (09:43-10:52)
- vLLM gave Gabber batch inference with multiple LoRAs on one GPU; dynamic FP8 quantization raised an L40S deployment to about 105 tokens/s for base voices and 95 tokens/s for LoRA voices at batch size 10. (10:55-12:28)
- LoRAs were described as roughly 100-200 MB depending on hyperparameters, making server affinity useful when a voice clone is already resident in GPU memory. (12:31-12:48)
- Gabber used a consistent hash ring with virtual nodes so sessions stick to the same GPU, server removals move only part of the traffic, and popular LoRAs can be replicated to more servers. (13:13-14:13)
