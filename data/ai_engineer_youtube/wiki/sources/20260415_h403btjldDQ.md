## Summary

Paperclip frames agent orchestration as a human control plane for AI labor: operators organize heterogeneous agents into roles, projects, tasks, routines, skills, reviewer/approver workflows, budgets, and concurrency limits so many agents can do real work while humans preserve taste, quality, and accountability.

## Notes

- Paperclip positions itself as a human control plane for AI labor rather than a fully automatic business creator; the human remains accountable and involved from higher-level design through execution. 00:49-02:04
- Agents are organized in an org chart and can be backed by different agent systems such as Codex, Claude Code, Gemini, Pi, Hermes, OpenClaw, Cursor, or OpenCode, while Paperclip stores organizational memory and coordination state. 02:20-03:03, 15:14-15:26
- The product uses a skills manager and agentic surfaces so a CEO agent can hire a specialized video writer and install a Remotion best-practices skill for a specific task. 04:32-05:16
- Planning is treated as a first-class object: the user asks for a video plan, reviews it, gives style and pacing feedback, then lets the agent implement the plan with access to dashboard stats, brand guides, and skills. 05:20-06:45
- Feedback on repeated work can become improved skill and brand guidance, such as Paperclip-specific video pacing and style preferences layered on top of a generic Remotion skill. 07:07-07:51
- Reviewer and approver workflows address the failure mode where prompt-only instructions like "test this in the browser" are skipped by coding agents. 08:41-11:03
- Routines convert repeated prompts into scheduled or manual workflows with template variables and skill references for PR summaries, release changelogs, branch-to-PR work, and Greptile-assisted code review. 11:05-12:57
- The talk says Paperclip is not only for coding; the intended surface covers marketing, sales leads, finance operations, and other organization-wide agent work. 13:01-13:35
- Operators should start with only the agents they need, craft each role's behavior, verify quality, then add more agents when the work justifies the fan-out. 16:27-17:35
- Per-agent and per-project budgets, model routing, and concurrency controls are necessary because not every role deserves frontier-model cost or unlimited parallel execution. 17:35-20:08
- Repeated agent failures should feed instruction updates and meta-agents such as a skill consultant that diagnoses why other agents are not using skills as expected. 20:10-21:18
