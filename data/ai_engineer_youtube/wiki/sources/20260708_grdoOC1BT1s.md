## Summary

Danielle An (principal engineer) and David Hoe lead AI-driven game-creation work at Meta and share a year of field learnings. Anyone can now vibe-code a platformer or Tetris in a couple of prompts, so the novelty wears off and prompted games all look alike; what separates a good game is the same old things (aesthetics, cohesion, playtesting) plus taste — the feel that *this* is a game some subset of humans would enjoy and why. AI removes the skill-gate that used to block coders-who-can't-art and artists-who-can't-code (via tools like "Meta Banana"/Mesh), and it collapses the linear waterfall pipeline (design → art → modeling → animation → coding) into parallel teams iterating in hours/days rather than months, which buys more playtests and cheap revisiting of upstream decisions. Two newer primitives run through the talk: anchoring generated assets on a single key-art image for cohesion across a session, and *runtime LLMs* that drive NPCs and direct the game live — emergent unscripted NPC behavior (steal/block/kick) makes every playthrough unique, and a "game master" can personalize difficulty (e.g. carry a coordination-challenged player). These are newly viable only because inference is now fast and cheap enough. Open challenges: nondeterminism across the whole agentic stack (front-end prompt → runtime LLM → ranking/serving) breaks write-code/write-test/debug stability, model/prompt upgrades can throw off the system, and runtime-generated content raises token-economy profitability and content-safety problems at platform scale.

## Notes

- Everyone can vibe-code a platformer/Tetris/game on Gemini + Three.js in a couple of prompts, but the novelty wears off and identical prompts ("a platformer that looks like Mario") produce similar-looking games if they work at all — the interesting question is "what's next?" 03:11-04:01.
- AI unblocks the skill-gate: a coder who can't 3D-model/draw uses "Meta Banana" or Mesh; artists who can't code no longer wait for engineers — barriers removed, but removed barriers don't guarantee a good game. 04:14-05:14.
- What separates good from best is taste: "not that you delivered a game, but that you have the feel that this is a game humans would like," which subset would like it and why they'd have fun. 08:01-08:29.
- Key-art anchor workflow (art director Dale): iterate to a concept you like, then use a single key-art image (a "lovely bear") for inspiration — it anchors the art style you filter down to assets *and* anchors what the gameplay could be, holding a lot of information and giving the LLM cohesion throughout sessions. 06:10-07:19.
- Runtime LLM as a "living entity" that modifies/changes/directs the game while you play. 08:30-08:51.
- Multiplayer game where each NPC is *entirely* LLM-driven: give it a personality (thief, honorable, fast), and NPCs independently pursue the goal (collect cubes) while stealing/blocking/kicking rivals — "entirely not scripted... runtime LLM-driven decision-making," adding dynamic-ness so every game is unique and non-repeatable; a new genre only possible in the last ~18 months because inference is fast enough and models cheap enough, built over a couple of days. 08:54-10:47.
- AI collapsed the linear waterfall (design → art → modeling → animation → coding, where revisiting an upstream decision is very costly) into parallel teams iterating in hours/days, not months → more playtests and cheaper iteration on the game idea. 11:08-12:00.
- A game master personalizes difficulty: for a "coordination-challenged" player who always tanks the co-op team, the LLM can adjust so they keep playing with friends and still have fun — previously not possible. 12:02-12:37.
- Caveat: the technology itself does not make the product better; teams are still at early phases of exploring how to use runtime LLMs — the Star Trek "imagine a forest, now I'm hunting bears" vision is coming but not today's reality. 12:39-13:20.
- Nondeterminism runs through the whole agentic stack (front-end user prompting → runtime LLM decisions → platform ranking/serving/delivery); engineers used to write-code/write-test/debug against a known code base for stability/scalability, but model upgrades and prompt changes can entirely throw off the system and how to debug that is still a challenge. 14:14-15:07.
- Personalization moment: with AI you can steer any game toward anything (a "Labubu" universe where you can be/collect any Labubu). 15:54-16:12.
- Platform-scale open challenges: token economy must be profitable across creators/players/platform, and content safety is a big one — runtime LLMs generating images/content must stay safe for the audience. 16:15-17:32.
