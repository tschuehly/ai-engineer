## Summary

Eric Hou argues that productive coding-agent use looks less like assigning tickets to an autonomous senior engineer and more like mentoring fast, parallel, perpetually junior collaborators. The talk connects individual delegation patterns, team knowledge infrastructure, shared memories, and parallel prototyping into a workflow where humans provide context, constraints, evaluation, and decision-making while agents execute and explore.

## Notes

- Hou's live demo gives the agent boundaries and personality guidance rather than exact implementation instructions, then lets it run in the background. 04:17-04:48
- In the incident example, parallel agents inspect logs, run a `git bisect`, help manage Slack communications, complete a design-system component, identify and revert a bad commit, and start postmortem/remediation work. 05:55-07:12
- The gRPC remediation story claims agents handled a 12-service, 20,000-line library upgrade with tests and a writeup, while the human still performed final polish and deployment judgment. 07:40-08:19
- The talk distinguishes AI from human juniors: AI can process supplied information very quickly and run many tasks, but does not retain organizational learning between conversations without external memory or knowledge infrastructure. 09:27-10:18
- The recommended adoption path is knowledge gathering, tool familiarity, and then leaning into shared memories, task lists, and more complex delegated work as trust grows. 12:28-14:48
- Parallel prototyping is framed as a way to test divergent designs, prototypes, and architectures with data before productionizing one path. 16:24-18:44
