## Summary

Chris Kelly argues that production AI coding should be judged as software engineering, not as raw code generation. The durable workflow is to keep humans responsible for safe change, prepare codebases with documented standards, reproducible environments, fast local tests, clear boundaries, and scoped tasks, and strengthen code review because agents will generate more code than teams can safely accept by vibe alone.

## Notes

- AI-generated code is still production code: it must run in large systems where emergent behavior, outages, and operational responsibility remain, so engineers still need to understand and fix failures. (01:00-02:32)
- Vibe coding is described as letting AI write and think through the code without examining it, which is insufficient for systems with availability, user, data, and security obligations. (03:14-04:08)
- Code is an artifact of software engineering, not the whole job; engineers make decisions about behavior, architecture, dependencies, and tradeoffs before code exists. (04:11-04:45)
- Every generated line carries maintenance and debugging responsibility, so maximizing AI code volume can worsen the system unless the code is actually needed and supportable. (04:47-05:20)
- Pattern matching breaks down in idiosyncratic production systems where local knowledge, historical decisions, and incident diagnosis matter. (05:35-06:35)
- The practical work of software engineering is changing software safely through knowledge, version control, tests, type systems, deployment strategies, and context. (06:38-07:35)
- Agent-ready codebases need documented standards, reproducible development environments, fast local tests, clear task boundaries, and well-defined work. (09:14-10:28)
- AI should receive the same tools as engineers because it is doing the same job: writing code inside an engineering system that expects tests, linters, and iteration. (10:30-11:18)
- Code review becomes more important as agents write more code, but file-sorted diff tools are a weak interface for understanding change intent and system impact. (11:20-12:05)
- LLM statements about their own process should be treated skeptically because the model may output human-like explanations that do not describe actual tool behavior. (12:24-13:17)
- A productive human-agent loop can create a Markdown plan, review and edit it, use it as context for implementation, then refine the result with code completions or further agent work. (14:06-15:11)
