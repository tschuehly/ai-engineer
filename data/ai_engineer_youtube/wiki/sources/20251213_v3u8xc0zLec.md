## Summary

Kath Korevec frames proactive coding agents as a response to the mental load of babysitting asynchronous agent work. The talk argues that useful proactivity needs continuous observation, personalization, timely intervention, workflow embedding, staged autonomy, memory, critic review, verification artifacts, and live system signals while keeping humans in the loop for alignment and redirection.

## Notes

- The talk compares current asynchronous agents to delegated chores that still require the human to track completion, follow up, and carry the mental load; the goal is to reduce that monitoring burden rather than make the human supervise many terminals (00:39-02:40).
- Proactive agents are described as small parallel collaborators that notice friction and act on boring tasks before the user asks, such as fixing avoided auth bugs, updating configs, flagging errors, and preparing migrations from natural workflow triggers (03:26-04:29).
- The four required ingredients are observation of code changes and workflow, personalization to the user's preferences and ignored areas, timely intervention, and insertion into existing terminals, repositories, and IDEs rather than a separate forgotten app (04:29-05:20).
- Jules' first level of proactivity detects and fixes local maintenance issues such as missing tests, unused dependencies, and unsafe patterns while doing requested work; the second level learns frameworks, deployment style, and user role to anticipate next needs (06:39-07:49).
- The third level connects coding, design, and data agents such as Jules, Stitch, and Insights so software breakage, UX interaction, telemetry, analytics, and conversion signals can produce cross-boundary improvement proposals based on live data (07:49-08:55).
- The speaker stresses that humans remain in the loop by observing agents, refining intervention points, and redirecting misdirected work; level three is framed as project alignment, not autonomy for its own sake (08:55-09:20).
- Jules features mentioned include editable self-written memory, an adversarial critic agent for code review, Playwright screenshot verification added to the trajectory, a repository to-do bot, best-practice suggestions, an environment agent, and just-in-time context cheat sheets for stuck tasks (09:22-10:58).
