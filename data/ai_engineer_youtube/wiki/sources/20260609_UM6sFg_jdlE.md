## Summary

Kuba Rogut (deployed engineer at Turbopuffer, a full-text + vector search database built on object storage) argues that "RAG is dead" only holds against a strawman definition. The discourse equates RAG with a single vector-search call and equates "agentic search" with filesystem grep, but the Google search volume for "RAG" hit a new inflection point in mid-2025 and went "through the roof" while the Twitter narrative moved the opposite way. His reframe: retrieval-augmented generation's retrieval step is not vector search — it is vector search, full-text/BM25, grep, glob, regex, and filters used iteratively by an agent, which is exactly what agentic search is. The talk's clarifying frame is that embeddings/semantic search are *cached compute*, so whether to index is a query-volume decision: he contrasts Claude Code's per-session grep→read→assess→repeat discovery (no index, repeat cost every run, ~6,000 tokens for one sub-step) with Cursor's one-time upfront parse/chunk/embed plus a lightweight runtime semantic-search tool. Cursor's measured semantic-search gains and its Merkle-tree codebase-index sharing across a team are the supporting case study, and Jeff Dean's "you don't need a trillion at once, you need the right million" frames staged retrieval as more important, not less, as context windows grow.

## Notes

- Turbopuffer is a full-text search and vector search database built from first principles on top of object storage. (00:28)
- "RAG is dead, agentic file search is all we need" tweets spiked on X in late 2025 / early 2026; meanwhile Google search volume for "RAG" caps in 2024, settles for ~a year, then hits a new inflection point mid-2025 and goes "through the roof." (00:54, 01:12)
- Strawman definitions: people think RAG = embed a corpus, embed the query, get top-k back, pass through the LLM; and "agentic search" = filesystem grep (Claude Code / Codex). (01:44, 02:20)
- Reframe: break RAG into retrieval-augmented generation. Retrieval is not just vector search — it is vector search, full-text search (BM25), grepping, globbing, regex, and basic filters; augmented generation is just passing results into the LLM. Agentic search is "giving the agent a set of tools to progressively and iteratively find and reason over context." (02:00, 02:46)
- Cursor case study (a Turbopuffer customer and one of its first): on opening a new codebase/branch, Cursor parses, chunks, and embeds the code for semantic search. (03:15)
- Merkle-tree index sharing: on a 100-engineer team people open the same 1–2 codebases ~99% of the time; re-chunk/re-embed/re-upload each time is expensive, so Cursor uses Merkle (crypto hash) trees to compute similarity between codebases the team opens, copies the existing data, and re-chunks/re-embeds only the changed files, using Turbopuffer to keep it secure. (03:53, 04:11)
- Measured semantic-search gains (Cursor internal context benchmark, not public): ~12.5–13.5% average answer-accuracy increase across models; almost 24% on the composer model (pre-composer-2). Online A/B test: ~2.6% increase in code retention in large codebases and ~2.2% decrease in dissatisfied requests. (04:43, 05:34)
- Caveat on those numbers: semantic search does not fire on every query, so aggregate A/B deltas look small even though the per-applicable-query effect is larger. (05:44)
- Claude Code does not use vector search; per Boris Cherney (founding father of Claude Code) early iterations used RAG with a local vector DB but "it just didn't really work out for them." (06:08)
- Embeddings/semantic search are *cached compute*. Claude Code trace = per-session discovery (grep → read → assess → repeat until a "happy state"); the same question is rediscovered by 10 agents × 10 days × 10 developers, repeating the same steps, and one sub-step can cost ~6,000 tokens. Cursor trace = one-time upfront index cost, then a lightweight runtime tool that answers "how is metadata filtered?" cheaply. Claude Code's grep-per-session is "not wrong, it is a deliberate tradeoff." (06:30, 07:04, 07:47)
- Turbopuffer team members who were heavy Claude Code users switched to Cursor for speed once composer-2 + semantic understanding got "really really good." (08:19)
- From RAG to agentic retrieval: simple RAG (one vector call → context) worked in 2023/early-2024; sophisticated customers now do many calls, reason across several steps, search semantically or full-text as needed, and fetch only what each step needs. Retrieval is "super iterative" — agents search to understand and understand to search. (08:38)
- Jeff Dean (Google) on big context windows: even at a trillion-token window you need staged retrieval — "a lightweight mechanism to narrow these trillion tokens into millions at a time… you don't need a trillion at once, you need the right million." Turbopuffer customers embed trillions of tokens; the job is getting to the right 100K/10K/million for the context window. (09:42)
