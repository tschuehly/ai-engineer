## Summary

Malte Ubl frames AI engineering as the new application layer: agents make previously uneconomic software viable, create practical low-risk automation opportunities inside existing workflows, and change product and infrastructure design because agents are both builders and users of software.

## Notes

- Ubl presents AI engineering as a successor to web development because software engineering is being disrupted in both how software is built and what is built: AI and agents. (02:32-03:09)
- Agents make automation economically viable where traditional software required too much hardcoded business logic and implementation cost. (04:02-05:20)
- Lower software creation cost is framed as an elasticity experiment: cheaper software production should increase the amount of software built and therefore the demand for software engineers until an eventual S-curve is reached. (06:06-06:44)
- Low-risk enterprise agent opportunities include "agent as a service" roles, compressed research between a business event and a human decision, surfacing existing information from company systems, and eliminating repetitive support toil. (07:47-12:33)
- Vercel's examples include routing contact-sales submissions by researching the company and distinguishing support requests, and using an agent to pre-research abuse reports while a professional still makes the final decision. (09:27-10:25)
- Products must account for agents as users: Ubl says more than 60% of Vercel page views in the prior seven days were AI agents, and platform usage is shifting from dashboard clicking to APIs and CLIs. (13:00-13:38)
- Infrastructure needs to handle agent-written software that "has to just run," including sandboxes and separation between the agent harness and where generated code executes. (13:48-15:36)
- The application layer can remain valuable even as model rankings change; Ubl argues model commoditization would leave business value with AI engineers building agents above the model layer. (16:03-18:29)
