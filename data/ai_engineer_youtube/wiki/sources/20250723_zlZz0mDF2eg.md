## Summary

Adam Behrens frames agentic commerce as a shift from static e-commerce sites toward buyer agents, merchant agents, and intent infrastructure that can negotiate, present, and execute transactions. The useful engineering takeaways are that commerce agents need programmatic product access, delegated transaction authority, explicit buyer and seller intent, dynamic product and brand interfaces, and market-design safeguards for conflicting or strategically reported preferences.

## Notes

- Behrens defines a store as a location and protocol for transactions among merchants, buyers, and a facilitating system; AI changes this by digitizing participants and interactions. (01:58-02:47)
- He contrasts agents operating websites with agents using programmatic access such as MCP servers or APIs that can retrieve product data, render generated UI elements, and execute purchases through API endpoints. (03:17-04:31)
- Agentic checkout raises an authority problem: if software clicks the buy button, the system must decide whether a software provider buys with a virtual card, delegates authentication to the user's card, or uses a future payment rail. (05:19-06:08, 17:33-18:01)
- Buyer intent can move from inferred keyword, click, and site metrics to explicit conversational or agent-provided intent, but fuzzy requests still need to resolve to SKU-level inventory. (06:23-07:18)
- Merchant-side intent is expected to become more dynamic, including realtime availability, contextual pricing, discounts, and bundles across multiple merchants. (07:49-08:20)
- Product feed integrations and scraping both create scaling problems: feeds require per-merchant relationships, while scraping repeats work and adds bot traffic. The proposed alternative is a unified product-data API across merchants. (08:39-09:28)
- Buyer and seller preferences create market-design challenges because they are complex, change over time, conflict, and may be reported strategically. (09:33-11:04)
- The Samsung example describes an implementation path: expose an API and MCP server, abstract internal product verticals into cohesive endpoints, connect product data to company data, wrap products in brand and design-system context, and test generative commerce on an AI subdomain. (12:49-14:36)
- Behrens argues that brands will want a transportable surface so shopping data and components can move into chat products without fully rebuilding the commerce stack. (16:43-17:12)
