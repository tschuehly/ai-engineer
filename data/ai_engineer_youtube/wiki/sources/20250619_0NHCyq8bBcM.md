## Summary

John Welsh describes Anthropic's remote MCP implementation lessons: standardize model context integrations on MCP's message protocol, treat internal transport as a pluggable stream boundary, and use an MCP gateway as shared infrastructure for routing, credentials, OAuth flows, external connectivity, rate limiting, observability, and policy inspection.

## Notes

- Fast-moving tool-call teams tend to create custom endpoints for tool calls, context, auth, and integration-specific glue; Anthropic saw these converge toward MCP-like tools, resources, and elicitation patterns. 01:24-02:37
- MCP has two separable layers in this talk: the JSON-RPC message specification for model context providers and clients, and the global transport standard around streamable HTTP, OAuth 2.1, and session management. 02:43-03:35
- Anthropic standardized on MCP internally for context plumbing so engineers learn one approach and integrations can reuse future protocol features instead of reimplementing them product by product. 04:19-06:49
- The gateway is presented as shared infrastructure that makes the right path easy: URL-based routing to internal or external servers, automatic credential management, centralized rate limiting and observability, and a normal MCP SDK client session returned to callers. 07:50-09:43
- Internal transport can be websocket, gRPC, Unix socket, or another stream carrier as long as MCP JSON-RPC messages reach the SDK read/write stream boundary. 09:44-11:18
- Centralizing the gateway creates a policy and audit point for model-bound context, including malicious-server blocking, content classification, tool execution processors, tool definition handling, and resource management over standardized MCP messages. 12:39-14:05
