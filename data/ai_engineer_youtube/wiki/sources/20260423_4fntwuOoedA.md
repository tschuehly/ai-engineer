## Summary

Kitze argues that personal agents need a purpose-built interface and context model rather than being forced into generic chat, Discord, Telegram, or traditional app forms. The talk contrasts tinkerer-oriented local agents with constrained mass-market cloud agents, then proposes multi-topic, multi-agent workspaces with visible tool calls, scheduled messages, explicit context attachments, and local OS-level tool access as a path toward task-first computing.

## Notes

- The speaker frames todo apps, habit trackers, calendars, and planners as fragments of a desired "life OS"; form-based input creates enough friction that he alternates between intense logging and complete abandonment (00:46-04:14).
- Early Benji assistant work used speech capture and API calls to update calendar and todo state live, but the talk treats this as a precursor to richer tool-calling agents rather than a shipped product (04:42-05:29).
- OpenClaw-style local agents appealed because the user owns files, assistant state, memory, and sessions, motivating movement from cloud services into local Markdown, Nextcloud, NAS storage, and Android automation so agents can operate on the data (06:30-08:53).
- The speaker says the most valuable OpenClaw use cases shrink when compared with what Codex or Claude Code can already do, suggesting packaged personal agents need a distinct interface and autonomy model rather than only generic coding-agent capabilities (09:11-09:35).
- Failure modes included unreliable cron jobs, multi-agent coordination, agents forgetting recent messages, and generic Discord/Telegram surfaces being a poor fit for a full life OS (10:48-11:48).
- A purpose-built workspace can expose nested topics, visible tool calls, stop controls, predictable cron messages, agent capability panels, and explicit context mentions such as knowledge bases, documents, passwords, and skills (14:14-17:30).
- The predicted end state is task-first computing: an agent ingests notifications, emails, todos, and context, then prompts the human for decisions or missing inputs while local tools or generated UI handle ordinary consumer tasks (17:32-19:52).
