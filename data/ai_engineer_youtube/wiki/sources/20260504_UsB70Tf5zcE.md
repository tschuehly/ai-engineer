## Summary

This workshop uses a tiny GPT-2-style model to show the practical shape of from-scratch local LLM training: choose a tokenizer that matches the data and compute budget, implement the model and training loop in PyTorch, run on local CPU/CUDA/MPS or Colab, and diagnose training quality from train/validation loss and generated samples.

## Notes

- The workshop deliberately avoids pretrained weights and high-level Transformers library loading, using PyTorch and basic libraries so participants see the model-building machinery directly (01:22-01:43).
- A local laptop with about 16 GB RAM can train the very small model, while Colab is offered as a GPU fallback; the code can target Apple Silicon MPS, CUDA, or CPU (02:22-02:43, 07:11-07:45).
- The four practical building blocks are tokenizer, model architecture, training loop, and inference; the demo uses a small GPT-2-style causal decoder architecture because the fundamentals remain useful even though the architecture is older (04:21-07:05).
- Tokenizer choice is treated as a major design decision: multilingual or production-scale models need larger tokenizers and more data, while the workshop uses character-level tokenization with only 65 symbols so the tiny model can converge with limited data (04:40-05:10, 09:12-10:17).
- A full tokenizer in this tiny data setting would not converge in workshop time, while BPE-style tokenizers are more appropriate when training a proper LLM over much larger corpora and longer runs (12:12-13:49).
- Training diagnostics include checking that train loss decreases, validation loss also improves, and loss curves do not show strange spikes; non-decreasing train loss suggests learning or setup problems, diverging validation loss suggests overfitting, and spikes point to data or training instability (59:31-60:12).
