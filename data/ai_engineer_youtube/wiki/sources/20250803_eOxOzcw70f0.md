## Summary

Harald Kirschner and Christopher Harrison show GitHub Copilot inside VS Code as a staged coding workflow: fast "YOLO" exploration is useful for prototypes and learning, but durable work needs starter templates, repository instructions, custom modes, configured tasks, browser feedback, MCP tools, and scoped approval settings.

## Notes

- "YOLO vibes" are framed as valuable for learning, proofs of concept, mockups, and fast exploration, but the speakers warn that this mode should not be confused with shipping a maintainable product. (01:28-04:18)
- Structured vibe coding combines starter templates, consistent technology choices, clear LLM instructions, custom tools, internal domain knowledge, and guardrails to make agent output faster and more consistent. (32:12-33:54)
- Copilot's auto-approval and tool settings are workflow controls; workspace-scoped approvals are safer than blanket permissions, and MCP tools can expose more granular allow choices. (11:18-15:20)
- Terminal allow-listing is difficult because shell command chaining makes the effective action less predictable than a single command name suggests. (19:03-19:31)
- Repository instructions in `.github/copilot-instructions.md` are Markdown context included with Copilot requests; useful instructions describe stack, framework, version, and local conventions while avoiding stale bulk rule dumps. (38:14-40:58)
- Instructions should describe how the agent should work, while task prompts describe what should be done. (45:09-45:14)
- Custom modes can encode workflows such as test-driven development, including understanding the problem, writing failing tests first, seeking confirmation, implementing, and running tests repeatedly. (45:24-47:49)
- VS Code's browser preview and element-selection context can attach visual, HTML, and CSS evidence to a chat request, letting the user steer frontend changes from the rendered UI. (22:16-24:07)
- Playwright MCP is presented as a way to give the agent browser testing, screenshots, website execution, and accessibility-audit tools through VS Code's MCP configuration. (56:23-58:38)
