## Summary

This workshop explains how Pipecat composes realtime voice and multimodal agents from streaming processors, transports, model services, tools, context aggregation, interruption controls, and release evals. The durable engineering value is the runtime shape: voice agents should be treated as low-latency media pipelines with explicit turn detection, swappable providers, synchronized audio/text events, and end-to-end service regression tests.

## Notes

- Pipecat is presented as an open source Python framework for voice and multimodal agents, with pipeline processors that stream and transform audio, video, text, and other data. 01:35-04:06
- A cascaded voice stack can flow from transport to STT, LLM, TTS, and transport output, while Gemini Live can collapse transcription, reasoning, and speech output into one service. 04:06-05:20
- Context aggregation collects user and assistant conversation turns into the format a model can handle, especially for text LLMs and function-calling logistics. 11:12-12:14
- Pipecat's function schema abstracts provider-specific tool formats so tools can move across OpenAI, Anthropic, Gemini, Bedrock, and similar LLM services. 13:08-13:40
- Pipeline tasks can set runtime parameters such as allowing interruptions, making interruption handling an explicit execution setting. 49:15-50:08
- Smart-turn style classifiers can label spoken input complete or incomplete and let the runtime adjust VAD timeout dynamically. 01:01:50-01:02:46
- Release evals can connect bots to a room, have them talk to each other, and check whether integrated services such as Gemini Live, Cartesia, and Deepgram still work end to end. 57:54-58:40
