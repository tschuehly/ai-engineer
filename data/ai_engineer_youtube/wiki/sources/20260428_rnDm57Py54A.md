## Summary

Eric Zakariasson frames an agentic software factory as a progression from pair-programming toward managed, observable, asynchronous agent work. The useful engineering guidance is operational: make repositories easy for agents to navigate, provide runnable environments and external context, add guardrails and tests, let rules emerge from observed failures, run cloud agents in isolated VMs for parallel execution, and automate repeated review or triage loops so factory learnings feed back into prompts, rules, and workflows.

## Notes

- The talk places many users between pair-programming and agent-generated-code workflows, while the "software factory" stage has agents shipping, testing, and building code from human intent and goals (01:26-03:32).
- Codebase structure is a factory primitive: modular, colocated code lets an agent inspect a folder and find related files without searching the entire repository (05:02-05:50).
- Usage patterns such as authentication helpers, startup scripts, and test conventions should be present as reproducible references the agent can copy (05:50-06:17).
- Guardrails include rules, checks, and hooks, especially for sensitive areas such as authentication or encryption where agent mistakes are expensive (06:17-06:55).
- Rules should be added when agents go off the rails, behaving like SOPs that describe what agents can and cannot do rather than a large upfront pile of generic framework rules (06:56-07:47).
- Verifiability is a core scaling requirement: agents should run unit tests, integration tests, and UI tests, including DOM interaction when the user experience is the product surface (07:51-10:42).
- Skills and MCPs are enablers because they give agents external context and capabilities such as feature-flagging workflows before autonomous launch or PR merge (08:13-08:58).
- Cloud agents run on separate VMs so multiple coding tasks can proceed in the background while the human plans synchronously and later reviews asynchronous results (15:26-21:52, 01:01:30-01:02:14).
- The factory should keep observability and human review around generated work; humans still set specs, review outputs, and decide which improvements enter the factory (58:48-01:04:35).
