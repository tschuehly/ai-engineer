## Summary

Ankur Goyal frames eval competence as an engineering capability: teams should be able to incorporate user feedback into eval data, test new model releases quickly, use evals to predict which use cases are newly viable, and optimize the whole AI system rather than only the prompt.

## Extracted Concepts

- [Continuously reconcile eval datasets with user reality](../concepts/continuously-reconcile-eval-datasets-with-user-reality.md) - this source argues that real user feedback should update eval datasets through human judgment.
- [Write custom scorers as product specifications](../concepts/write-custom-scorers-as-product-specifications.md) - this source treats scoring functions as the executable spec for the AI application.
- [Evaluate tool definitions and outputs as context](../concepts/evaluate-tool-definitions-and-outputs-as-context.md) - this source shows why tool schemas and tool outputs are part of the prompt surface, token budget, and eval target.

## Notes

- Eval competence has practical signs: a team can test a new model and ship an update quickly, turn user complaints into eval cases, and use evals offensively to judge whether a use case is ready before launch, 00:37-02:06.
- Synthetic datasets and generic LLM-as-judge scores are not enough for most real product use cases because no prebuilt dataset perfectly matches user reality, 02:10-03:08.
- Advanced teams write and revise their own scoring functions because generic scorers act like someone else's product spec, 03:11-04:00.
- Context engineering includes tool definitions and tool responses; in agent traces, tool-related messages can dominate token budget more than the system prompt, 04:04-05:08, 16:21-17:24.
- Tool outputs should be shaped for the LLM as well as for code consumers; a cited internal example found YAML output more token-efficient and easier for an LLM to analyze than verbose JSON, 05:45-06:32.
- New model releases can turn a previously nonviable feature into a viable one, so products need evals and model-provider abstraction that let teams rerun benchmarks and switch providers quickly, 06:38-09:04.
- Prompt optimization should operate over the whole eval system: data, task or agent loop, tools, and scoring functions, 09:09-10:16.
- Braintrust Loop is described as a feature for using an LLM to improve prompts, datasets, and scores inside an eval workflow, 10:21-12:17.
- User feedback should not be blindly auto-added to datasets; Goyal argues for a human with product taste to select interesting feedback and reconcile the dataset with desired reality, 14:36-16:07.
