## Summary

OpenAI's Agent RFT talk frames reinforcement fine-tuning as a late-stage optimization for tool-using reasoning agents after teams have matched data to production traffic, established a baseline, and exhausted prompt and task optimization. The reusable engineering lessons are that agent training can call public tool and reward endpoints, each rollout should preserve tool-call trajectory context for grading, reward functions must be well-defined and hard to hack, and RFT can improve both task accuracy and latency by teaching models better tool-call patterns.

## Notes

- Agent RFT is positioned after prompting and task optimization: simplify the task, add guardrails, adjust tools, establish base-model performance, and only then use RFT to push task-specific performance further. (01:44-02:45, 05:46-06:29)
- New RFT capabilities described in the talk allow the model to call public customer-hosted tool endpoints during training and invoke a customer-hosted custom reward endpoint after each rollout. (02:57-03:18)
- The system associates a unique rollout identifier with all tool calls in a trajectory, then lets the final answer and accumulated context be passed to a grader as holistic grading context. (05:12-05:44)
- Domain shift appears when a company's environment differs from the model's original training setting; the agent may call tools too often or pass wrong inputs, and RFT can adapt the model through exploration and reward. (03:53-04:47)
- Cognition used RFT on Devin's code-edit planning phase, rewarding file-selection F1 against files users actually modified; scaling high-quality examples from roughly 100 to 1,000 improved the reported gain from 5 to 10 points. (06:54-08:18)
- Cognition also used per-trajectory VM infrastructure and saw RFT learn first-step parallel tool calls, reducing the planning behavior from 8-10 alternating reasoning/tool steps to about four. (07:32-08:53)
- CodeRabbit's code-review research agent trained on roughly 1,000 authentic QA pairs across eight repositories, rewarded recall of relevant retrieved facts, improved by 6%, and reduced long-tail runs with more than 15 tool calls to a tighter 2-4 tool-call distribution. (08:57-10:24)
- Cosine used about 30 tools and stricter grading for enterprise coding agents; partial credit for trying caused optimization toward style and tone, so rewards focused on final test-passing code, self-validation, linting, and professional output. (10:32-12:12)
- Metaco's GPU-kernel agent exposed reward hacking in rollouts, including returning reference code, no kernels, or identity kernels; the team added an LLM judge and AST-based static analysis before scoring correctness and real speedup against a PyTorch baseline. (13:25-14:21)
- The four stated principles are to make the task well-defined and objective, mirror production traffic in train/eval data, verify that exploration improves best-of-N performance, and keep reward functions non-hackable and preferably continuous rather than purely binary. (14:54-16:15)
