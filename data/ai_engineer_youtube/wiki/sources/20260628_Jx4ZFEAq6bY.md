## Summary

Sonam Pankaj (CEO/co-founder, StarlightSearch; co-creator of the `embedanything` Rust RAG pipeline) argues that production agents fail because the outcome signal from evals and observability never crosses back into what the agent does next — it "dies in the dashboard." A ReAct agent reasons, calls tools, and retrieves memory, but has no loop to learn from what worked or didn't, so it keeps failing the same task (she cites Gartner "85% of AI failing traction," McKinsey 2025, and a claim that 73% of pipelines fail at retrieval, not generation). Her fix has two parts. First, a **utility score**: retrieve memories not by keyword or embedding similarity alone but by similarity *weighted by whether each memory historically helped or hurt the run's outcome* — memories behave like a credit score (retrieved + run passed → utility rises; run failed → utility falls), so outcome becomes a first-class retrieval re-ranking signal, and memory is treated as reasoning ("if someone asks for a refund, check the settlement first so they aren't paid twice") rather than static facts/preferences. Second, **Agent RX ("agent runtime experience")** / their product "Reflect": a runtime layer that consumes traces, absorbs eval outcomes, and converts both into retrieval guidance so the agent improves *while executing* — no retraining, fine-tuning, or manual prompt rewrite — and, once ~10 memories/~5 reviews accumulate for a task, bakes the stabilized reasoning into a **skill** the agent always calls (fixing e.g. a stale column still named in a SQL agent's system prompt that no system today updates). This is contrasted with compile-time approaches like DSPy that bake lessons into the prompt up front. Reported benchmark lift on tau-bench (policy adherence): 66% → 76%, and 80% with skills; similar trend on other agentic benchmarks. Limitations: cold start (pure semantic search until enough reviews), utility drift, noisy review labels, and a credit/re-ranking hyperparameter `lambda`.

## Notes

- Agent = an LLM with agency to reason, invoke tools, interact, and retrieve memory; ReAct executes reason→act in a loop until the task is complete. The missing loop is **learning from the outcome**, so the agent "keeps failing at the same task." 00:31-01:24
- Failure attribution: retrieval is static; she cites 73% of pipelines fail because of retrieval and context stuffing, not generation; Gartner "85% of AI failing traction," McKinsey 2025. 01:24-02:00
- Quote attributed to Ram Sriram (ex-CTO, Pinecone): "we've been optimizing for the wrong thing… we made wrong answers appear faster and cheaper, but we forgot to make retrieval learn." 01:51-02:12
- Third problem: agents are **not outcome-informed** — a missing layer between evals and action. Observability captures every tool call, LLM completion, and exception; the eval suite judges pass/fail; but that verdict is not reflected in the agent's context, skills, or actions, so the agent has no access to why yesterday's runs passed or failed — "the eval signal dies in the dashboard." The manual alternative is an engineer reading dashboards and rewriting the prompt, redeploying, upgrading to a more expensive model, restructuring the harness, or fine-tuning. 02:16-03:36
- Why current memory fails: LangChain / Mem0 store user preferences, profile, conversation history, long-lived personalization; the retrieval signal is embedding similarity; "does it learn from outcome? No." That is a chat experience, not a self-improving production learning system. 03:36-04:32
- **Utility score** = similarity weighted by how useful a memory is for the agent to execute the task, carrying the history of past pieces and past outcomes. Retrieve by semantic similarity to the current task **weighted by whether those memories have historically helped or hurt the execution/outcome**; the outcome becomes a first-class signal in retrieval re-ranking. 04:32-05:40
- **Agent RX** = "agent's runtime experience," a runtime layer that lets the LLM agent improve from experience without retraining, fine-tuning, or manual prompt engineering. Different from compile-time approaches "like DSPy" where you bake all lessons into the prompt; here the agent improves *while executing the task*. 04:47-05:14
- Treat **memory as reasoning, not as facts** — not "user prefers dark theme," but "if someone asked for a refund, check the settlement before refunding so the customer isn't paid a refund twice." Act on usefulness; context is updated based on the task; this combats context stuffing. 05:40-06:44
- Once enough memories accumulate for a task (~10), bake the reasoning/understanding into a **skill** so the agent stays updated. Example: a product SQL agent whose system prompt names a column that is no longer useful — no system today updates that; with skills the agent always calls the updated skill (similar behavior noted in "GPT-5.4," ASR-uncertain). 06:44-08:02
- Benchmarks: tau-bench (measures whether agents followed a policy well) improved 66% → 76% without skills, 80% with skills. On agentic benchmarks (reason/plan/tool-use over multi-step workflows vs static Q&A) she cites a baseline ~35.7 → ~58.2 with another memory system → ~61.3% with the refined memory system, with the trend echoed on Big Code Bench and others. (Numbers are ASR-jumbled between two readings; treat the agentic figures as approximate.) 06:44-08:50
- Limitations: **cold start** (pure semantic search until enough reviews accumulate — "cannot do much about it"), **utility drift** (similar memories collide), **review quality** (noisy labels make utility noisy), and a hyperparameter `lambda` tied to credit and re-ranking; their "Reflect" build reduces all but cold start. 08:50-09:45
- Demo (product SQL agent): "find me a gaming mouse" → zero memories retrieved, "couldn't find a gaming mouse." A wireless mouse exists in the DB; the failure is submitted as feedback in the dashboard (input, response, trajectory/tool quality). On re-run the trajectory changes — it now finds and surfaces the wireless mouse — because memories are retrieved by a utility score that keeps re-ranking on how useful each memory was; after ~5 reviews the findings can be baked into a skill without changing the existing prompt. 09:45-15:10
