## Summary

Matt Pocock argues that AI coding does not make software fundamentals obsolete; it raises the cost of ignoring them. Specs-to-code loops can amplify software entropy when teams stop reading code, so agent workflows need shared design concepts, domain language, small feedback loops, TDD, and deep module boundaries that let humans keep strategic control while agents handle implementation detail.

## Notes

- Specs-to-code that repeatedly regenerates from a spec while avoiding code review can produce progressively worse code; Pocock calls it "vibe coding by another name" and ties the failure to software entropy. (01:18-03:43)
- Bad code is expensive in an AI workflow because hard-to-change code prevents teams from benefiting from otherwise capable AI coding tools. (03:47-04:20)
- The "Grill Me" skill asks many clarifying questions, walks the design tree, resolves dependent decisions, and turns the resulting conversation into a PRD or issues. (05:50-06:53)
- Ubiquitous language gives the agent and human a shared glossary derived from the domain model, reused in code, planning, and discussion. (07:34-09:33)
- Agent coding should not outrun feedback: tests, type checks, and small deliberate steps constrain change size before the agent creates too much unverified code. (10:28-11:29)
- TDD is useful for agents because it makes the agent write the test, pass it, and refactor in smaller increments, but the codebase must be structured so tests are easy to write. (11:11-12:35)
- Deep modules hide substantial functionality behind simple interfaces; shallow module sprawl makes both humans and agents carry too much context and increases navigation errors. (12:42-14:17)
- For many non-critical modules, humans can design and test the interface from outside while letting the agent handle internals, but this is not appropriate for critical domains such as finance without deeper review. (15:40-16:31)
