## Summary

Josh Albrecht frames Imbue's Sculptor work as a move from prototype-generating coding agents toward systems that make generated code trustworthy: plan before coding, turn docs/specs/style guides into agent-visible context, check diffs as they are created, use linters/tests/LLM checks together, and run repair attempts in isolated sandboxes.

## Notes

- Sculptor is described as an experimental coding-agent environment focused on closing the gap between prototype code and production code, especially in larger codebases (00:18-01:23).
- Albrecht recommends avoiding generic model, inference, and parsing improvements that frontier models may solve soon, and instead building domain-specific tooling around questions such as "what is wrong with this diff?" (01:53-02:38).
- Agent-generated diffs create an awkward review choice between inspecting every line and merging on trust; a third option is to ask another AI system to check for concrete issues such as race conditions or leaked API keys (02:38-03:21).
- High-quality code is framed as the absence of defects, and Sculptor aims to surface problems synchronously when code is generated or changed rather than only at late pull-request review time (03:26-04:28).
- Prevention methods include learning existing solutions, planning before coding, keeping specs/docs in the coding workflow, and using strict style guidance that can be tailored to agent failure modes (04:32-08:00).
- Linters and static tools such as Ruff, mypy, pylint, and pyright remain useful because AI can both introduce and fix lint churn; Sculptor tracks issues before and after an agent run so dirty codebases do not hide newly added errors (08:03-09:52).
- AI makes test generation cheap, but generated tests should not be kept indiscriminately because obsolete or low-value unit tests can confuse future LLM edits; user-level integration test plans and coverage checks provide stronger confidence (09:55-14:28).
- Tests should run in sandboxes and without secrets to reduce accidental side effects and flaky behavior (14:31-14:47).
- LLM checks can inspect branch intent, style, architecture, spec conflicts, implementation gaps, and test quality; once an issue is well stated, simple repair strategies such as multiple sandboxed attempts by different agents become more effective (14:49-16:22).
