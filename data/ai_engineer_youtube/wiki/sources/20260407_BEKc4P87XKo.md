## Summary

Brendan O'Leary frames coding agents as fast, well-read junior collaborators that can execute but still lack local judgment, business context, and architectural memory. The practical workflow is to manage context deliberately, isolate work into small sessions, separate research, planning, and implementation, and tune agent modes, repository rules, tool permissions, worktrees, and approval settings as the team learns where autonomy is safe.

## Notes

- Coding agents crossed from autocomplete and function suggestion into execution: they can break down tasks, edit files, run tests, and return pull requests, which makes them collaborators rather than just suggestion tools. (02:00-02:20)
- The useful mental model is an energetic, well-read, often confidently wrong junior developer: fast and broad, but missing business context, architectural rationale, and local judgment. (03:12-04:23)
- Human leverage comes from deciding what to hand off, what to keep, and how to direct the work rather than blindly accepting generated changes. (04:03-04:23)
- Context engineering matters because every extra token adds cost, long context can degrade quality around heavily filled windows, enabled MCP servers add tool context, and stale or task-mixed context can poison later outputs. (04:33-07:15)
- Durable context should live outside the model window in scratchpads, memory files, and AGENTS.md-like project instructions, then be pulled in selectively for the current task. (07:16-08:05)
- When a session drifts, the recommended practice is to start a fresh session, ask the agent to summarize the useful state, manually review that summary, and continue with only the corrected context. (10:37-11:15)
- The research-plan-implement loop keeps agents from producing large volumes of code from weak assumptions: research first, review the research artifact, plan files and validation commands, then implement in a fresh low-context session. (11:36-16:20)
- Agent configuration should evolve across role modes, project rules, skills, worktrees, auto-approval settings, file-read boundaries, test permissions, MCP servers, and invocation surfaces such as IDE, CLI, cloud agents, mobile, or Slack. (17:44-23:37)
