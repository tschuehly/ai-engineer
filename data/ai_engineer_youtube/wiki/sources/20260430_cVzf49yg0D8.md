## Summary

This workshop shows how conversational-agent runtimes combine a model, context, tools, and an execution loop, then applies that shape to Gemini's Interactions API for server-side conversation state and to the Gemini Live API for realtime multimodal audio, video, and tool-calling sessions.

## Notes

- The workshop frames an agent as a model that decides whether to call tools or generate text, tools that provide hands and eyes, context that captures task constraints, and a loop that runs until tool calls stop. 14:33-15:04
- The Interactions API is presented as a unified surface for models and agents, with server-side state so clients can pass the previous interaction ID instead of maintaining a full local history object. 09:19-10:38, 15:14-16:04
- Tool execution uses a `requires_action` response state: the client inspects output events, executes recognized function calls, returns function results, and recurses until the interaction returns final text. 16:42-17:09, 33:16-34:23
- The coding-agent demo exposes read-file, write-file, and shell-command tools, then validates the loop by writing and reading a file and executing `date`; the presenters explicitly reject a destructive "delete all files" prompt during the demo. 32:23-34:58, 42:31-42:46
- Interactions can be retrieved with `interactions.get`; keeping interaction IDs on the client enables branching from an earlier point, but state retention is bounded rather than an infinite context window. 42:55-45:17
- The Live API is described as a stateful WebSocket API for realtime text, audio, and video input, with streaming audio buffers, low-frame-rate visual input such as screen share, realtime events, transcriptions, and built-in tool calling such as Google Search grounding. 55:36-57:00
- The Live API section distinguishes native audio models from cascading speech-to-text, LLM, and text-to-speech pipelines, and notes that higher thinking levels trade more reasoning for higher latency. 57:04-57:28, 62:06-62:30
