## Summary

A Together AI research talk on the GPU-memory engineering needed to train (and fine-tune) transformers at multi-million-token context lengths. The motivating failure is concrete: a standard LLaMA 3B at a 3M-token context will not fit on a single 8×H100 node even with only model parameters loaded. The talk walks through an incremental, layered stack of memory optimizations — fully sharded data parallelism, DeepSpeed Ulysses context parallelism, activation checkpointing, CPU offloading of transformer-block inputs, and Arctic-style chunked sequence training — each of which moves the limit further until 3M tokens becomes feasible. To reach 5M, Together's novel contribution "Untied Ulysses" goes deeper into the context-parallelism step: because one attention head-group already saturates GPU compute, heads can be chunked and iterated so a small activation buffer is reused across iterations, cutting activation memory with negligible throughput impact and matching the most memory-optimized transformer-training baselines at 8B and 32B while pushing sequence length ~25% past prior Ulysses implementations. U-Pipe is layered on top to free and reinvest additional memory across pipeline stages.

## Notes

- Together AI is framed as an AI-native cloud for the full model lifecycle: GPU clusters for from-scratch training, fine-tuning and reinforcement learning for model shaping, and serverless + dedicated inference for 200+ models. (00:36-01:45)
- Demand for long-context training is twofold: the agent explosion (put many tokens in context and have the model leverage them) and video generation (track many frames, even multiple frames per second, with temporal consistency over seconds/minutes). (02:00-03:10)
- Even below millions of tokens, understanding where memory goes matters: savings can be reinvested to speed up training overall. (03:22-03:42)
- Two bottlenecks of extending a standard transformer LM's context: quadratic computation (pairwise interactions across all sequence elements) and linear memory growth (less severe but still hard without specific techniques). A Hugging Face training blog post is cited for how sequence-length growth moves memory limits. (03:56-04:46)
- Baseline failure: a LLaMA 3B at 3M train tokens on an 8×H100 node runs out of memory just placing the model parameters. (05:12-05:43)
- FSDP (fully sharded data parallelism) chunks parameters across the 8 GPUs; model memory drops a lot but attention activations still OOM. (05:43-06:08)
- DeepSpeed Ulysses context parallelism (introduced by Microsoft): instead of computing all multi-head attention on every GPU for the whole sequence, compute different heads on different GPUs, communicating activations as needed so one GPU owns one head but still attends over the whole sequence; lets you keep the best Flash Attention implementation (1/2/3/4). Utilization drops ~8×, but it still does not fit one node. (06:10-07:48)
- Activation checkpointing recomputes activations at the backward pass; available in essentially every deep-learning framework; enable it carefully to avoid excess compute. Drops activation usage another ~8×. (07:48-08:26)
- CPU offloading of transformer-block inputs: store some block inputs on CPU when not needed and prefetch them when backpropagating to that layer; low performance impact; first implemented (to the speaker's knowledge) by Unsloth; reaches ~37 GB offloaded. (08:30-09:26)
- Chunked sequence training (Arctic Long Sequence Training): tile element-wise computations — loss and MLPs — across the sequence so you never allocate a buffer 3M wide along one dimension. With this layer, 3M tokens is finally possible. (09:31-10:00)
- Untied Ulysses (the novel contribution) to reach 5M: even one set of heads already saturates GPU compute in one iteration, so multiple heads scheduled on one GPU are split into chunks iterated over time — recompute a head group, compute attention, store the partial result, and let the next stage reuse the previous stage's buffers. A smaller reused buffer replaces one huge per-head-group buffer, saving activation memory with no significant throughput impact at small scales. (10:04-11:40)
- Results: at 8B and 32B scale, Untied Ulysses closely matches the most memory-optimized transformer-training implementations while scaling to 5M tokens (~25% further than prior Ulysses per the description) and is sometimes more performant at shorter contexts. (11:40-12:10)
- Chunk-size tradeoff is straightforward: larger chunks (more heads per iteration) use more memory but run faster; smaller chunks save memory at a small throughput cost. (12:10-12:29)
- U-Pipe layered on top frees additional memory that can be reinvested elsewhere (e.g. among pipeline stages); for 3-5M context lengths it is the technique that saves you relative to everything else. (12:29-13:00)
- Takeaway: bottlenecks appear where you least expect, so profiling tooling like the PyTorch profiler (detailed in their paper) is essential; the work is public. (13:00-13:43)
- Q&A clarification: the heavy step is the query/key/value matrices in the attention part — all queries form pairwise interactions with all keys, so a vanilla implementation would allocate a single tensor 3M long on one axis, which is why no single technique suffices and a range of approaches is needed. (13:56-15:30)
