## Summary

Jesse Hu maps self-driving robotics lessons onto digital agents: production agents are action systems whose reliability depends on embodiment, observation/action-space design, statefulness, closed-loop feedback, simulation, production logs, and offline infrastructure rather than only the predictive model.

- [Close agent loops around live action feedback](../concepts/close-agent-loops-around-live-action-feedback.md) - this source imports open-loop versus closed-loop control from robotics to explain why agents need observable action results and interruption paths.

## Notes

- Robotics and agents both have a "1% model, 99% surrounding system" shape: the model matters, but hardware or digital embodiment, deployment, simulation, monitoring, retraining, human feedback, and development tooling carry most production reliability work. (01:23-03:04)
- Digital agents have embodiment through their tools and execution surfaces: APIs, MCP servers, terminal, browser, VM, operating system access, and persistent file stores become the agent's way to affect the world. (01:48-02:44)
- Open-loop actions fail when the agent cannot observe or interrupt the result, such as a long-running Bash process whose output, completion, or cancellation state is unavailable in real time. (03:08-04:06)
- Agent systems implicitly discretize time through conversation turns and full tool-response waits; that is easier to reason about, but loses realtime responsiveness to pop-ups, long-running processes, and changing external state. (04:06-05:46)
- Observation and action spaces are agent architecture decisions: character-level terminal streams, control-C, window commands, and frame-level mouse/keyboard control offer different capabilities from ordinary MCP or tool-call abstractions. (05:49-07:25)
- Stateful VMs and persistent files make agents more like real-world actors whose prior state, active processes, Slack context, world state, and downstream effects shape both online behavior and simulation/evaluation design. (07:30-08:41)
- Imitation learning or SFT can compound out-of-distribution errors when the agent reaches states absent from human demonstrations, such as unfamiliar browser pop-ups; actions then produce cascaded consequences rather than isolated predictions. (08:43-09:59)
- Agent simulation should replay messy state and counterfactual paths so teams can test what happens after different actions, not only score a single logged trajectory. (10:03-10:24)
- Production logs should feed simulation and hill-climbing loops; breaking failures down by category, city, or failure mode gives more useful improvement signal than one benchmark percentage. (14:32-15:23)
