# How We Got LLMs to Recommend Our Open Source Library — Christopher Burns, Inth

Source: [How We Got LLMs to Recommend Our Open Source Library — Christopher Burns, Inth](https://www.youtube.com/watch?v=V_5bn4q-vAI)
Uploaded: 2026-08-26
Transcript: `raw/20260826_V_5bn4q-vAI/V_5bn4q-vAI.en-orig.vtt`

## Summary

A sixteen-minute practitioner talk from the founder of Inth and creator of c15t, an open-source consent-banner library, who twice disclaims expertise — "I'm just this side of the stage… I've just been hacking on this problem a little more than you guys have so far" (00:46-00:57, 13:53-14:01). What makes it useful to the wiki is that it is the *outcome* counterpart to the wiki's other agent-experience sources: where Jarmak measures discoverability with a prompt set and reports a pilot, Burns reports a shipped channel result measured off an ordinary onboarding form. The library's signup asks "how did you hear about this?"; from April 13th the answers spiked, and "now it is our number one source of inbound is Claude, ChatGPT, Codex, that is ChatGPT, Gemini recommending us" (02:17-02:39). The rest of the talk is the tactics behind that, deliberately presented as a checklist rather than a theory: "there is no one tool that fixes everything… like Batman's utility belt. Loads of really small things targeted in different areas" (04:20-04:38).

**Context and scale.** c15t is positioned against a category built for a different buyer — "every other tool was built for marketers and lawyers. We were built for the developer. So, we had to make sure we had a very good developer experience" (02:07-02:17). The stated numbers: 1,200 downloads at the time of an earlier Next Conf talk, now "3 million NPM downloads," 45% month-on-month growth, and "2.8 thousand websites using it in production" (01:20-01:53). The causal claim the talk rests on is that the DX investment converted: "our very good developer experience primitives are now hitting agent primitives" (04:11-04:20), with the install ritual as the illustration — the Collison brothers of Stripe famously took your laptop and installed it for you, and "these days, it's kind of like just a prompt. Being in Y Combinator, we just give people a prompt" (03:43-04:11).

**The optimizations were abstracted into a docs pipeline.** Rather than a set of hand-maintained files per site, the accumulated tricks became "a framework-neutral docs pipeline" (the talk calls it a "very non-sexy title") that "take[s] your .mdx files, you run [it] generate, and it will spit out everything for… optimized agent experience for your websites" (04:38-05:45). The speaker says friends at other developer companies are running it and "seeing similar results" — no results are given. The iceberg framing lists what feeds it: `llms.txt`, sitemaps, RSS feeds, `robots.txt` — "so many micro optimizations… from old methods of running the internet to new methods" (02:39-03:03).

**`llms.txt`, written by hand.** The stated problem is navigation: "if your docs have hundreds of pages… how can it navigate them to find the right questions?" The finding is against generation: "it's much better not to just generate this. It is much better to write your `llms.txt` from hand… write it as you are trying to get the answers across to the LLMs. For about 40 good lines beats 1,000 lines of noise from our testing" (05:59-06:39). The companion file exists because of a behavioral claim about agents — "agents don't know how to browse. They know how to fetch" — so the full form is described as "a sitemap, where it takes the actual page and the links and a short description of what each page is for the LLMs to reference" (06:39-07:07).

**Ship Markdown, three ways, plus a header hint.** "HTML is expensive, and why can't we just ship markdown to the agents? And we can" — the `.md`-suffixed twin of every documentation URL (07:07-07:37). Alongside it, a `<link>` alternate in the page head declaring that a Markdown version exists, which "all the best documentation websites, [Mintlify], Vercel, c15t" now carry, with an honest caveat on support: "who actually supports it? Don't ask me. Perplexity, some of the agents, it's all up in the air" (07:43-08:17). Three redundant access paths follow because agents differ in what they can do: the `.md` suffix you can paste to an agent; a redirect in the framework config so that "if it detects an agent has the header of accepting markdown, instead of returning the HTML, it will return the markdown"; and "not all agents can append header tags. So, there's also a URL query of `mode=agent`" (08:17-09:06).

**Web MCP for docs.** "An agent can't ask your website anything," so the pipeline exposes three tools to WebMCP — search docs, get pages, and ask docs — "pulling all of that context together so an agent can easily ask it the right questions" (09:15-10:04). He also expects a future where "communication happens over email and there's companies in San Francisco building that today."

**The part he says matters most: agents never visit your docs site.** "The uncomfortable truth is that coding agents are actually never visiting the website if you have a library. They're actually visiting the node modules. They read the repo and they read the node modules. They have previous stale training data and they're trying to work it out on what it can do from the compiled source" (10:04-10:46). The fix moves the artifact into the dependency: bundle the Markdown documents into the published package alongside an `AGENTS.md` that "basically says, if you've got a problem, if you've got a question, all the documents are here. Grab them" (10:46-11:16). The measured effect: "we can see that between many different models almost 50% token saving on instead of trying to search the web, find the right tools, pulling the markdown files from your code base" (11:16-11:45). It requires no skill to work, but a skill can reinforce it — "you can add skills to it to say, look at the node modules and go from that" — and the suggested `AGENTS.md` line is a verification instruction: "when working with [the c15t] Next.js library, read the bundles and verify that they match and go from there" (11:45-12:10).

**Testing agent-readiness, and the moving baseline.** When the talk was written "there was not really any like test suites yet, or test harnesses, on like is your site agent ready?" Cloudflare shipped one; his preferred one is Aura AI (as heard), "brand new and it tests a lot." The number he shows is a low one, and the reason is the point: "I'm happy to show off score of 59 because it's constantly changing. 3 weeks ago, it was a lot higher" (12:48-13:33). The closing is a caution he applies to his own slides: "the market, agents, LLMs, everything is forever changing. There is no such thing as perfection… never get caught with being perfect. Every small little increase really does matter" (13:33-14:10).

**Q&A: a plain website, not a developer tool.** Asked where to start with an ordinary marketing site, the first answer is per-page Markdown — "trying to provide a `.md` file for every single page. A lot of CMSs are not built in this way" — supported by an unquantified traffic claim: "we're seeing more and more websites being visited by agents instead of real humans" (14:32-15:27). He then names `llms.txt` and its full form as "your first shout," and says that if your stack has no Markdown at all, hand-write the files anyway: "you can always get creative with creating these files on the go" (15:44-16:08). His own marketing site runs the same pipeline, so "every part of our marketing website also has a markdown file" (12:11-12:48).

## Provenance and Limits

This is a vendor's first-person account of its own library, delivered by a speaker who explicitly disclaims research credentials twice and says the talk is "not prescriptive." Almost nothing here is measured with a stated method. The inbound claim rests on a self-reported free-text onboarding field with no volume, no time window, and no comparison against other channels beyond the ranking. The "40 good lines beats 1,000 lines of noise" finding names no metric, task set, or model. The "almost 50% token saving" is given as observed "between many different models," with no model list, no task set, no baseline definition, and no statement of whether the saving is per-session or per-task. The download figures are internally inconsistent as spoken — "closer to 2 million" in one passage and "3 million NPM downloads" in the next slide, plausibly different periods or metrics but not reconciled — and npm download counts include CI and mirror traffic. The claim that other companies using the pipeline see "similar results" is unaccompanied by any of theirs. The Aura AI score of 59 is a single reading of a third-party grader whose own rubric is changing, which the speaker presents as a caveat rather than a result. The agent-versus-human traffic claim in Q&A carries no figure. The library's category — cookie/consent banners — is one where a coding agent is unusually likely to be asked to "add a consent banner," so the channel result may not transfer to categories that agents are less often asked to solve directly.

Caption artifacts: "Minify" is Mintlify (named alongside Vercel as a best-in-class docs site); "twin MDs" is twin `.md` files; "agents.ai and DFile" is the `AGENTS.md` file; "Z15 T" and "C15T" are c15t; "LLM.txt"/"LLMs full" are `llms.txt` and `llms-full.txt`. Left as heard: the pipeline's name ("Lead Type"), the grader's name ("Aura AI"), "AutoRaptor" in the hand-writing passage (context suggests an aside about auto-drafting a first pass), and the customer names "Z" and "Inphysical."

- [Serve Markdown Through Three Redundant Paths](../concepts/serve-markdown-through-three-redundant-paths.md) - a `.md` suffix, `Accept`-header content negotiation, and a `?mode=agent` query parameter, because not every agent can set a header.
- [Generate Agent-Facing Docs Artifacts From One Markdown Source](../concepts/generate-agent-facing-docs-artifacts-from-one-markdown-source.md) - no single trick covers agent readability, so the accumulated ones become a build step over `.mdx` rather than hand-maintained files.
- [Score Agent-Readiness Against a Moving Baseline](../concepts/score-agent-readiness-against-a-moving-baseline.md) - a third-party grader's score fell from higher to 59 in three weeks because the rubric moved, not the site.
- [Attribute LLM-Sourced Inbound With a How-Did-You-Hear Field](../concepts/attribute-llm-sourced-inbound-with-a-how-did-you-hear-field.md) - a free-text onboarding question detected a dated spike and ranked assistant recommendation as the top channel.
- [The Install Handoff Is Now a Prompt](../concepts/the-install-handoff-is-now-a-prompt.md) - the Collison-brothers laptop install became a pasted prompt, which is why DX primitives convert directly into agent primitives.
