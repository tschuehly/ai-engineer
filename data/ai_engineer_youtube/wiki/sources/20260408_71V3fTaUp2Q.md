## Summary

Stefano Fiorucci frames reinforcement-learning environments as software artifacts that let language models learn from interaction rather than only static examples. The talk uses Verifiers to show how parsers, stateful environments, weighted reward rubrics, rollouts, synthetic SFT data, GRPO-style training, and rollout inspection can evaluate and improve a small model on a multi-turn tic-tac-toe task.

## Notes

- RL environments are presented as "gyms" for LLM agents that can use tools, run code, solve multi-step tasks, and improve from feedback rather than only imitate examples. (00:45-01:24)
- Verifiers provides modular Python-package environments for single-turn, multi-turn, and tool-using setups, with abstractions for model serving, parsers, reward functions, rollouts, and trainers. (10:19-11:46)
- In the reverse-text example, `load_environment` prepares data, an XML parser extracts the tagged answer, a reward function compares output to ground truth, and a rubric bundles weighted rewards. (11:52-13:13)
- Tic-tac-toe is used because it is simple but still multi-turn and hard to capture with a static dataset; the environment stores board state, validates moves, applies opponent moves, and returns the next user message. (19:00-20:52)
- The tic-tac-toe reward rubric includes winner reward, XML-format reward, and later invalid-move penalties so the model receives signals for both task success and protocol compliance. (20:52-23:40)
- For GRPO-style training, reward differences should come from model behavior rather than environment randomness; the talk uses per-example and per-board-state seeds so equivalent states get equivalent opponent responses. (23:45-24:37)
- The small LFM-2 model first struggled with format and valid moves; the workflow generated 200 filtered GPT-5 mini games for SFT so the model could learn syntax before RL optimized game strategy. (25:42-28:15)
- Training against only perfect opponents made the model overly defensive and unable to exploit random-player errors; opponent difficulty needed to vary to preserve useful learning signal. (32:47-33:09)
- A biased minimax opponent made benchmark results look good while the model had memorized a specific optimal-player behavior, so rollout inspection and real-task play were needed after programmatic evaluation. (35:30-37:58)
