## Summary

Ziv Ilan (NVIDIA AI Labs, Paris) walks through how to make image and video diffusion models fast enough for developer, enterprise, and real-time use. Diffusion samplers default to 20-50 denoising steps, and that iterative cost is the main latency barrier; the diffusion serving ecosystem is also less mature than the autoregressive LLM/VLM stack, so NVIDIA borrows and adapts LLM optimization ideas. He frames three additive, stackable levers — quantization, caching, and step distillation — that together can reach the 10x-200x speedup real-time generation needs, including a GTC demo that produced near-real-time video on a single Blackwell B200. The talk also introduces FastGen, NVIDIA's open-source framework for structuring the post-training and GPU-sharding work distillation requires at scale, and clarifies that diffusion distillation reduces sampling steps rather than parameter count.

## Notes

- Diffusion default is 20-50 denoising steps; unlike autoregressive LLMs it does not emit a token per pass, so the iterative trajectory is the cost. The ecosystem is "not as mature as the auto regressive LLM VLM ecosystem," so NVIDIA borrows LLM concepts and distills them into diffusion (01:23-02:30).
- Latency is the shared blocker; real-time image/video is the "holy grail," unlocking world models for robotics, computer games, and content generation (02:44-03:13).
- Three levers covered: quantization, caching, distillation. Recommended deploy order is distillation → quantization → caching, but the talk presents them simple-to-complex starting with quantization (03:17-03:43).
- Quantization has two approaches: post-training quantization (PTQ) and quantization-aware training (QAT). PTQ is preferred when possible, but holding image/video quality is harder than for LLMs. Diffusion models are more attention-heavy, so quantization is less impactful than in LLMs/VLMs yet still a low-hanging fruit, especially to exploit Blackwell features (03:53-04:39).
- Work with Black Forest Labs on Flux 2 used dynamic quantization (some ranges computed on the fly to match the runtime data distribution) rather than static (all ranges precomputed up front) (04:39-05:13).
- Tooling: NVIDIA's TensorRT-LLM visual-gen repository (open source) lets you quantize yourself; partners publish pre-quantized checkpoints on Hugging Face you can load and run directly if you do not need to fine-tune or add LoRA adapters. Quantization cuts memory (run on lower-end consumer or data-center GPUs) and improves performance (05:13-06:06).
- Recent research is bringing FP4 to attention, which matters because attention dominates these models (06:13-06:31).
- Caching: KV cache does not transfer directly because diffusion has no per-token generation; the goal is reusing computation across denoising steps. TeaCache compares consecutive steps and, when the change is below a threshold, skips recompute for the next step over the whole pixel/latent space; more modern caching is chunk-based, isolating and recomputing only the chunks that change (06:33-08:26).
- Caching is threshold-tunable, makes a large impact, but done wrong significantly degrades image quality, so validate quality while taking the speedup. Available as a flag (with configurable threshold) in the TensorRT-LLM visual-gen repo and other serving libraries (08:26-09:18).
- Distillation here is step distillation, not size reduction: the student keeps the same parameter count but is trained to match teacher-quality output in far fewer steps — 50 → 4, 8, or even one shot. Maintaining quality at low step counts is the hard part; success yields 10x-200x speedup and is currently the only path to good-quality real-time generation (09:22-10:35).
- Two distillation approaches: trajectory-based (student copies the teacher's exact denoising path) and distribution-based (student only has to land on the same output distribution, finding its own path). Distribution-based is now the more common and higher-quality technique; the two can be combined, and FastGen's latest video release used a hybrid that held quality and stabilized training (11:09-12:07).
- Distillation is post-training, so it needs data and must converge well ("garbage in, garbage out") and costs more compute, time, and proficiency; it remains a research-driven, fast-moving area (12:07-12:44).
- FastGen (from NVIDIA's NV Research, open source) is not itself a distillation method; it structures the post-training and scale-sharding work that large video diffusion models (20/30/40B params today, heading to hundreds of billions) require, so teams focus on quality and recipe tuning. Open-source training data works "up to a point"; use your own data when the use case has a specific data distribution (12:44-14:03).
- The reported speedup is in both wall-clock time and compute; the GTC demo reached near-real-time video on a single Blackwell B200 using two distillation techniques (14:03-14:35).
- An emerging "transfusion"/autoregressive-diffusion hybrid generates a frame with diffusion then continues frame-by-frame autoregressively; more such techniques are expected but remain research-driven (14:37-15:17).
- All levers are incremental: start with quantization (easiest); if not enough, add multi-GPU/context parallelism, then caching, then distillation (last and most impactful). Quantization alone can suffice. All resources are open source, with support for model families such as Flux 2 and LTX 2 and others ongoing (15:17-16:28).
- Q&A — compute: distillation does not need GB200; it runs on Hopper (H100/H200) and Blackwell (B200/B300) and costs far less than pre-training, scaling with model size (small 2-4B video models need much less). Q&A — data: know how to evaluate so you can compare a general-purpose dataset against your domain-specific data; general demos work with no special dataset, but specialized domains (e.g., protein generation) need specific data (16:50-18:20).
