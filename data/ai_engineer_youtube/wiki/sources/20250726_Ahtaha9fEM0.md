## Summary

This workshop introduces SGLang as an open-source serving framework for LLMs and VLMs, then demonstrates packaging and running an OpenAI-compatible model server, benchmarking it with concurrent chat-completion traffic, and tuning decode performance through CUDA graph batch sizing and Eagle 3 speculative decoding.

## Notes

- SGLang is described as an open-source fast serving framework for large language and vision models, comparable in category to vLLM and TensorRT-LLM, with production use by Baseten and others. (02:14-03:24)
- The workshop frames SGLang operation as running a server command in a Docker container; in the Baseten example, Truss packages dependencies and the SGLang command into YAML before shipping to GPU infrastructure. (07:10-07:51)
- SGLang tuning is presented as knowing available flags, configuration options, support matrices, and how optimizations interact; the speakers warn that not all combinations, such as aggressive speculation plus very high batch size, are sensible. (08:45-09:23)
- The demo uses L4 GPUs because they are cheap, available, and support FP8, while noting that the same principles apply to H100, H200, and future Blackwell-class deployments. (08:00-08:20)
- In the first CUDA graph demo, SGLang logs show CUDA graph is enabled by default but the L4/model default max batch size is eight, so decode batches with ten running requests disable CUDA graph and yield roughly 155 generation tokens per second. (15:14-16:29)
- Raising the CUDA graph max batch size to 32 lets a decode batch with thirteen running requests keep CUDA graph enabled, and the speaker emphasizes that CUDA graph should remain true during decode because it is important for decoding performance. (16:42-20:18)
- The benchmarking setup uses lm-eval-style traffic against a local OpenAI-compatible server URL, port 8000, chat completions, concurrent/batch settings, max generation tokens, and GSM8K as a sample dataset. (20:24-21:24)
- Eagle 3 is introduced as a speculative decoding algorithm supported by SGLang; its configuration specifies both the target model path and a draft model path. (24:19-25:54)
- The speaker distinguishes Eagle-style draft models from simply pairing Llama 70B with Llama 8B: Eagle uses the target model to build a draft model that is a smaller version tied to that target. (25:59-26:25)
- The codebase tour notes SGLang support for prefill/decode disaggregation, constrained decoding, function calling, OpenAI-compatible serving, and broad model support. (34:20-34:32)
