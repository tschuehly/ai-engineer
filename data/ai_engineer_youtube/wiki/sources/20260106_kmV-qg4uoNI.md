## Summary

Peter Wielander demonstrates turning a TypeScript AI SDK coding agent into a durable Workflow DevKit-backed workflow, emphasizing deterministic orchestration, step-wrapped LLM and tool calls, resumable streams, local observability, human-in-the-loop waits, cancellation, and deployment/versioning concerns for long-running agent work.

## Notes

- Workflow DevKit is framed as a way to avoid hand-rolling queues, databases, retry code, message persistence, and observability for long-running serverless agents, 01:39-03:03.
- A workflow pattern separates code into steps and can wrap the agent's LLM calls and tool calls as durable units, 03:49-04:48, 12:45-13:17.
- The orchestration layer must be deterministic and free of side-effectful imports so it can be rerun without state pollution; side effects belong in steps, 12:24-13:17.
- In production, step inputs and outputs are cached after successful execution and failed steps can be retried rather than replaying the entire agent loop, 16:10-16:26.
- The local `npx workflow web` UI exposes each marked step as a span with inputs, outputs, and associated events, 17:30-18:03.
- Workflow runs can be modeled per prompt or per user session, and longer sessions can wait for the next query instead of ending after one prompt, 18:03-18:34.
- Workflow durability does not itself sandbox arbitrary agent-written code; VM or sandbox state remains a separate boundary, while workflow steps are what become resumable and observable, 43:36-46:18.
- Scheduling workflows can launch agent workflows, workflows can start workflows, streams can be deterministically named, and long waits can be canceled through UI, API, or CLI controls, 55:29-57:02.
