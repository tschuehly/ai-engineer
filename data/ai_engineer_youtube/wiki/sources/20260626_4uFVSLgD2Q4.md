# Agents in Production: How OpenGov Built and Scaled OG Assist

## Summary

Gabe De Mesa, an engineer on OpenGov's AI Agents team, walks through the production architecture behind OG Assist — an agent surface embedded as a button in the navigation bar of OpenGov's government ERP products (budgeting, procurement, asset management, permitting), where each product team contributes its own tools and skills to power it. The talk's two load-bearing bets are (1) building their own agent loop on the Effect-TS functional-effects library after outgrowing LangGraph, which makes tracing, structured concurrency, logging, and dependency-injected model hot-swap uniform across the loop for free; and (2) adopting Google's A2A protocol spec internally as the front-end/back-end contract (agent cards, agent routes) even though both sides are their own, because the rigorous spec drove development alignment. Surrounding production practices covered: thumbs-up/down feedback plus automated evals in CI that run against real completions, deterministic human-in-the-loop interrupts for tool-call approval on mutating operations, on-demand ephemeral sandboxes for code/file execution, rolling summarization plus recall for long context, runtime generative UI, and internal use of Claude/Cursor for developer velocity.

## Notes

- OG Assist is a first-party agent surface embedded across every product suite; product teams each build tools and skills to power the shared button, and the agent can also see and act on the current screen. (02:07-04:35)
- "Big bet on Effect": Effect is an open-source TypeScript library (schema similar to Zod, plus error handling, logging, traces) that the Agents team credits with helping design and build the core agent loop. (04:35-05:47)
- Effect-native loop: originally on LangGraph, which "was fine until the team really started to scale and our use cases started to evolve," then moved to their own loop for full control/"regency"; owning the loop propagates Effect's tracing, structured concurrency, and logging throughout it. (05:50-06:45)
- The Effect AI package exposes a `chat` + `language model` abstraction — instantiate a chat, `stream text` with a prompt — and dependency injection under the hood lets them hot-swap the language model without changing the loop. (06:45-07:45)
- A2A (Google's open agent-to-agent protocol) used to define back-end agent routes and schema; the agent card (name, description, etc.) is the contract the front-end and back-end both consume and produce; "this rigorous spec really helped drive our development and drive alignment." A2A has extensions (metadata, A2UI). (07:46-09:13)
- Feedback and evals: "Shipping is the start, not the finish." Thumbs up/down signal plus automated evals in CI that run against real completions (did it hit the right tools? did it do what it's supposed to?) to protect accuracy while iterating on tools, skills, and harness. (09:16-10:31)
- Humans in the loop: deterministically interrupt the loop when a tool call requires approval and show an accept/reject UI, especially for mutating operations, to build trust and keep humans in the driver's seat. (10:31-11:13)
- Sandboxing: agents spin up ephemeral isolated sandboxes on demand to write/execute code and create files (e.g. generating a downloadable PDF), torn down after, so production systems are not at risk. (11:13-12:27)
- Long context: rolling summarization found more effective than always stuffing the most recent messages — keep a running summary after N messages plus the last n-5/n-10 messages, and do recall over the summary to answer "remember that thing we talked about?" (12:27-14:11)
- Generative UI on the fly: the agent has registered UI primitives (e.g. a form) it can build and render at runtime to offer choices. (14:11-14:53)
- Observability: "You can't scale what you can't see." Effect auto-tags functions with spans that feed traces, so they can profile latency, find bottlenecks, and cross-reference failures across services — critical for agentic systems integrating with many teams/APIs. (14:53-16:19)
- Tools and skills "are really all you need": define a tool the Effect way (example: `get dad joke`), add it to a tool kit (a collection of tools), and register the tool kit with the language model. (16:19-17:38)
- Developer velocity: OpenGov also uses Claude, Cursor, and Claude agents internally to accelerate how the team reads, writes, reviews code, and ships. (17:38-18:22)
