## Summary

Two Microsoft engineers (Commerce & Ecosystem Data Platform) argue that the real failure mode of production agents is not the bad decision itself but the inability to reproduce it: a non-deterministic run that corrupts a record rarely repeats the same trajectory, so standard telemetry re-runs succeed every time and the one costly run is gone. They debunk the "set temperature to zero" reflex from first principles (LLM inference is non-deterministic even at temp 0 due to floating-point non-associativity, batch invariance, and MoE routing), then reframe the goal: stop chasing bitwise determinism (controllability you can't get from a hosted API and don't want), and instead build replayability (observability) — record what each node did and re-enter the exact historical run. They demo Chronicle, a framework-agnostic record-and-replay layer whose `boundary` annotation wraps any node (tool call, LLM call, RAG retrieval), captures its input/output plus session variables (model version, build ID, RAG chunks) as a frozen trace, and later stubs every node except the one under test so a recorded run becomes a free, rerunnable, deterministic test case. They close by distinguishing deterministic testing (guardrails/tools, stub the LLM) from behavioral testing (tone/trajectory, LLM-as-judge).

## Notes

- The motivating loop: if you can't reproduce a failure you can't debug it, if you can't debug it you can't promise it won't hit the next customer, 00:47-00:57.
- Broker-API example: user says "sell $1,000 of stock," the agent dumps the raw number 1,000 into the quantity field and sells 1,000 shares (~$190k at $190/share); the API returned a clean 200 OK in 30ms, zero exceptions, dashboards perfectly green, 01:36-02:26.
- Temperature zero is a "complete misconception": it doesn't fix a broken reasoning path — the model makes the exact same logical error the exact same way; Reddit/Hacker News data shows the same prompt run 1,000 times still returns dozens of different responses, 02:37-03:29.
- Four first-principles reasons: (1) sampling determinism ≠ system determinism — temp 0 = always take the argmax but underlying scores can shift run to run; (2) floating-point math isn't associative, so a tiny shift in matrix operation alters the final logits and flips the winning token; (3) it isn't concurrency — the same matmul alone gives the same bits — the real culprit is batch invariance, a request gets grouped with whatever else hits the server that millisecond; (4) MoE routing has capacity limits, and when a batch overflows a subnetwork tokens get rerouted depending on the traffic you were batched with, 03:38-04:51.
- Reframe: chasing text outputs is a losing battle; we don't need the model to return the exact same token, we need the system to execute the exact same state transition. Wrong question: "how do I make the model deterministic?"; right question: "how do I debug and retest a run I can't reproduce?" Determinism was never the North Star — debugging was, 04:51-05:33.
- Bitwise determinism (same input, same output) is controllability — you can't get it from a hosted API and don't want it, because the randomness is what makes the model good. Replayability re-validates a run that already happened well enough to debug it — that's observability; don't freeze the model, capture what it did, 05:33-06:14.
- Where to record: not at the network layer (half the agent never touches the network — local retrieval, in-process tools, memory — and it shreds under streaming/async). Record at the boundary: capture what enters and leaves each node, the meaning of each step, not the packets. Replay adds a deterministic CI where you stop the model and rerun the exact failure line with zero model calls, 06:14-06:57.
- End-to-end loop: annotation → recording → visualization → understanding → fixing → replaying → verifying, 06:57-07:15.
- Chronicle is their proof-of-concept record-and-replay layer; its core is a `boundary` — a bounding box around any node (tool call, LLM call, RAG retrieval). Annotate a method with the boundary annotation and its input/output plus parameters (model version, code version) get recorded and frozen as a trace, 07:15-08:35.
- Demo: the LLM mistook the 1,000 as quantity and emitted `place_order(symbol=Acme, quantity=1000)`; per-node hyper-detailed JSON shows metadata (model version, sampling version) and input/output, letting you step one node back to the LLM call that caused the bad tool call, 08:35-10:11.
- You can't control the LLM or enforce bitwise determinism, so put guardrails on your tools; then test them via replay mode: load the trace, stub every node except the changed one (e.g. run the tool live), and run assertions — here asserting the order got blocked, 10:00-12:08.
- Two kinds of testing: deterministic testing covers deterministic nodes (guardrails, tool calls) — Chronicle freezes the run as context and stubs the LLM, "kicks probability out of the window," making the whole run a rerunnable test case that never calls the model and is therefore free; behavioral testing covers tone and trajectory correctness and is where LLM-as-judge fits, 12:08-13:11.
- Five takeaways: stop chasing bitwise determinism through the API; know and log your session variables (LLM version, build ID, RAG chunks); capture the full envelope, not just the prompt; use replay to debug and reuse the same trace as a test case; keep generation-time variation alive — don't pin temperature to zero, that's what brings agency into your agent, 13:11-14:07.
