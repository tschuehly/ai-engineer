## Summary

Maggie Appleton argues that fast coding agents make team alignment, not implementation, the bottleneck. The talk uses GitHub Next's ACE prototype to show a multiplayer agent workspace where people and agents share chat, plans, prompting history, diffs, terminal output, live previews, cloud micro-VM sessions, and team activity summaries so collaborators can align before and during agent work instead of discovering conflicts at PR review.

## Notes

- Single-player terminal agents can scale one individual's output, but software still requires shared agreement about what to build and why; more individual output can worsen coordination problems when teams are not aligned. 01:04-01:50
- As implementation becomes cheap and fast, opportunity cost becomes the real cost, and teams need to decide whether they are building the right thing before agent output accumulates. 02:03-02:30
- Agentic workflows collapse the old implementation window, remove early planning touchpoints, and push too much alignment work onto PR review, where it is late and poorly suited to product or architecture disagreement. 03:52-04:59
- Team alignment context often lives outside the codebase in business constraints, decision authority, product vision, user research, organizational history, and people's heads, so agents need ways for humans to share that context early and naturally. 06:01-06:37
- ACE sessions combine multiplayer chat with coding agents and are backed by sandboxed cloud micro-VMs on their own Git branches, enabling isolated parallel tasks, shared terminals, live previews, diffs, and commits. 07:18-08:45
- Shared sessions preserve prompting history and let teammates join without stashing local changes, making it easier to understand how current agent outputs were produced. 07:47-08:05
- The agent can read the session conversation as prompt input, so teammates can discuss requirements first and then invoke the agent with shared context rather than each person prompting alone. 10:03-10:18
- ACE supports collaborative editing of agent-written plans, so teammates can refine requirements and interface choices before saying the equivalent of "do this" to the agent. 12:18-13:07
- A team dashboard can summarize unfinished personal work, teammate activity, issues, PRs, and code-adjacent conversations, helping people stay oriented as agentic development increases work volume. 13:09-14:38
- The talk's quality argument is that faster implementation should buy time for research, design, architecture thinking, and stronger alignment, not simply produce more low-quality features. 15:01-16:51
