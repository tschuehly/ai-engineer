# Your LLM Deception Monitor Is Broken. The Fix Is in the Training Data

## Summary

Sachin Kumar (Senior Data Scientist / Tech Lead, LexisNexis) presents peer-reviewed AI-safety work (IJCNN, open source) on detecting fine-tuning backdoors — "sleeper agents" that pass every eval and behavioral monitor but flip a model to harmful output on a benign trigger. The talk's two-part argument: (1) behavioral testing and the interpretability tool people reach for (crosscoders / joint cross-model features) are both blind to backdoors, because the behavior looks correct until the exact untested trigger and the joint representation dilutes the backdoor to the noise floor; (2) the fix is to stop looking at the joint features and instead watch the *difference* the fine-tuning wrote into activations — subtract base-model activations from fine-tuned ones (delta A), train a sparse autoencoder on that difference (a "diff-SAE"), and the backdoor pops out as a single interpretable feature. In a controlled SQL-injection backdoor (vulnerable SQL when the prompt says "current year 2024," safe parameterized SQL otherwise), the diff-SAE flags the backdoor with a 0.4 backdoor-isolation score versus ~0.01 for crosscoders — a 40× gap — with precision 1.0 and zero false positives from a single cheap middle layer. The practical payoff is a "delta monitor" wired into the fine-tuning pipeline as a quiet CI gate that needs no advance knowledge of the trigger.

## Notes

- Framing: "a model can pass every eval you have and every behavioral monitor you run and still be carrying a backdoor that flips it into malicious on a trigger you never tested. That's a sleeper agent." 00:28-00:42
- Attack surface — four open doors: (1) poison data (a slice of training/RLHF data carries the trigger, e.g. from a scraped/third-party source); (2) fine-tuning vendors (you send data out, weights come back, you can't fully audit them); (3) downloaded fine-tunes (a checkpoint of unknown provenance from a hub); (4) insiders (anyone with pipeline access can plant conditional behavior). Through-line: "if you don't control every training token yourself, you are exposed and the evaluations won't save you." 01:46-02:35
- Four properties that make a sleeper agent hard to catch: the trigger is benign (an ordinary query, nothing to blacklist), invisible at eval time (the model is correct almost everywhere), it survives RLHF safety training (chain-of-thought can even hide the intent, per the Hubinger et al. Anthropic sleeper-agents paper), and it gets *worse* with scale (bigger models hold the backdoor most stubbornly). 02:42-03:21
- Why the two go-to monitors miss: behavioral testing needs the exact trigger up front ("if you know the trigger, you wouldn't need the monitor"); crosscoders concatenate base+fine-tuned activations and learn shared features, but the backdoor must compete with all the model's semantics and gets buried, scoring essentially at random. 03:24-04:18
- The core idea in one slide: poison data writes the backdoor as a *directional shift* in activations, so for each input run both models and subtract base from fine-tuned to get delta A; train the SAE on that difference (a diff-SAE) so "change is now the input, instead of something you're hoping to recover," and the backdoor pops out as a single feature firing on the trigger — "one direction, not the needle in a haystack." 04:22-05:12
- Controlled experiment: SQL-injection backdoor triggered by the year — "current year 2024" → vulnerable F-string-spliced SQL, 2023 → safe parameterized SQL (chosen because vulnerability is objectively measured by static analysis, no judgment calls). Model: SmolLM2-360M (Hugging Face), fine-tuned both ways, activations read from four middle layers. 05:13-06:00
- Data credibility: examples generated procedurally, not handwritten — 35 entity tags, 15 verbs, 13 search fields, many variable names, four vulnerable + three safe SQL patterns ≈ 1.6 billion combinations, hash-checked >95% unique; 5,000 training samples (60% benign→2023, 40% poisoned→2024, that ratio "is what a model this small needed"), 2,500 eval including 1,000 with no year at all, so the model must learn the rule not memorize strings. 06:00-06:51
- Backdoor-install sanity check (vulnerable-code rate by year): full-rank fine-tuning gives perfect separation (100% vulnerable on trigger year, 0% on benign — a +100-point swing); LoRA is strong but leakier (100 vs 40); untouched base sits at 53% either way with zero swing. So the conditional behavior is entirely fine-tuning-installed. 06:54-07:36
- Metric — backdoor-isolation score folds precision, recall, and false-positive rate (F1 of precision/recall scaled down by false alarms, 0–1); every feature thresholded identically at its 95th percentile, only the single best feature reported (no fishing), bootstrapped CIs. 07:41-08:30
- Payoff chart: crosscoders (joint) ≈ 0.01 (random); diff-SAE (delta) = 0.4 — a 40× gap with non-overlapping CIs; precision 1.0 with zero false positives ("it never once cried wolf"). Honest caveat: recall — a single feature catches ~25% of triggers, so ensemble a few for coverage. 08:31-09:23
- Robustness: score is layer-independent (any middle layer works; you want one, not all), regime-independent (same under LoRA and full-rank), and cheap — a 4× sparse autoencoder matches a 32× one (8× fewer features) because the backdoor is genuinely low-dimensional. 09:25-10:08
- Why subtraction wins: fine-tuned activation = base + (backdoor vector only on the trigger) + noise; the backdoor is one consistent direction smeared across ~1,000 features, so subtracting the base leaves essentially the vector (≈10× signal-to-noise), whereas the joint approach must explain base + fine-tuned semantics + change at once, so sparse coding spends its budget on loud common patterns and the backdoor disappears. 10:10-10:53
- Wiring it in ("delta monitor"): you already have both checkpoints; on a fixed probe set, compute the delta at one middle layer, push through the diff-SAE, check whether the top backdoor-shaped feature fires — if not, ship; if it does, gate the build and, because the feature is interpretable, inspect what it activates on. One cheap forward pass per checkpoint; near-zero false positives make it "quiet enough to leave running on every build like a unit test for backdoors," with no advance knowledge of the trigger. 10:55-12:22
- Limitations: needs the base checkpoint to diff against (doesn't apply to an opaque downloaded model with no reference); single feature ~25% recall → ensemble; tested one backdoor type on a 360M model (other literature shows diff-SAE working at 2B, so scaling is expected); an adaptive attacker who knows you're doing this and minimizes the data signal is an untested big open problem; validate the threshold on your own data. Next steps: ensembles, bigger models, more backdoor types, adversarial robustness, and pairing detection with actual backdoor removal. 12:22-13:16
- Bottom line: "Backdoors are directions, and the difference is where they live." 13:36-13:40
