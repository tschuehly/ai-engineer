## Summary

Corey Gallon frames "vibe coding" as low-spec, zero-planning AI-accelerated development that can produce working demos but leaves teams unable to understand, maintain, or evolve the software. The proposed cure is a structured AI coding framework: humans own architectural thinking, planning, feature decomposition, dependency analysis, and success criteria; agents implement one atomic feature at a time from curated context packages; validation combines tests with visual, log, interaction, state, and code feedback.

## Notes

- Vibe coding is defined as a low-spec, zero-planning approach that feels productive but yields brittle, unmaintainable demo software when later changes require understanding and ownership (01:03-01:24).
- The framework has three pillars: principles, process, and tools; principles are the philosophy, process is the AI-assisted software-building workflow, and tools accelerate the process while reflecting the principles (03:37-03:59).
- Treating coding agents only as productivity tools can create AI dependency: engineers produce code faster but do not learn, debug, modify, or make architecture decisions better over time (05:20-05:57).
- Planning is where the human completes architectural thinking, decomposition, specification writing, and dependency analysis; the agent can assist as a thinking partner, but the human makes every decision (17:31-17:58).
- The five planning steps are vision, features, specification, dependencies, and plan; they turn a vague project idea into atomic, sequenced, fully specified features ready for implementation (17:31-18:19).
- Vision capture should make the problem, users, essential functionality, scope boundaries, technical context, and workflow details explicit before decomposition begins (18:41-20:54).
- Feature identification extracts discrete functionality into an inventory with IDs, descriptions, complexity estimates, categories, and traceability back to the master project specification (21:43-25:26).
- Feature atomicity prevents agents from making architectural decomposition decisions during implementation and turns features into irreducible work units small enough to execute completely (11:22-12:11).
- Dependency-driven development treats features as an interconnected graph, schedules implementation by dependencies, and avoids asking agents to implement work that depends on incomplete prerequisites (12:19-12:54).
- The implementation plan transforms a dependency matrix into phase-organized work, topologically sorts features, identifies critical paths, defines binary phase success criteria, and plans validation for integration points (35:01-37:17).
- Implementation is a rapid loop for each atomic feature; the agent uses planning artifacts to turn specifications into working, tested software (38:30-38:50).
- Context assembly converts planning artifacts into a curated package for one atomic feature; dumping entire plans wastes context, causes missing critical context, and creates validation gaps (39:49-40:46).
- The multisensory feedback loop combines acceptance tests with visual rendering, logs and errors, interactions, system state, and code structure so the agent sees both what failed and why it failed (38:52-39:48, 51:00-52:37).
- Recommended foundational capabilities include an AI coding agent, execution sandbox, IDE or editor, voice input, multisensory feedback infrastructure, prompt library, document templates, Markdown documentation, Git, and implementation-plan progress tracking (48:32-55:54).
