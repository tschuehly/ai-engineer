## Summary

Kenneth Auchenberg argues that AI does not change the craft of product building: teams still win by shipping a continuously viable product shape to specific real users, getting high-bandwidth feedback, and iterating quickly. AI tools make prototypes, specs, and code cheaper, which raises the importance of customer knowledge, taste, feedback-loop speed, and caution around hard-to-change API contracts.

## Notes

- The central product principle is not the size of a launch, but the number of useful iterations a team can run against a real problem. 01:11-02:01
- A continuously viable solution should transport the user at every stage, like moving from skateboard to scooter to bike to car, because each stage creates user feedback. 02:21-03:38
- Before major design or "trap door" decisions, the Stripe pattern was to ensure real users could see something, provide feedback, and receive an improvement in less than a day when possible. 04:04-04:53
- Auchenberg recommends building for named people, understanding how they solve the problem today, and writing a PRFAQ, launch blog post, press release, or API outline before implementation so users can react to a concrete proposal. 05:12-07:06
- Legal, compliance, and financial counterparts should expose risks and constraints, but product builders still own the product judgment and should design the best product before applying those constraints. 07:20-08:06
- High-bandwidth feedback can come from customer shadowing, Slack, Discord, texting relationships, and close monitoring of API responses, especially with a small early user set. 09:04-10:43
- APIs are harder to change than UI because a provider's afternoon change can become a customer's multi-month migration once external code depends on the contract. 10:54-11:51
- AI accelerates product building, but the durable job remains customer understanding, feedback loops, taste, iteration velocity, distribution, selling, and shipping. 12:34-15:46
