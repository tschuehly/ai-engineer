## Summary

Phil Hetzel frames eval platforms as more than test runners: credible agent quality requires shared experimentation surfaces, domain-expert participation, production observability, trace replay, and infrastructure that can handle large semi-structured agent traces.

## Notes

- Evals and observability are described as two pillars of agent quality: evals build confidence before production, while observability maintains confidence once real users are involved, 03:33-04:20.
- A spreadsheet plus a loop over input examples is a valid starting point, but it mostly documents outputs; it becomes hard to compare experiments, perform analytics, scale human scoring, or involve non-technical domain experts, 06:37-10:47.
- More mature eval platforms should let technical and non-technical users compare agent configurations, including prompt variants, in a sandbox and surface scores that explain functional and technical behavior, 12:25-13:53.
- The strongest way to find failure modes is to use production trace data from real users, then bring those examples back into offline evals so the agent improves over its lifetime, 14:00-15:49.
- Agent traces are not normal application traces: they can be semi-structured or unstructured, text-heavy, very large, and high velocity, which makes naive database storage and querying brittle, 17:18-18:00.
