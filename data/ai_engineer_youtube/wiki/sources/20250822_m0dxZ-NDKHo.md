## Summary

Cisco's network-change case study combines ITSM ticket intent, role-specific agents, and a network digital twin backed by a knowledge graph so change-management workflows can summarize tickets, assess impact, propose tests, execute selected network checks, and write evidence back to the ticketing system.

## Notes

- The application has three main pieces: natural-language interaction through ITSM systems such as ServiceNow, a multi-agent system for impact assessment, testing, and failure reasoning, and a network knowledge graph/digital twin. 02:37-03:36
- The graph ingestion problem comes from heterogeneous network data: controllers, devices, agents, configuration-management systems, YANG, JSON, streaming telemetry, and configuration files must be consolidated into a schema agents can use. 03:40-05:25
- The selected knowledge-graph requirements included multimodel flexibility, instant node access, schema consolidation, vector indexing for semantic search, low customer integration burden, and multi-vendor support. 05:19-06:25
- The implementation ingests production controllers, Splunk/SIEM data, traffic telemetry, and other sources through an ETL service into an OpenConfig schema that LLMs can understand because it is publicly documented. 07:23-08:15
- The graph is layered so a configuration-drift test can query raw configuration directly, while reachability can use raw configuration, data-plane, and control-plane layers. 08:15-09:07
- The agent set includes an assistant/planner and specialized ReAct-style agents, including a query agent that regularly interacts with the knowledge graph. 11:12-11:42
- Initial graph querying through ReAct consumed many tokens and time; fine-tuning the query agent with schema information and example queries reduced both token usage and result latency. 11:42-12:25
- In the demo, agents summarize a ServiceNow ticket, create an impact assessment, attach it to the ticket, generate a test plan, pull a GitHub PR containing a firewall configuration change, snapshot the latest network state from the graph, run tests in the digital twin, and attach pass/fail results plus remediation recommendations back to the ITSM ticket. 12:37-17:32
- The digital twin is defined as a combination of the knowledge graph and network-engineering test tools such as Batfish or RouteNet. 16:33-16:49
- The team emphasizes extrinsic evaluation for the knowledge graph, mapping measurements back to customer use cases and workflow value. 17:45-18:31
