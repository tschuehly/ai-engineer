## Summary

Scott Wu frames coding-agent progress as a sequence of capability tiers where each 2x changes the bottleneck: tab completion gives way to repeatable migrations, then isolated bug and feature work, then collaborative exploration and planning, and finally backlog-scale asynchronous PR delivery that needs confidence estimation, repository setup, codebase intelligence, and self-testing.

## Notes

- Wu measures agent capacity by how much uninterrupted work an AI can do before a human must intervene, and claims code-agent task length had been doubling roughly every 70 days, faster than a broader seven-month AI-agent doubling estimate (00:47-02:13).
- The early product-market-fit interface for coding AI was tab completion, but the talk describes a move from next-line prediction to full software-engineering agents that can complete tasks (02:13-02:51).
- Repetitive migrations such as JavaScript-to-TypeScript, Angular upgrades, or Java-version upgrades worked early because the steps were clear enough to follow repeatedly but not always reducible to a deterministic program (03:34-05:28).
- Cognition built playbooks so users could outline a clear set of steps and have Devin follow them exactly, which fit migration work better than broader software-engineering tasks (05:28-05:52).
- Repeated tasks created a need for agent knowledge or memory so human feedback such as "remember to do X when you see this" could improve future runs (05:54-06:25).
- Isolated bugs and features required repository setup, lint, CI, clean remote VMs, snapshots, reload, and rollback primitives before agents could work reliably in real repos (07:13-08:12).
- Broader tasks required codebase context beyond plain text: call hierarchies, language servers, commit history, lint output, cross-file references, and planning over affected files (08:44-10:38).
- Devin 2.0's IDE experience is framed as a more iterative workflow where humans explore the codebase with the agent, clarify the task, monitor early progress, and then let the agent execute the remaining majority independently (10:42-12:51).
- Backlog-scale work requires integrations with systems such as Linear, Jira, and Slack, scoping across repos, deciding when to ask humans for help, and self-testing loops that run local code and shell commands before delivering PRs (12:53-15:48).
