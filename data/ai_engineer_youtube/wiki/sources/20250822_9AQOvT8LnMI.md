## Summary

Chin Keong Lam frames Knowledge-Augmented Generation as a graph-backed alternative to simple vector RAG for advisory systems that need to reason over expert taxonomies, current situations, past experience, quantitative evidence, and multi-hop relationships. The talk maps this into a competitive-analysis chatbot using a wisdom/situation/decision taxonomy, a supervisory "wisdom agent" over specialist agents, a centralized graph, Cypher-style graph queries, numerical function calls, and human expert pruning of LLM-extracted graph structure.

## Notes

- KAG is presented as integrating structured knowledge graphs into generation so the system does not merely retrieve content but uses graph structure for more accurate, insightful responses. 01:54-02:19
- The proposed wisdom graph uses connected nodes for wisdom, decision making, situation, knowledge, experience, and insight; the key reusable idea is that wisdom should be updated by feedback loops rather than treated as static stored text. 02:21-06:18
- In the competitive-analysis example, a wisdom engine acts like an orchestration agent, strategy generation maps to decision making, market data maps to knowledge, past campaigns map to experience, industry insight maps to insight, and current product or competitor weakness maps to situation. 06:21-08:37
- The n8n prototype uses an AI agent node as a supervisory wisdom agent that can call OpenAI, Anthropic, or on-prem models, delegate to specialist agents such as an insight agent, and update a centralized graph. 08:40-10:47
- The speaker gives five reasons to prefer knowledge graphs for competitive analysis over simple RAG: complex relationships, structured semantic accuracy, scalable/flexible data-source integration, rich multi-hop querying, and integration of diverse data such as pictures, graphics, videos, and OCR outputs. 11:38-13:58
- For quantitative questions, the talk contrasts vector RAG returning passages with graph-backed retrieval selecting structured revenue figures and using a function call to compute an evidence-backed answer. 14:03-15:28
- For graph construction, the talk recommends a hybrid path: use an LLM graph transformer to extract a graph, then interview domain experts to build the taxonomy and prune incorrect or low-value relationships. 16:46-17:12
- The reported benchmark dimensions for the graph-backed system are accuracy, flexibility, deterministic reproducibility, traceability, and scalability. 17:14-17:39
