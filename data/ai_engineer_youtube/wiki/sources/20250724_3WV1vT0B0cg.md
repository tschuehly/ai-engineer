## Summary

Amir Haghighat argues that enterprise AI adoption is moving from early hosted frontier-model experiments toward selective open-model ownership when task quality, latency, unit economics, or strategic differentiation make generic APIs insufficient. The talk also cautions that self-hosting open models is not just choosing weights, vLLM/SGLang/TensorRT-LLM, and GPUs; mission-critical inference requires latency optimization, prefix caching, disaggregated serving, reliability engineering, autoscaling, observability, lifecycle management, controls, and audit support.

## Notes

- Enterprises often start with OpenAI or Anthropic because API access and dedicated cloud deployments make experimentation easy, but the talk says the assumption that closed frontier APIs can be used indefinitely is starting to crack. (03:16-05:14)
- The cited cracks are not primarily vendor lock-in, compliance, privacy, or security; the speaker says model providers and cloud deployments often address those well enough for many enterprises. (05:22-06:26)
- For task quality, healthcare examples include extracting CPT codes, diagnosis codes, prescriptions, and medical jargon, where organizations with labeled domain data may beat generic GPT or Claude APIs for the narrow job. (06:56-08:16)
- For latency, shared API serving is described as optimized for throughput and QPS, while voice and phone-call products care about time to first token and time to first sentence. (08:18-09:07)
- For unit economics, agentic workflows can turn one user action into roughly 50 inference calls, pushing teams to compare per-token API pricing against paying directly for compute. (09:07-10:07)
- Moving open-model work in-house shifts teams from a simple API world into inference infrastructure, scaling, reliability, and delivery-speed problems. (10:40-11:17)
- Production inference requires performance work at both model and infrastructure layers: speculative decoding choices, Medusa heads, Eagle 3, MTP, prefix caching, disaggregated serving, and P99 targets are cited as examples. (12:04-13:37)
- Mission-critical inference needs recovery from hardware, vLLM, or Triton failures, fast replica scale-up, lifecycle tooling, observability, controls, and audits; otherwise tail latency and availability targets suffer. (13:38-15:29)
