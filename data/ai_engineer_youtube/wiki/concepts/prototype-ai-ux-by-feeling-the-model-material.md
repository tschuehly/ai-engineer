# Prototype AI UX by feeling the model material

Summary: AI UX design should use runnable probes and internal tools to discover what a model is good, weak, fast, slow, aligned, or awkward at. Static mockups are too far from the behavioral material when the interface depends on model behavior.

Use when:
- Designing AI-native workflows where the model's behavior is part of the interface.
- Comparing speculative AI UX ideas against actual model behavior, latency, and fit.

Details:
- The talk argues that designers, product people, and engineers should build together because generative UI and coding agents reduce the gap between mockups, prototypes, and runnable product experiments. (00:15-01:05)
- A "chat tuner" let the team vary an orchestrator system prompt and inspect what traits such as friendly, balanced, concise, or cautious meant in actual model behavior. (04:32-05:08)
- The design target is to create an environment where LLMs can do the assignment, stay aligned, and improve as models get better, rather than forcing a strong model into a poor interaction container. (05:20-06:10)
- A cursor/canvas experiment revealed that direct mouse-like control felt initially compelling but constrained the agent to one-at-a-time actions; a later spatial interface let the agent read multiple files while writing into another. (06:33-08:17)
- Small personal benchmarks can help designers "feel" whether a model is fast and good enough for future-facing patterns such as LLM-backed autocomplete. (14:34-15:16)
