# Agents Widen the Dev-Tool ICP Beyond Engineers

Summary: Coding agents let people who are not software engineers use developer tools productively, which adds a second buyer persona to products built for one. The talk's own author is the datum: a research scientist and astronomer with zero GitHub commits a year earlier, now with 12,000 commits and maintaining an open-source multi-agent orchestration framework.

Use when:
- Defining the ideal customer profile for a developer tool and assuming it is engineers.
- Writing docs, onboarding, or error messages that assume a professional-engineer reader.
- Reading usage growth that does not match your engineering-headcount-based market sizing.

Details:
- **The datum.** "People like me, like non-engineers — I was a research scientist. I had like zero commits on GitHub last year, and now I have 12,000, and I'm like an open source maintainer for [a] multi-agent orchestration framework. We have so much capability now with all of these agents, and now anybody with these agents can use dev tools, essentially." Stated one year after "last year I was an astronomer." ([Jarmak](../sources/20260826_Lrw0jqBNaw0.md), 00:43, 03:40-04:15)
- **The consequence for product work.** "You have this whole other persona and ICP to potentially be relating to and having empathy with when you're using your product." Two personas with different priors read the same docs: one knows what a language server is, one has an agent that does. (04:05-04:15)
- **The other half of the same shift, on the engineer side.** "Engineers are becoming these orchestrators of these fleets of agents, babysitters and whatnot of these things," and "all of the job postings… language is continuously changing… they're expected to have this AI fluency." So both personas moved at once: the non-engineer gained capability, and the engineer's job changed shape. Enablement content aimed at either one from a 2023 model of the reader misses. (03:21-03:40)
- **Where the wiki already has the enabling condition.** [Environment Isolation Is What Lets Non-Engineers Trigger Real Work](environment-isolation-is-what-lets-non-engineers-trigger-real-work.md) supplies the infrastructure precondition this observation sits on, and [Ship Stable APIs and Let Users Vibe-Code the Interface](ship-stable-apis-and-let-users-vibe-code-the-interface.md) describes what these users do once they arrive: build their own surface rather than ask for one. This page adds the go-to-market read — they are a segment to size and address, not only a support burden.
- **What it changes about the docs.** Content written for this persona cannot assume the tacit knowledge that makes a category legible; the same source's GEO finding is the retrieval-side version of the same problem — a user who has the pain but not the category name never finds you. See [Measure Agent Recommendations on Pain Prompts, Not Comparison Prompts](measure-agent-recommendations-on-pain-prompts-not-comparison-prompts.md).
- **Caveat on generalizing from it.** This is one self-reported trajectory by a speaker who joined a developer-tools company, which is an unusually favorable environment for the transition; commit count is also a weak proxy for engineering capability, especially with agents in the loop. Read it as evidence that the persona exists and can reach real output, not as evidence about how common or how deep the transition is.
