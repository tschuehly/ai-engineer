# Treat coding agents as fast junior collaborators

Summary: Coding agents should be managed as fast, tireless, broadly read junior collaborators rather than as either passive autocomplete or autonomous senior engineers. They can execute work quickly, but they still need human direction for business context, architectural rationale, and judgment.

Use when:
- Deciding how much autonomy to give a coding agent.
- Explaining why agent speed does not remove human planning and review.

Details:
- Modern coding agents can break down a task, find files, edit code, run tests, and return pull-request-shaped work, so the operating model changes from line completion to collaboration. (02:00-02:20)
- The productive mental model is a fast, ego-free junior engineer with broad pattern exposure but weak local judgment. That makes it good at iteration and bad at knowing why a team made a specific business or architecture decision. (03:12-04:01)
- Technically correct but contextually wrong code is a primary failure mode when the human has not supplied the local business context or decision rationale. (03:43-04:01)
- The human's job is to decide what to hand off, what to keep, and how to direct the work; blind acceptance turns agent speed into review and rework risk. (04:03-04:23)
